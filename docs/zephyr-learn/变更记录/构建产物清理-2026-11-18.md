# 构建产物清理（2026-11-18）

> 变更类型：删除路径治理 + 新增清理入口。**没有跑编译**。

## 一、起因

2026-11-18 回收站爆满、资源管理器打不开。实测：

| 项 | 数值 |
|---|---|
| 当前账户回收站顶层条目 | **1,133,929**（约 56 万个被删文件，每个文件带一个 `$I` 元数据） |
| 清理后释放 | **约 52 GB**（C 盘剩余 27.26 GB → 79.18 GB） |
| 回收站可打开耗时 | 清理前**卡死**；清理后 0.12 s |

被删文件的扩展名集中在 `.lock` `.tmp` `.cmake` `.pyi` `.d` `.ninja_lock` —— 就是一棵 Zephyr / Ninja 构建树（`build\<芯片>\<工程>\<配置>`）。

**根因不是编译，是"删除方式"**：编译本身（`west build -p always`、`shutil.rmtree`、`Remove-Item`）都走 .NET 直接删除，**不进回收站**；真正把整棵树送进回收站的是资源管理器 / VS Code 的「删除」，那是 shell 的 `SHFileOperation`。一棵构建树几十万个小文件，条数一多，回收站自己就打不开了。

## 二、做了什么

### 1. 新增 `tools\zephyr\clean-builds.ps1`

- **只删 `<root>\build` 内的路径**（`Test-UnderBuildRoot` 白名单），其它一律拒绝；
- **默认干跑**，`-Delete` 才动手；`-Protect` 保护正在用的构建目录；
- 判"过期"用构建目录里 `build.ninja` / `.ninja_log` / `CMakeCache.txt` 的 `LastWriteTime`，不看目录 mtime；
- 构建目录识别 = "`build\` 下第一个带 `CMakeCache.txt` 的目录"（sysbuild 子缓存不重复计数）；`_scratch` / `_unsorted` 整层按 `_` 规则单独处理；
- 删除一律 `[System.IO.Directory]::Delete($p, $true)`，**永不进回收站**；前后用 `Get-Volume` 报磁盘剩余变化。

### 2. `tools\zephyr\build.ps1`

- 修搬迁后的路径 bug：脚本 2026-11-18 从 `tools\` 搬到 `tools\zephyr\`，`$root = Split-Path -Parent $PSScriptRoot` 会退化成 `tools\`；改为上两级，并 source 同目录的 `env.ps1`（它认 `kharon.host.yaml` 取根）；
- 修 west 工作区：原来硬编码 `zephyr_k`，仓库现役是 `west\`；改为用 `env.ps1` 暴露的 `$ws`；
- 新增 `-NoPrune`；构建成功后调用 `clean-builds.ps1 -KeepDays 7 -TriggerFreeGB 25 -Protect <当前 BuildDir> -Delete -Quiet` —— **只有 C 盘剩余 < 25 GB 才真干活**，平时零成本。

### 3. `.vscode\settings.json`（新建）

- `files.enableTrash: false` —— IDE 里删文件不进回收站（治本）；
- `files.watcherExclude` / `search.exclude` 排除 `build\` `west\` `zephyr_k\` `.ccache\` `.venv\`。

### 4. 文档

- `tools\zephyr\README.md`：§1 构建表加 `clean-builds.ps1` 一行 + "删构建目录别用资源管理器"提示；
- `docs\zephyr-learn\参考\构建入口与产物规则.md`：新增 §八「清理 `build\`：一条命令，且不进回收站」。

## 三、验证

```powershell
pwsh -File .\tools\zephyr\clean-builds.ps1              # 干跑
pwsh -File .\tools\zephyr\clean-builds.ps1 -All -Protect .\build\esp32s3\s3_wifi_portal\default
```

## 四、还没动的

1. **`tools\` 顶层到 `tools\zephyr\` 的搬迁没做完**：`check-layout.ps1` 仍是 `$root = Split-Path -Parent $PSScriptRoot`，且检查目标写的是 `apps\`（仓库现役是 `applications\`）；`defender_exclude.ps1` 还硬编码 `C:\Users\xiao1\Desktop\esp32\zephyr-learn`。这次只修了 `build.ps1`。
2. **`env.ps1` 是 UTF-8 无 BOM 且含中文**：pwsh 7 正常，Windows PowerShell 5.1 按 ANSI 读会乱码、解析失败（所以 README 里写的"ASCII only 也能在 5.1 跑"对 `build.ps1` 已不成立，因为要 source `env.ps1`）。要么给 `env.ps1` 加 BOM，要么统一只用 pwsh 7。
3. **回收站容量上限没设**：`HKCU\...\Explorer\BitBucket\Volume\{GUID}\MaxCapacity` 可按卷设上限（到顶自动清最旧），属于系统级设置，没替用户改。
