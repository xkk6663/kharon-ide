# 文档路径同步（2026-11-15）

> 变更类型：纯文档（**没有跑编译**）。把 `教程\`、`课程同款\`、`参考\` 及根 README 里指向 2026-11-14 重构前布局的路径，全部换成新布局。

## 为什么这次改成"同步"而不是"保留历史"

2026-11-14 重构时，`教程\` 里的命令故意没动 —— 那些命令和串口输出是当时的原始证据，事后改路径会让"当时的命令"和"当时的输出"对不上。

但放了几天发现代价更大：读者照着敲会得到 `apps\korvo_sys` 不存在、`-d build-sys` 落到错误位置；而真正的一手证据在 `logs\` 里本来就有原件。所以这次改口径：

- **文档正文（命令、路径指引、目录树）** → 按新布局同步；
- **`logs\` 下的串口/构建日志** → 原件不改，以它为准；
- **旧名与新路径的逐条对照** → 保留在 `变更记录\目录结构重构-2026-11-14.md` 第四节，作为历史记录。

## 换算规则

| 类别 | 旧 | 新 |
|---|---|---|
| 源码 | `apps\<工程>` | `apps\<芯片>\<工程>`（`korvo_*` → `esp32s31`；`blinky-s3`/`input_btn`/`s3_wifi_portal`/`korvo_wifi` → `esp32s3`） |
| 构建（顶层旧目录） | `build-s3-portal` 等 | `..\build\esp32s3\s3_wifi_portal\default` 等（按 4.2 表） |
| 构建（工作区内旧目录） | `zephyr-s31\build-sys` 等 | `..\build\esp32s31\korvo_sys\s31-debug` 等 |
| 工程内旧产物 | `apps\<工程>\build\<配置>` | `..\build\<芯片>\<工程>\<配置>` |
| 已归档的验证目录 | `build-check-*` / `build-course-*` | 当时指向 `..\build\_legacy\…`；该归档已于当日删除，现在按 04 §5 命令重建到 `..\build\<芯片>\<工程>\<配置>` |

书写约定统一为：源码路径 = 仓库根相对；构建目录 = `..\build\…`（因为 `west` 必须在 `zephyr-s31\` 里执行）。写进了 `docs\README.md` 的"路径约定"一节。
