# 环境自举：把"本地独有资产"从 zephyr 树里搬进本仓库（2026-11-16）

> 触发问题：`zephyr_k` 这个 west 工作区到底要不要进 git？如果不用，别人 clone 下来怎么才能不缺依赖？

## 一、结论先写

- **`zephyr_k\` 不入库**（上游 clone，84,222 文件 / 0.9 GB，其中 `zephyr\.git` 147 MB；`west.yml` 已逐条钉住 revision，`west update` 就能精确复现）。
- **真正"重 clone 就会消失"的只有三样**，它们必须入库：板级 15 文件、mbedtls 本地补丁、以及"怎么把这两样装回去"的脚本。
- 于是新增三件套：`boards_local\`、`patches\zephyr\`、`tools\bootstrap.ps1`；同时把 `env.ps1` 与 `tools\build.ps1` 里写死的个人绝对路径去掉，否则换台机器脚本第一步就崩。

## 二、为什么要单独拿出板级文件

`zephyr_k\zephyr` 是 `pr-s31` 分支的浅克隆（depth 1），HEAD = `34e025569cbb27660b71db809627c3a7402e2111`（`tests: add esp32s31 driver test overlays`），`git branch` 看是 `## pr-s31`，**没有上游跟踪**。

那块板的 15 个文件（`boards\espressif\esp32s31_function_coreboard\`）**只活在这个 commit 里**：上游若删分支、或换台机器按别的 commit 克隆，这块板就彻底没有了。逐个文件的 SHA-256 已经拷到 `boards_local\esp32s31_function_coreboard\`（15/15 与 zephyr 树内副本逐字节一致，`Compare-Object` 差异 0）。

另一件是 `zephyr\modules\mbedtls\legacy_support.cmake` 的本地改动——`git status --porcelain` 里唯一未提交项。它是给这段加了个存在性守卫：

```cmake
-if(CONFIG_ESP32_BT_LE_CRYPTO_STACK_MBEDTLS OR CONFIG_ESP32_WIFI_MBEDTLS_CRYPTO)
+if((CONFIG_ESP32_BT_LE_CRYPTO_STACK_MBEDTLS OR CONFIG_ESP32_WIFI_MBEDTLS_CRYPTO)
+   AND EXISTS "${MBEDTLS_REMOVED_MODULES_PATH}/ecdh.c")
```

原因：这套树只拉了 crypto/hal 模块，`ZEPHYR_HOSTAP_MODULE_DIR` 为空，`MBEDTLS_REMOVED_MODULES_PATH` 会解析到不存在的路径，CMake 直接报 `Cannot find source file`。导出成 `patches\zephyr\mbedtls-legacy_support.patch`（1211 B，UTF-8 无 BOM，20 行 diff）。

## 三、`bootstrap.ps1` 四步

| 步 | 做什么 | 幂等判据 |
|---|---|---|
| 1 | 前置检查 pwsh 7 / git / python / SDK / cmake / ninja | 只打印，缺什么说什么 |
| 2 | `.venv` + `pip install west`；zephyr 无 blob 浅克隆 + `fetch --depth 1 <pin>` + checkout | `zephyr_k\zephyr\.git` 存在且 HEAD 前 12 位对得上 |
| 3 | `west init -l` + `west update hal_espressif hal_stm32 cmsis_6 mbedtls tf-psa-crypto mcuboot` | `zephyr_k\.west\config` 存在 |
| 4 | 拷 `boards_local` → `zephyr\boards\espressif\`；`git apply` 补丁；写 `tools\local.env.ps1` | `git apply --check` 失败但 `--reverse --check` 通过 = 已打过，跳过 |

只拉 **6 个模块**是有意的：manifest 里 70 个项目，盘上历来只落这 6 个（`modules\hal\{espressif,stm32,cmsis_6}`、`modules\crypto\{mbedtls,tf-psa-crypto}`、`bootloader\mcuboot`）。`west update` 全量会多拉 60 多个用不上的仓。

## 四、`env.ps1` / `build.ps1` 的可移植化

- `env.ps1`：仓库根改成"从脚本路径/当前目录向上找同时含 `env.ps1` 与 `zephyr_k` 的那一层"——**不能裸用 `$PSScriptRoot`**，被 `. .\env.ps1` 点源时它会退化成当前目录（实测：在 `C:\...\zephyr-learn` 里点源却把根算成 `C:\Users\xiao1\Desktop\esp32`）。SDK 三级回退 = 环境变量 > `tools\local.env.ps1`（bootstrap 写入，已 gitignore）> 常见位置搜 `zephyr-sdk-*` 且必须含 `gnu\arm-zephyr-eabi\bin`。PATH 只加真实存在的目录；`.tools\` 下的 cmake/ninja/ccache 同样"存在才加"，优先于系统 PATH。
- `tools\build.ps1`：第 36 行 `$root` 从写死路径改成 `Split-Path -Parent $PSScriptRoot`（该脚本按约定仍保持纯 ASCII，PS 5.1 也能跑）。
- `tools\check-layout.ps1` 本来就是派生根，无需改。

## 五、验证

| 项 | 命令 | 结果 |
|---|---|---|
| 板级副本一致 | `Compare-Object`（15 文件 SHA-256） | 差异 0 |
| 补丁与现状一致 | `git -C zephyr_k\zephyr apply --reverse --check patches\zephyr\mbedtls-legacy_support.patch` | exit 0（说明树里就是这条改动） |
| 自举脚本静态可用 | `pwsh -File .\tools\bootstrap.ps1 -DryRun` | exit 0，清单打印正常（不联网、不改文件） |
| 钉住 commit 可直取 | 空仓 `git fetch --depth 1 --filter=blob:none https://github.com/zephyrproject-rtos/zephyr 34e025569cbb…` | exit 0；`ls-tree …:boards/espressif` 里有 `esp32s31_function_coreboard`。同一条命令对 gitee 镜像报 `not our ref` |
| `west init -l` 可用 | 临时顶层目录 + 假 manifest 仓（真 `west.yml`） | 生成 `.west\config`、exit 0（探针目录已删） |
| 6 个项目名有效 | `west list --format "{name}"` | 70 个项目里 `hal_espressif` / `hal_stm32` / `cmsis_6` / `mbedtls` / `tf-psa-crypto` / `mcuboot` 全部命中 |
| env 可点源 | 从任意目录 `. .\env.ps1` | `west v1.5.0`、`.tools` 的 cmake/ninja、SDK 全部命中；cwd 切到 `zephyr_k` |
| 布局巡检 | `pwsh -File .\tools\check-layout.ps1` | `5/5`、exit 0（新增 `boards_local\` / `patches\` 不违规） |

**没有跑真实构建**（用户明确要求"别编译了，改好依赖就行"），也没在**空的顶层目录**里跑完整 `bootstrap.ps1`。已单独验证的是：钉住 commit 能直取（GitHub 直连 exit 0、gitee 镜像 `not our ref`）、`west init -l` 能建工作区、6 个项目名在 manifest 里存在、`-DryRun` 与"已就绪则跳过"两条分支。**整条 `west update` 联网流水**要等第一台新机器第一次跑。

顺带发现：本机 7890 端口当时没监听（`Test-NetConnection 127.0.0.1:7890` = False），但**直连 GitHub / gitee 都通**——所以脚本的 `-Direct` 比 `-Proxy` 更可靠。
