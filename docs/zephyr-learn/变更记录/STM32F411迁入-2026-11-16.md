# STM32F411 迁入（2026-11-16）

> 变更类型：**新芯片接入 + 新工程 + 教程并入第 15 组（第二篇）**（全部实机验证：编译 / 烧录 / 串口）

## 背景

树里一直只有 ESP32 两种架构（S31 RISC-V、S3 Xtensa）。要验证"这套六步能不能真的跨到另一家厂商"，手上有一块 **WeAct Black Pill V2.0（STM32F411CEU6）** + **DAP-Link**，接线：
LED = PC13（低电平亮）、按键 = PA0（低电平按下，内部上拉）、串口 = USART1 PA9/PA10。

侦察结论：上游已经带了板级目录 `zephyr\boards\weact\blackpill_f411ce\`，其 dts 与实物完全一致（`led0` / `sw0` / `chosen console=&usart1` / HSE 25 MHz → 96 MHz / 512 KB flash）。所以这一轮**不是"加板"，而是"补齐板之外的三个前置条件"**。

## 决定与理由

| 项 | 决定 | 理由 |
|---|---|---|
| 工具链 | **Zephyr SDK 1.0.1 的第三个目标 `arm-zephyr-eabi`**（14.3.0） | 项目口径统一走 SDK；系统 `arm-none-eabi-gcc`（13.3.1）只用于早期探路，成品全部用 SDK 重编 |
| HAL 模块 | `zephyr-s31\modules\hal\stm32\` **离线复原**（上游胶水文件 + 本地 `STM32Cube_FW_F4_V1.28.2`） | `west update` 与浅克隆实测只有 6~22 KB/s，40 分钟级；复原完整目录后可正常编译 |
| CMSIS | 同一方式复原 `modules\hal\cmsis_6`（Zephyr 4.2 起 Cortex-M 必需） | `core_cm4.h` 等缺失时，报错是 `HAS_CMSIS_CORE* dependencies 0`，不直观 |
| 烧录 | 自写 `apps\stm32f4\common\dap_link_openocd.cfg`，**不修改上游板级 cfg** | 板级那份是 `interface/stlink-dap.cfg` + `dapdirect_swd`（ST-Link 专用）；DAP-Link 用 `cmsis-dap.cfg` + `swd` |
| 呼吸灯 | **软件 PWM**（1 kHz 帧 + `k_busy_wait`，sin² 65 档） | PC13 在 F411 上没有任何 `TIMx_CHy`（只有 GPIO / RTC-TAMP / EXTI13），硬件 PWM 到不了这颗灯 |
| 入口 | 全部经 `tools\build.ps1`：编 `build\stm32f4\f411_breath\default`，烧 `-Flash` → `--runner openocd --config …` | 维持"唯一入口 / 产物只落 build\ / env.ps1 唯一环境"三条规则 |

## 补充轮：按键验证逼出的两个真缺陷（同日）

按键一按就发现两个"只在关灯态出现"的问题，都已改代码并重编重烧（`FLASH 19676 → 19940 B / 3.80%`，RAM 不变）：

| # | 缺陷 | 改法 |
|---|---|---|
| 1 | `breathe=false` 走 `k_msleep(1)`，帧 1094 µs > 1050 门限 → `late` 每帧 +1、`frames` 冻结 | 统计块包进 `if (breathe)`；关灯态改打 `breathing OFF (idle, CPU released, frames=…)` |
| 2 | `t=` 用 `cycles_to_us(k_cycle_get_32())` 当秒，96 MHz 下 **44.7 s 回绕**（实测 `t=41 s` 后跳 `t=0`） | 上报节拍改 `k_uptime_get()`（64 位毫秒）；帧周期仍用 cycle 相减 |

顺带确认：抓到的日志偶有 `…e…pressed` 残行是 **DAP-Link CDC 丢字节**（约 1/10），同一份固件 55 s 窗口 28 行全正常 → 属抓取侧，非固件（坑表 15）。

## 补充轮二：硬件 PWM 对照工程 `f411_hwpwm`（同日）

新增 `apps\stm32f4\f411_hwpwm`（与 `f411_breath` 并列，互不影响）：TIM4 CH1 → **PB6**（sin² 呼吸）、CH2 → **PB7**（反相），复用同一张 65 档亮度表；`prj.conf` 只多一行 `CONFIG_PWM=y`。

| 坑 | 现象 | 处置 |
|---|---|---|
| 16 位 ARR | 1 kHz 直接 `pwm_set()` 返回 `-134`（-ENOTSUP）：96 MHz / 1 kHz = 96000 > 65535 | 新增 `boards\blackpill_f411ce.overlay`，`&timers4 { st,prescaler = <1>; }` → 48 MHz、ARR 47999 |
| overlay 不生效 | 增量 configure 不重算 overlay 列表，`zephyr.dts` 里仍是 `st,prescaler = <0x0>` | 首次必须 `build.ps1 -Pristine` |
| 软复位无效 | `openocd -c "init; reset run"` 报 `Failed to read memory at 0xe000ed04` | 按板上 `R` 键或重新插拔 USB（坑表 18） |

实测：`configure=37.8s build=9.5s total=47.3s`、`FLASH 21824 B / 4.16%`、`RAM 5632 B / 4.30%`；串口寄存器回读 `psc=1 arr=47999 ccr1=duty×48 ccr2=(1000−duty)×48`，`96 MHz / 2 / 48000 = 1000 Hz` 精确成立。证据：`logs\f411-hwpwm-build.log`、`logs\f411-hwpwm-serial.txt`。波形未上示波器，外接 LED 亮度对比属肉眼判断。

## 遗留问题（写在这里，别让它变成"以后再说"）

1. `modules\hal\stm32\` 与 `modules\hal\cmsis_6\` **不是 git 仓库**。以后若要 `west update`，它会因为"目录非空"报错——**只能删掉重拉**（网络好时再走标准流程）。
2. 烧录日志末尾的 `Failed to read memory at 0xe000ed04` 是"没有硬复位线"的必然噪音，`flashed OK` 已说明成功；要彻底干净得把 DAP-Link 的 nRESET 接到板上 R 脚。
3. `tools\probe_serial.py --reset`（拉 RTS）对 DAP-Link CDC **无效**，STM32 复位只能靠 OpenOCD（教程 11.4 已写明）。
4. `tools\check-layout.ps1` 本机当时是 **3/5**：两条 FAIL 来自 2026-11-15 的 S3 OTA 在建工作（`apps\esp32s3\s3_wifi_portal\build`、`build\esp32s3\s3ota` 下的 sysbuild 子缓存），**与本轮无关、也没有替用户清理**。本轮只做了一处合规改动：`$allowedTop` 加入 `stm32f4`，否则新芯片的构建目录会被误报"层级不合规"。
