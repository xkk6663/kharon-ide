# 仓库瘦身（2026-11-15）

> 变更类型：删归档 + 清死代码审计 + 脚本归位。**没有跑编译**。

## 一、起因

问"仓库能不能真正变小"。实测后发现：**git 仓库本身只有 1.5 MB**，历史里最大的对象是一条 181 KB 的日志，压不动。真正占地方的是工作区里可重建的东西：

| 目录 | 体积（改之前） | 性质 |
|---|---|---|
| `build\_legacy\` | **1,696 MB** | 2026-11-14 重构前 39 个旧构建目录，已 gitignore |
| `zephyr-s31\` | 682 MB | 上游源码（west 工作区），必须留 |
| `.venv\` | 501 MB | west/python 运行环境，重建要几分钟，建议留 |
| `.tools\` | 120 MB | cmake/ninja/ccache 本体 |
| `.ccache\` | 102 MB | 编译缓存，`ccache -C` 可清（代价是下次全量） |
| `docs\ apps\ tools\` | 1.1 MB | 代码与文档，本来就不大 |

## 二、做了什么

### 1. 删除 `build\_legacy\`（回收 1.7 GB）

- 删前先把唯一的映射原件 `_migration-manifest.json`（39 条 `From`/`To`）转存为
  `docs\变更记录\目录结构重构-迁移清单-2026-11-14.json`；
- 再整目录删除：`Remove-Item -LiteralPath build\_legacy -Recurse -Force`（先 `Resolve-Path` 校验绝对路径确实落在本仓库 `build\` 下）；
- 第一次删除执行到一半被打断，剩 30 个条目（1,674 MB），二次删除补完；
- 结果：`build\` 从 1,808 MB → **112 MB**，只剩 `esp32s31\`、`esp32s3\`、`samples\` 三个正常层。

**代价（要说清）**：归档里那些 `zephyr.bin` / `.elf` / `.map` 一起没了。要镜像就重新编（`tools\build.ps1`，一个工程几分钟）。历史对照关系不受影响——4.2 表和迁移清单都在。

### 2. `tools\` 审计结论：20 个文件，**一个没删**

按引用扫了 148 个 `md/ps1/py/conf/json` 文件：

| 分类 | 文件 | 引用数 |
|---|---|---|
| 高频入口/工具 | `build.ps1` 28、`serial_cmd.py` 21、`usb_cmd.py` 14、`probe_serial.py` 11、`wifi_bench.py` 10、`read_serial.py` 9、`check-layout.ps1` 8、`fetch_s3_blobs.ps1` 3、`ble_scan.py` 2 | 都在文档里有实际命令 |
| 提交流水线 | `commit_wifi_milestone.ps1` → 调 `syntax_check_main.py`、`selftest_wifi_bench.py` | 一条链 |
| 编译速度实验 | `speed_bench.ps1` / `speed_bench2.ps1` / `speed_bench3.ps1` / `speed_full.ps1` / `ccache_micro.py` / `defender_exclude.ps1` | 见下 |
| 一次性留档 | `fetch_tfpsa.ps1`、`_rollback-layout-2026-11-14.ps1` | 各自 1 处 |

**原本准备删的 5 个"零引用"脚本，逐个看过内容后全部保留**：

- `defender_exclude.ps1` —— **这是真正的提速手段**：把 `build\`、`.ccache`、`zephyr-s31\`、SDK 加进 Defender 排除项，避免实时扫描反复扫几万个 `.o/.d`。文档里一直写着"需要管理员、我没替你改"，它就是那条命令的实现。
- `speed_bench.ps1/2/3`、`speed_full.ps1` —— 同一实验的三代草稿 + 一次最正式的重跑。**它们本身不加速编译**，是"量出来到底哪套参数最快"的测量脚本（ccache 冷/热全量对照就是这么得到的）。留着是为了以后换机器能照同一口径复测。

### 3. 把这套实验工具归位（不停留在"能跑但破坏布局"）

- 4 个 bench 脚本的临时构建目录：`仓库根\tmp-speed-*` → `build\_scratch\speed-A…D / r1…r3 / s1…s2`，不再往仓库根扔目录；
- `ccache_micro.py`：`build-s3-ble\compile_commands.json`（该目录已随归档删除）→ 自动在 `build\` 下递归找第一个 `compile_commands.json`，输出对象改到 `build\_scratch\ccbench\`；
- `_rollback-layout-2026-11-14.ps1`：加头部警告——`From = 'build\_legacy\…'` 的条目已失效，回滚 `apps\` 时要先注释掉那几行；
- 新增约定 `build\_scratch\`：`_` 开头只给系统用，`_scratch` = 可整删的实验临时目录（`_unsorted` 仍是"违规落点"）。

### 4. 文档同步

改动涉及"归档还在"的 6 处说法，全部改成"已于 2026-11-15 删除"：根 `README` 目录树与重构段落、`变更记录\目录结构重构`（顶部提示 + 4.2 表脚注 + 回滚节 + 遗留项）、`变更记录\构建入口收口`（遗留项）、`参考\构建入口与产物规则`（树、`_` 命名规则、巡检第 4 项）、`课程同款\README`（两处可删清单）、`变更记录\文档路径同步`（两处换算说明）。

`参考\编译速度优化.md` 另外补了一节"七点一、这套实验用的是哪些脚本"（7 个脚本各干什么、输出在哪、该用哪个），并把第五节 ① 的 Defender 排除路径改成新布局 + 给出 `pwsh -File .\tools\defender_exclude.ps1`。
