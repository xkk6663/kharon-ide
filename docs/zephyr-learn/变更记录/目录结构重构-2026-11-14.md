### 四条规则

1. **工程只按芯片分组，不按用途分组**：`apps\esp32s31\` 与 `apps\esp32s3\` 两级，芯片之上不放中间层。
2. **一期工程只有一个家**：`korvo_*` 主开发板是 Korvo-1，就放 `esp32s31\`；它同时能编 S3，S3 产物落在 `build\esp32s3\korvo_sys\s3-debug`，**不因此再复制一份源码目录**。
3. **产物永远在项目根的 `build\`**：格式固定 `build\<芯片>\<工程>\<配置>`；上游 sample 走 `build\samples\<芯片>\<样例>\<配置>`。工程目录里不再出现 `build\`。
4. **相对路径只允许往上找**：`apps\<芯片>\<工程>\boards\*.overlay` 引共享 dtsi 统一用 `../../../common\`；`CMakeLists.txt` 的 `KORVO_COMMON` 用 `../../common`。

## 二、为什么原来那么乱（根因，不是"随手放"）

| 根因 | 表现 |
|---|---|
| `tools\build.ps1` 的默认构建目录是 `$root\build-<工程名>` | 顶层平铺 `build-s3-portal`、`build-sdk-riscv`… 每编一个工程就在根上多一个目录 |
| `CMakePresets.json` 里 `binaryDir = ${sourceDir}/build/${presetName}` | 走 preset 编出来的产物藏在 `apps\<工程>\build\<preset>\`，和 west 的构建**两套位置** |
| 手敲 `west build -d ...` 时按板子和主题起名 | `zephyr-s31\build-*` 一个工程多份：`build-apps` / `build-check-apps` / `build-course-apps` / `build-s3-apps` 全是 `korvo_apps` |
| 板子差异没进目录名 | `apps\` 12 个工程平铺，芯片信息只藏在名字后缀（`-s3`、`korvo_`）和 board 名里 |

理顺后：顶层 build 目录 **29 → 0**，`apps\` 顶层目录 **12 → 4**（`_template`、`common`、`esp32s31`、`esp32s3`）。

## 六、怎么验证搬迁没搬坏

**本次只做了静态校验**（按你的要求不跑编译）：11 个 overlay 的 `#include "../../../common/…"` 全部能解析到实体文件；两个工程的 `KORVO_COMMON` 指到 `apps\common\{src,include}`；9 个 `CMakePresets.json` 里所有 `binaryDir` 换算后 100% 落在 `build\<芯片>\<工程>\<preset>`；`apps\` 下已不存在任何 `build\` 目录。**没跑 cmake 配置和编译**——第一次真编时如果报错，先看下面这两条命令。

> 旁证：`build\esp32s3\s3_wifi_portal\` 里那份构建缓存（11-15 00:05 生成）记录的 `APPLICATION_SOURCE_DIR` 已经是 `…/apps/esp32s3/s3_wifi_portal`、`BOARD` 是 `esp32s3_devkitc/esp32s3/procpu`，说明搬完目录后按新路径配置这条链路是通的，可以接着往里编。

```powershell
. C:\Users\xiao1\Desktop\esp32\zephyr-learn\env.ps1

# 1) S31 一侧：overlay 的 ../../../common 与 KORVO_COMMON 是否能解析
west build --cmake-only -b esp32s31_function_coreboard/esp32s31/hpcore `
  "$root\apps\esp32s31\korvo_sys" -d "$root\build\esp32s31\korvo_sys\s31-debug"

# 2) 产物落点是否真在 build\ 下（工程目录里不该再出现 build\）
Select-String -LiteralPath "$root\build\esp32s31\korvo_sys\s31-debug\CMakeCache.txt" `
  -Pattern '^(BOARD:|APPLICATION_SOURCE_DIR:|DTC_OVERLAY_FILE:)'

# 3) preset 入口是否指到新路径
cd $root\apps\esp32s31\korvo_apps
cmake --preset s3-debug
```

判断标准：`APPLICATION_SOURCE_DIR` == `…\apps\esp32s31\korvo_sys`；`DTC_OVERLAY_FILE` 指向 `apps\esp32s31\korvo_sys\boards\…overlay`；`BOARD` 与 `-b` 一致。
