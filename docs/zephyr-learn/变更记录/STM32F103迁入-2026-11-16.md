# STM32F103C8T6 迁入（2026-11-16）

> 变更类型：**同系列换型号 + F1 系列离线复原 + 新工程 + 教程并入第 15 组（第三篇）**（全部实机验证：编译 / 烧录 / 串口）

## 背景

第 15 组第二篇刚把 STM32F411CEU6 接进树（`apps\stm32f4\f411_breath`）。这一轮换的是 **Blue Pill（STM32F103C8T6）**，同一支 DAP-Link，接线：
LED = PC13（低电平亮）、串口 = USART1 PA9/PA10、**无用户按键**（板上只有 NRST / BOOT0）。

侦察结论（决定了这一轮的工作量）：**F1 系列在这棵树里完全缺失**——
`modules\hal\stm32\dts\st\` 只有 `f4\`；`modules\hal\stm32\stm32cube\` 只有 `stm32f4xx\`；`modules\hal\cmsis_6\` 只有 `core_cm4.h`。
但 Zephyr 核心仓是齐的：`zephyr\dts\arm\st\f1\` 有 15 个 SoC dtsi，`zephyr\soc\st\stm32\stm32f1x\` 有 SoC 支撑代码，`stm32cube\series_list.cmake` 的 `supported_series` 里已写着 `stm32f1`。
所以这一轮**不是"加板"，而是"把 F1 的厂商包和头文件按 revision 搬回来"**。

## 决定与理由

| 项 | 决定 | 理由 |
|---|---|---|
| 板目标 | 用上游 `stm32f103_mini`（target 名 `stm32f103_mini/stm32f103xe`） | 板级 dts 与 Blue Pill 同构：LED PC13 ACTIVE_LOW、console `usart1` PA9/PA10、HSE 8 MHz → PLL ×9 = 72 MHz；不新建板子（仓库规则里也没有 `boards\`） |
| 容量 | **overlay 里把 `flash0` / `sram0` 改回 64 KB / 20 KB** | 板目标按 F103x**E**（256 KB / 48 KB）建，实物 C8T6 是 64 KB / 20 KB；不改则 size 百分比失真 4 倍 |
| HAL 模块 | 在既有 `modules\hal\stm32\` 里**补 `stm32cube\stm32f1xx\`**：上游 `CMakeLists.txt` + 本地 `STM32Cube_FW_F1_V1.8.6` | 与第二篇同一手法（`west update` 实测只有 6~22 KB/s）；本地有 1.8.4 / 1.8.5 / 1.8.6 三份，取最新 |
| pinctrl | 只补板级 dts **真正 include 的那一个**：`dts\st\f1\stm32f103r(c-d-e)tx-pinctrl.dtsi`（37738 B） | 上游 `dts/st/f1` 有 58 个，只有这一个被 `stm32f103_mini.dts` 引用 |
| CMSIS | 给 `cmsis_6` 补 `core_cm3.h`（顺带 `core_cm0/0plus/1/7/23/33/35p/sc000/sc300`） | F1 的 `stm32f103xe.h` 里写死 `#include "core_cm3.h"` |
| LL 头 | 给 `stm32cube\common_ll\include` 的 22 个 shim 加 `CONFIG_SOC_SERIES_STM32F1X` 分支 | 那些 shim 是上一轮手写的单系列文件，只有 F4 分支，F1 会在 `gpioport_mgr.c` / `stm32_backup_domain.c` 报未声明 |
| 呼吸灯 | **仍是软件 PWM**（1 kHz 帧 + `k_busy_wait`，sin² 65 档） | F103 的 PC13 在复用表里只有 GPIO / RTC-TAMP / EXTI13，没有任何 `TIMx_CHy`——与 F411 同因 |
| 按键 | **不做** | Blue Pill 没有接 GPIO 的按键；板级 dts 也没有 `sw0` 别名，照抄 `DT_ALIAS(sw0)` 会直接编译失败 |
| 探针 | 新建 `apps\stm32f1\common\dap_link_openocd.cfg`（`cmsis-dap` + `swd` + `target/stm32f1x.cfg` + `reset_config none`） | 板级 `board.cmake` 默认是 ST-Link；目标层必须换 F1 |
| 入口 | 全部经 `tools\build.ps1`；产物落 `build\stm32f1\f103_breath\default\` | 维持"唯一入口 / 产物只落 build\ / env.ps1 唯一环境"三条规则 |

## 遗留问题（别让它变成"以后再说"）

1. `modules\hal\stm32\` 与 `modules\hal\cmsis_6\` **仍不是 git 仓**（`west update` 会因"目录非空且不是 git 仓"失败）。**拉齐方式已脚本化**：`pwsh -File .\tools\pull-stm32-modules.ps1`（先 `-DryRun` 看清单），代理稳定后一次跑完；脚本会把旧目录挪到 `zephyr-s31\_offline_bak_<时间戳>\` 备份，失败自动挪回。删掉重拉时要补的 F1 内容也就是正文 §4~§7 那四步——上游仓里本来就有，不必再手工补。
2. `common_ll\include` 那 42 个 shim 是**手写文件**，不属上游。以后再加 F0 / F7 / L4，需要再补一条 `#elif`；这份"shim 维护成本"是离线复原的代价——正确解法就是 §补充轮 那个脚本，一次换成上游仓，42 个文件全部由上游替换（上游版本里每个系列分支都是现成的）。
3. 板目标 `stm32f103_mini` 的 SoC 是 `stm32f103xe`，我们只在本工程 overlay 里改了小容量；**没有改上游板定义**（也不该改）。将来若编译更大的 F103 工程，请注意"容量分母"这件事要再说一遍。
4. 烧录末尾 `Failed to read memory at 0xe000ed04` 仍是噪音，但**这一轮它有时真复位、有时不复位**（同一命令两次结果不同）。要确定性复位：按 NRST 或重新插拔 USB。
5. `tools\check-layout.ps1` 本机当时是 3/5，两条 FAIL 来自 2026-11-15 的 S3 OTA 在建工作（`apps\esp32s3\s3_wifi_portal\build`、`build\esp32s3\s3ota` 下的 sysbuild 子缓存），**与本轮无关、也没有替用户清理**。本轮只加了 `stm32f1` 白名单。

`west list` 现在四行都对得上 pin。**真正的坑是 URL**：`west.yml` 里 crypto 两条没写 `url`，走 `defaults: remote upstream`，仓在 `github.com/zephyrproject-rtos/{mbedtls,tf-psa-crypto}` 镜像里，不在 `Mbed-TLS/…` 原厂。按原厂 URL 拉，克隆能成但取 pin 报 `upload-pack: not our ref …`（看着像网络问题，实测 22 次一模一样）。换成 zephyrproject-rtos 镜像后 `ls-remote HEAD` 正好等于 pin，整仓浅克隆直接就是对的 revision。
另一个取舍：crypto 只有 20 MB 量级，**不要走无 blob + 稀疏**——`tf-psa-crypto` 试过一次，卡在 `checkout`（稀疏后 checkout 仍要按需抓几百个 blob），改整仓就干净落地。脚本里这条按 `big` 标志控制的，已改回整仓。
期间还补了个真 bug：整仓克隆路径原本没处理"HEAD 不是 pin"，现在会补 `fetch --depth 1 + checkout`（对 crypto 这两个用不上，但对默认分支 ≠ pin 的仓是必需的）。

旧 crypto 目录备份（`_offline_bak_20261116-200929\mbedtls`、`_offline_bak_20261116-201946\tf-psa-crypto`）**暂时留着**，等 ESP32 复编通过再清。
