# 构建入口收口（2026-11-15）

> 变更类型：约定 + 工具（**没有跑编译**，全部是静态配置与脚本改动）

## 背景：留下来的口子

2026-11-14 的目录重构把产物统一到了 `build\<芯片>\<工程>\<配置>`，但那是靠两份东西维持的：

1. `tools\build.ps1`（自动推算目录）
2. 9 个 `CMakePresets.json` 的 `binaryDir`

两者之外，**任何人手敲一次 `west build <app>`（不写 `-d`）就绕过去了** —— 产物落在当前工作目录的 `build\`：在仓库根跑就是仓库根的 `build\`，在 `zephyr-s31` 跑就是工作区里的 `build\`。重构前那一堆 `build-*` 就是这么长出来的。

## 决定

| 项 | 决定 | 理由 |
|---|---|---|
| 唯一入口 | `tools\build.ps1` | 它已经能按 board 推芯片、按 app 推工程名 |
| 裸命令的落点 | `build\_unsorted\<app>` | 既不污染仓库根，又留下痕迹，`build/` 本就 gitignore |
| 入口外的 `-BuildDir` | 默认拒绝，`-AllowOutsideBuild` 放行 | 写死在脚本层，比口头约定可靠 |
| 判据 | 新增 `tools\check-layout.ps1`，5 项检查 | 让"布局是否合规"可执行、可 CI |

**没有**采用 `dir-fmt = build/{app}/{board}` 那种方案：`{board}` 是 `esp32s31_function_coreboard/esp32s31/hcore` 三段式，展开后会变成 5 级目录，而且提取不出"芯片"这一层 —— 只能兜底，不能承担主路径。

## 验证（全部静态，未编译）

**dir-fmt 展开结果**（按 `build_helpers.py:189` 的 `find_build_dir` 逻辑复算 `os.path.abspath(fmt.format(...))`）：

```
korvo_sys   -> C:\Users\xiao1\Desktop\esp32\zephyr-learn\build\_unsorted\korvo_sys
hello_world -> C:\Users\xiao1\Desktop\esp32\zephyr-learn\build\_unsorted\hello_world
```

**巡检首次跑出 78 条 FAIL，全部是脚本自身的两个 bug**（值得记一笔，避免下次误判）：

1. `CMakeCache.txt` 里 `APPLICATION_SOURCE_DIR` 是**正斜杠**（`C:/Users/...`），和 `C:\Users\...` 直接 `StartsWith` 永远为 false → 已统一换斜杠再比。
2. preset 的 `binaryDir` 是**相对工程目录**的 `../../../build/...`，我原来当成 `${sourceDir}/...` 处理，`GetFullPath` 相对的是进程工作目录，于是所有 preset 都被判"不在 build 下" → 已改成先替换 `${sourceDir}`，相对写法则 `Join-Path` 到 preset 所在目录再解析；同时子 preset 缺 `binaryDir`（靠 `inherits`）不再算错。

修完复跑：

```

OK: 布局合规
```
