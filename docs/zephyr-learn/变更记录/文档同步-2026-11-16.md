## 4. 为什么"架构文档"最容易过期

`项目架构与依赖树.md` 是一篇**结构快照**，它的每一行数字都对应一次现场盘点。三类改动会让它立刻失真：

1. **拉新模块**（`hal_stm32` / `cmsis_6` / `mcuboot`）→ §7 的三张表全变；
2. **加新工程或新芯片目录**（F411/F103）→ §2.1 的树、§8 的"多少个工程"变；
3. **组件层长大**（`ota_engine`、`breath_sync`）→ §8 的"组件层是什么"变，而这一节恰恰最容易被当成"设计原则"引用。

维护约定已经写进那篇的末尾：**改结构就必须重跑 §10 的命令并更新核查日期**，别凭记忆改数字。
