# 08 · 教程主线选型：主干 Zephyr + S3，还是补丁 Zephyr + S31

> 触发问题：教程前言写着"Zephyr 主干不支持 ESP32-S31"，那**我们的 S3 是主干支持的**，能不能改用主干 Zephyr 做教程？怎么迁移？两者区别在哪？
>
> 本文所有结论都带本仓库内的证据路径，可以逐条复验。

---

## 0. 一页结论

| 问题 | 答案 |
|---|---|
| 主干 Zephyr 支持 S3 吗？ | **支持，而且是"一等公民"**：`zephyr\boards\espressif\esp32s3_devkitc\` 在主干树里，板目标 `esp32s3_devkitc/esp32s3/procpu`，不需要任何补丁 |
| 能拿主线教程吗？ | **能，而且比 S31 更适合当主线**——WiFi / BLE / I2S / SD 卡 / 并口屏（LCD_CAM + MIPI-DBI）/ DVP 摄像头在 S3 上都已经有 SoC 节点和驱动 |
| 迁移要改什么？ | **三层，只改前两层**：① 板目标字符串 ② `boards\` 下的 overlay（引脚重映射）③ 应用代码几乎零改 |
| 两者最大区别？ | 支持来源（补丁 vs 主干）、能力面（S31 少 5 类控制器）、尺度参数（ADC 17 位 vs 12 位） |
| 建议怎么排？ | **三层**：S3 当主线；STM32 当"迁移练习"（主干有 30 个 STM32 系列 / 397 个 ST 板级目录，换架构、换厂商、换 pinctrl 语法最彻底）；S31 Korvo-1 当"未合并 SoC 支持"的附录案例——它反过来是最好的教学素材 |

---

## 1. 先纠正一个理解偏差：我们这份工作区到底是"主干"还是"补丁"

教程前言那句"主干不支持 S31"是对的（截至本文，S31 的 SoC 层还挂在 PR `zephyrproject-rtos/zephyr#119851` 上）。但**我们本地这份 west 工作区是"主干 + 那个 PR 的补丁"**，证据：

```
west\zephyr\soc\espressif\esp32s31\          ← SoC 层（PR 带进来的）
west\zephyr\boards\espressif\esp32s31_function_coreboard\   ← 板级（同样是 PR 带的）
```

所以准确说法是：

- **主干本来就有**：`esp32`、`esp32s3`、`esp32c3`、`esp32c6`、`esp32p4`…… 一堆 SoC 和板子；
- **主干没有**：`esp32s31`（以及 Korvo-1 这块板）；
- 我们的工作区 = 主干 + 一个还没合并的 PR。这决定了 S31 上任何"驱动没通"的问题都只能靠"等上游 / 绕驱动"，而 **S3 上不会有这个问题**。

## 2. S3 在主干里到底支持到什么程度（带证据）

以下全部在本仓库 `west\zephyr\` 内可验：

| 能力 | S3 状态 | 证据 |
|---|---|---|
| 板级定义 | ✅ 主干自带 | `boards\espressif\esp32s3_devkitc\`（同族还有 `esp32s3_eye`、`esp32s3_box3`） |
| 板目标 | ✅ | `esp32s3_devkitc/esp32s3/procpu`（`procpu/appcpu` 是 CPU 簇，`qemu` 才是变体） |
| WiFi | ✅ 有 dts 节点 + 驱动 | `dts\xtensa\espressif\esp32s3\esp32s3_common.dtsi:73` `compatible = "espressif,esp32-wifi"`；驱动 `drivers\wifi\esp32\` |
| BLE | ✅ | 同上 `:78` `espressif,esp32-bt-hci`；`drivers\bluetooth\hci\hci_esp32.c:24` 白名单含 `ESP32S3` |
| I2S | ✅ | `esp32s3_common.dtsi:269` `i2s0` |
| SD 卡（SDMMC） | ✅ | `esp32s3_common.dtsi:461` `sdhc` + `sdhc0/1`；`drivers\sdhc\sdhc_esp32.c:32` 只 gate `ESP32S3/ESP32P4` |
| CAN（TWAI） | ✅ 有控制器 | `esp32s3_common.dtsi:483` `twai`，且是 `zephyr,canbus` chosen |
| 并口屏（LCD_CAM / MIPI-DBI） | ✅ **有 SoC 节点 + 有驱动** | `esp32s3_common.dtsi:606` `lcd_cam`；`:620` `lcd_cam_disp`（`espressif,esp32-lcd-cam-mipi-dbi`）；驱动 `drivers\mipi_dbi\mipi_dbi_esp32.c` |
| 摄像头（DVP） | ✅ | `esp32s3_common.dtsi:615` `lcd_cam_dvp`；驱动 `drivers\video\video_esp32_dvp.c` |
| WS2812 / RMT | ✅ | `drivers\led_strip\ws2812_rmt_esp32.c` |
| ADC | ✅ 但 **12 位**（硬写 17 会 `unsupported resolution`） | 见 `docs\参考\平台现状与坑.md:59` |

**关键的一条**：`drivers\mipi_dbi\mipi_dbi_esp32.c` 的存在意味着——**"点一块 8080/DBI 并口屏"这件事在 S3 上有现成通路**，而在 S31 上是"SoC 节点 + pinmux + 驱动全缺"（`esp32s31_common.dtsi` 里 `lcd_cam|i2s|sdhc` 命中 0 条，实测命令见附录）。

## 3. 两块的差别，一张表说完

| 维度 | ESP32-S31（Korvo-1 V1.1） | ESP32-S3（DevKitC-1 / 最小板） |
|---|---|---|
| 支持来源 | 主干 + **未合并 PR #119851** | **主干直接支持** |
| 板级 | PR 附带的 `esp32s31_function_coreboard`（15 文件，**不是你的板**） | `esp32s3_devkitc`（17 文件，就是这块板） |
| 板目标 | `esp32s31_function_coreboard/esp32s31/hpcore` | `esp32s3_devkitc/esp32s3/procpu` |
| 工具链 | SDK 1.0.1 `riscv64-zephyr-elf` | SDK 1.0.1 `xtensa-espressif_esp32s3_zephyr-elf` |
| 控制台 | `uart0`（CP2102，COM9） | 板级默认 `uart0`，最小板只有原生 USB → overlay 切 `usb_serial` |
| ADC | 17 位，**驱动在 S31 上不可靠**（见 `07` §9.1） | 12 位，驱动成熟 |
| WiFi / BLE | ❌ 白名单不含 S31 | ✅ |
| I2S / SD / LCD_CAM / DVP | ❌ SoC dtsi 无这些节点 | ✅ 全有 |
| 板载外设 | WS2812(GPIO37)、四键(ADC IO42)、ES8389、4.3″ 并口屏子板、DVP 摄像头 | 只有 BOOT/RGB，其它靠自己接 |
| 分区 | `storage` @ `0xfb0000` / 192 KB | `storage` @ `0x3b0000` / 192 KB（**名字相同 → `store.c` 不用改**） |
| flash 声明 | 16 MB | dts 写 8 MB，芯片实际 16 MB（启动有警告，正常） |

## 4. 怎么迁移：三层，只有前两层要动手

### 4.1 第一层：板目标（一行）

```powershell
cd C:\Users\xiao1\Desktop\ELAB\kharon-ide
. .\tools\zephyr\env.ps1
west build -d C:\Users\xiao1\Desktop\ELAB\kharon-ide\build\esp32s31\korvo_periph\s3-debug `
  -b esp32s3_devkitc/esp32s3/procpu `
  C:\Users\xiao1\Desktop\ELAB\kharon-ide\applications\esp32s31\korvo_periph
```

顺手改 `CMakePresets.json` 里的 `s3-debug` 预设（仓库里已有这个预设，直接复用）。

### 4.2 第二层：`boards\` 下的 overlay（文件命名是自动命中的）

Zephyr 认文件名，规则是 `boards\<board>_<soc>_<variant>.overlay`：

```
applications\esp32s31\korvo_periph\boards\esp32s31_function_coreboard_esp32s31_hpcore.overlay   ← S31
applications\esp32s31\korvo_periph\boards\esp32s3_devkitc_esp32s3_procpu.overlay                  ← S3（新建）
```

仓库里同类文件已存在的有 `applications\esp32s31\korvo_apps\boards\esp32s3_devkitc_esp32s3_procpu.overlay`，可以直接抄结构。**S3 那份要改的地方**（都是"板子不同"而不是"代码不同"）：

| 要改的 | S31 的写法 | S3 的写法 | 为什么 |
|---|---|---|---|
| 控制台 | 板级默认 `uart0` 够用 | `chosen { zephyr,console = &usb_serial; }` | 最小板只有原生 USB 口 |
| WS2812 引脚 | `RMT_OUT0_GPIO37` | **`RMT_OUT0_GPIO48`**（DevKitC-1 v1.1 的 RGB 在 IO48；v1.0 是 IO38） | 板载灯换脚了 |
| 按键节点 | `/gpio_keys` | `/buttons`（`debounce-interval-ms` 也在这） | 两侧板级 dts 命名不同 |
| 功放 | `pa-ctrl` 别名（GPIO7） | 没有 → 删掉这条别名 | S3 小板上没有 PA |
| ADC | `adc0`（+ §9.1 的 unit 修正） | `adc0/adc1` 直接可用，**12 位** | SoC 不同 |
| 屏幕 | 无（S31 无 LCD_CAM） | 可加 `lcd_cam_disp` + `mipi-dbi` 子节点 | S3 有控制器 |

### 4.3 第三层：应用代码——基本不用动

这一层是最值得在教程里强调的：**同一份 `main.c`，换 overlay 就换板子**。仓库里已经实证过：

- `docs\参考\工程结构与可迁移性.md:226` —— "同一份 `applications\esp32s31\korvo_apps`，只靠 `boards\esp32s3_devkitc_esp32s3_procpu.overlay` 加一层，就编出了 S3 固件并跑通"；
- `logs\s3-flash-and-key.txt` —— S3 烧录 `215716 bytes`，`app btnsim` → `app btn` 打出"按下=1 次，短按=1 次"，input 子系统整链通。

需要动的地方只有两类：

1. **Kconfig**：S3 的 `CONFIG_INPUT=y` 放在 `boards\esp32s3_devkitc_esp32s3_procpu.conf`（板级专属 conf），别塞进公共 `prj.conf`；
2. **数值常量**：ADC 12 位 → 判窗的原始值要按 `2^12` 重算（S31 那套 17 位的窗口不能照搬）。

## 5. 教程结构建议（这条是重点）

### 5.1 主线换成 S3，理由是"可复验"

教程是写给别人跟着做的。跟着做的人会遇到两个问题：

1. 他有没有那块 Korvo-1？没有就卡在第一步；
2. 有的话，他得先把 PR 打上、把 S31 的 SoC 层编译过——这一步一旦上游 rebase，教程里的 commit 就失效。

而 S3 主线：

```powershell
west build -b esp32s3_devkitc/esp32s3/procpu samples\hello_world
```

**不需要任何补丁**，读者拿任意一块 S3 DevKitC 就能复现。这对"系统学 Zephyr"的定位是更合适的。

### 5.2 第三、四课怎么落在 S3 上

| 课程知识点 | S3 上的落地 | 差异提示 |
|---|---|---|
| 工程配置 / 自定义板级 | 给 `esp32s3_devkitc` 加自己的 overlay（`boards\...overlay`），这才是课程里的"布局 B"思路 | 不用造 SoC 层，难度正好落在"DT + pinctrl"这一层 |
| `chosen` 节点 | console 切 `usb_serial` | 课程里 `chosen` 那一节就是为这种场景准备的 |
| 迁移 / 新建 / 缓存 | `west build -d` 多 build 目录 + ccache，完全一致 | 与芯片无关 |
| 按键输入 | `input` 子系统 + `gpio-keys` + `k_msgq` | S3 上 ADC 12 位，若做 ADC 电阻梯要重标定 |
| 三层驱动模型 | 可用 `led_strip`(RMT) / `pwm`(LEDC) / `i2c` / `spi` / `sensor` | S3 还多 `i2s`、`sdhc`、`mipi_dbi`，可以加课 |

### 5.3 中间再插一层：STM32 当"迁移练习"

主线 S3 + 附录 A 只解决两件事：怎么从零跑起来、怎么理解未合并的 SoC。还缺一块："**换到完全另一家厂商**会怎样"。

STM32 正好做这件事，因为它把差异一次拉满：

| 维度 | S3 | STM32（Nucleo/Discovery） |
|---|---|---|
| 架构 | Xtensa | **ARM Cortex-M** |
| 工具链 | `xtensa-espressif_esp32s3_zephyr-elf` | **`arm-zephyr-eabi`**（本机 SDK 目前没装，`west sdk install -t arm-zephyr-eabi`） |
| pinctrl 语法 | ESP 的 `esp32s3_pinctrl.h` 宏 | 标准 Zephyr `pinctrl`（`&pinctrl` 节点 + `<PIN>_<FUNC>` 宏） |
| 外设控制器 | LEDC / RMT / TWAI | TIM / SPI / I2C / ADC（名字和行为都不一样） |
| 板级数量 | 主干 3 块 | 主干 **397** 个 ST 板级目录、30 个 STM32 系列 |

**做法不是新开一章，而是复用第 15 章的六步**：板目标换 `-b nucleo_xxx/stm32xxx` → 写 `boards\nucleo_xxx.overlay` → 应用层代码不动 → 只改 Kconfig 与数值常量。

实战已验证的迁移路径是 S31 → S3（RISC-V → Xtensa，两家工具链、两个 pinctrl 体系），STM32 只是把"换厂商"这一步也走一遍。**本书把 STM32 标为 📖（未实测）**，因为本机没装 ARM 工具链、也没有这块板；方法本身可用。

### 5.4 S31 Korvo-1 别删，改当附录 A

它反而是**最好的教学素材**，因为它是"主干还没有的芯片"，能讲清一件主干板子讲不清的事：

> **一块新 SoC 是怎么进 Zephyr 的？** SoC dtsi（外设地址/中断/unit 编号）→ pinctrl 头文件 → Kconfig.caps → 板级 15 文件 → 驱动里的 SoC gate。

而且我们踩到的坑正好是这一层的典型错误：

- `esp32s31_common.dtsi:456` 把 `unit` 写成 `<1>`，而 HAL 的 `ADC_UNIT_1` 是 0 → 整条 ADC 通路错位；
- `adc_channel_io_map[unit][ch]` 越界读，ch4/ch5 打出垃圾 io 号；
- `esp32s31_common.dtsi` 里没有 `lcd_cam / i2s / sdhc` 节点 → 板载 4.3″ 屏在 Zephyr 上"造轮子级"。

**这就是"未合并 SoC 支持"的真实成本，写进教程比藏起来有价值。**

## 6. 取舍与风险（不粉饰）

| 迁移到 S3 会失去什么 | 会得到什么 |
|---|---|
| 板载 ES8389 codec（`korvo i2c` 扫 0x10/0x14 这条演示没了） | 主干可复现，读者不用打补丁 |
| 板载四键电阻梯（S31 上本来也没通，见 `07` §9.1） | ADC/input 驱动成熟，按键演示能真跑 |
| 板载 4.3″ 并口屏（S31 需造 SoC 层） | **S3 有 `lcd_cam` + `mipi_dbi` 驱动，接一块 8080 屏就能点**，LVGL 也有落脚点 |
| 板载 DVP 摄像头（S31 只有驱动无节点） | S3 的 `lcd_cam_dvp` + `video_esp32_dvp.c` 是完整链路 |
| — | WiFi / BLE / I2S / SD 卡都能进教程（S31 全无） |

代价只有一个：**要买一块 S3 小板 + 一块 8080 并口屏**（若要做"点屏"那一课）。
