# 平台现状与坑（2026-11 核查）

> **现状校准（2026-11-19）**：本文是 S31（未合并 PR）与 S3 的可行性快照，保留原判据；
> 当前仓库操作主线已切到 **STM32F411/F103 + Kharon**（见 `tutorials/10–14`），
> S31 只作附录 A 的跨架构样本。

## SoC 支持在哪儿

- **主干没有**：`zephyr/boards/espressif/` 下没有 esp32s31 目录；`hal_espressif` 的 README 已支持列表只有 ESP32 / S2 / S3 / C2 / C3 / C5 / C6 / H2 / P4。
- **只有 PR**：<https://github.com/zephyrproject-rtos/zephyr/pull/119851>（`soc: espressif: add esp32s31 initial support`，Open）
  - 附带一块 `esp32s31_function_coreboard`（乐鑫的 S31 function core board，**不是 Korvo-1**）
  - 构建命令：`west build -p -b esp32s31_function_coreboard/esp32s31/hpcore samples/hello_world`
- **Zephyr 从不发板级预编译镜像**，所以"找镜像"这条路本身不成立，只有自己编。

## 那个 PR 已经支持什么

UART、USB-Serial-JTAG、GPIO、pinctrl、I2C、SPI（含 GDMA）、LEDC(PWM)、MCPWM、TWAI-FD（CAN）、ADC、Counter、QDEC、RMT（注释里明确写了用来驱板载 WS2812）、温度传感器、TRNG、AES/SHA、WDT、SPI Flash + PSRAM、`sys_poweroff()` 深睡。

限制：
- **只跑 HP 核，CPU1 保持在复位里** → 双核相关的实验做不了
- **没有 PM（电源管理）** → 只有 `sys_poweroff()` 这一档，没有 tickless  idle 之类的细粒度省电
- 依赖的分支：`hal_espressif` 的 `feature/esp32s31-initial-support`

## 为什么音频和屏幕做不了

- **ES8389 没有 Zephyr 驱动**。`zephyr/drivers/audio/` 下的 codec 驱动只有：aw88298、cs35l5x、cs43l22、da7212、max98091、pcm1681、tas2563、tas6422dac、tlv320aic26/3110、tlv320dac310x、wm8904、wm8960、wm8962。连 ES8311 都没有，ES8389 更没有。
- **I2S 不在上面那个 PR 的已支持列表里**，所以就算有 codec 驱动也没数据通路。
- **4.3″ 子板的 ST7262E43 + GT1151 没有 Zephyr 驱动**。
- 结论：音频和显示继续用 ESP-IDF（乐鑫有现成 BSP：`espressif/esp32_s31_korvo_1_noglib`），Zephyr 那条线只做"控制面 + RTOS 基本功"。

## 会踩的坑（按概率排序）

1. **拿主干的 west.yml 去 build** —— 一定要先切 PR 分支再 `west update`，否则 `hal_espressif` 里没有 S31 的寄存器头文件，报几千行 unknown type。
2. **在 `esp32s31_function_coreboard` 上直接改引脚** —— 它是别的板子，console UART、flash 分区、PSRAM 配置都是按那块板写的。前三个阶段别动它，练习时用 overlay 打补丁。
3. **以为 dts 写了节点就有驱动** —— 还得 `prj.conf` 里 `CONFIG_xxx=y`。
4. **PR 频繁 rebase** —— 记下你验证通过的 commit hash，别盲目跟进。
5. **Kconfig 选项名跨版本变化** —— 抄网上教程的 `CONFIG_` 前先在自己树里 `grep` 一下有没有这个符号。
6. **Korvo-1 上跑 Korvo-1 的板级定义** —— 目前不存在。想做的话是自己写 `boards/espressif/esp32s31_korvo_1/`（`board.yml` + `Kconfig.board` + `.dts` + `_defconfig` + pinmux），这件事本身是很好的 Zephyr 学习项目，但**建议放到阶段 4 之后**，因为写板级定义需要先理解 DT 和 pinctrl。

## 对照：ESP32-S3 是"主干直接支持"的板子（教程 15 组实测）

S31 的处境是"要等 PR"，S3 完全不同——**它就在主干树里**：

| 项 | ESP32-S31（Korvo-1） | ESP32-S3（DevKitC-1 / 最小板） |
|---|---|---|
| 板级定义 | 只有 PR 附带 `esp32s31_function_coreboard` | `boards\espressif\esp32s3_devkitc\`（另有 `esp32s3_box3` / `esp32s3_eye`） |
| 板目标 | `esp32s31_function_coreboard/esp32s31/hpcore` | `esp32s3_devkitc/esp32s3/procpu` |
| 预编译镜像 | 没有 | **一样没有**（Zephyr 从不发 `.bin`） |
| 工具链 | 同一个 Zephyr SDK 1.0.1 的 `riscv64-zephyr-elf`（`VARIANT=zephyr`；早期用 ESP-IDF `riscv32-esp-elf`，已统一） | 同一个 SDK 的 `xtensa-espressif_esp32s3_zephyr-elf`；ESP-IDF 的 `xtensa-esp-elf` 默认大端核，报 endianness mismatch |
| 控制台 | `uart0`（CP2102，能用） | 板级 dts 默认 `uart0`，但最小板只有原生 USB 口 → **要 overlay 切 `usb_serial`** |
| ADC | 17 位 | **12 位**（应用里硬写 17 会 `unsupported resolution`） |
| `storage` 分区 | `0xfb0000` / 192 KB | `0x3b0000` / 192 KB（同样叫 `storage`，所以 `store.c` 不用改） |
| flash 声明 | 16 MB | dts 写 8 MB，芯片实际 16 MB（启动时有警告，正常） |

**额外要记住的一条**：S3 的板级 yaml 里写着 `toolchain: zephyr`——这块板官方就是用 Zephyr SDK 编的，这不是"退而求其次"的选法。细节（原始报错、分段下载、安装目录结构）见 `docs\教程\15-Zephyr跨芯片\换芯片实战.md` 第 2 节。

## 构建环境与编译速度（2026-11 实测，详见 `docs\参考\编译速度优化.md`）

| 项 | 结论 |
|---|---|
| 干净全量（hello_world，257 步，默认并行） | 216.7 s（8C/16T + NVMe） |
| CMake configure 单独 | 25.1 s |
| 无改动重建 | 1.64 s |
| 改一个 `main.c` 的增量（**hello_world 口径**） | 6.59 s |
| 改一个 `.c` 的增量（**`s3_wifi_portal`，分层后 `-j8`**） | **10.5–11.0 s**：no-op 0.82 s、改 L2 文件 11.02 s、改 `main.c` 10.93 s、改 `applications\common\ota_engine.c` 10.53 s |
| 单次极小文件编译 | 123 ms（同机 Linux 通常 25~40 ms） |
| 危险点 | `-j18` 曾把提交内存打光：`cc1.exe: out of memory`；当时可用提交只剩 0.63 GB |
| 修复 | `kharon env` 固定 `CCACHE_DIR`（`.deps\ccache`），`kharon build` 带 ccache + `-j8` + 计时；旧 `tools\zephyr\env.ps1` / `build.ps1` 同样支持 |

**一次真实事故（必须记住）**：`.venv` 曾建在沙箱自带的 Python 3.13 上，沙箱回收后 `west.exe` 报
`did not find executable at '...\sandbox_runtime\...\python.exe'`，**所有构建当场失败**。
已用系统 `Python 3.12.4` 重建，现目录为 `.deps\venv`（历史坏目录保留为 `.venv-broken-3.13`）。教训：**venv 的 base interpreter 必须在稳定的系统路径上**，
不要在临时环境里创建项目 venv；自检一条 `python -c "import sys;print(sys.executable)"` 就能提前发现。
