# 换台机器：从 clone 到能编译

> **现状校准（2026-11-20）**：学习线随 Zephyr 产品线拆到 `kharon-ide`，west topdir 是同级的
> `zephyr-workspace`（不再有 IDE 仓内的 `west\`）；`.deps\` 是本地生成物，`kharon bootstrap`
> 负责补齐，`kharon deps --check` 只做只读校验。旧 `tools\zephyr\bootstrap.ps1` 仍留在树里，
> 但按 `.venv` / `boards_local` 的旧布局写，**当前不要直接跑**；用 `kharon bootstrap` +
> `kharon env`。新机器按下面三步走；缺依赖时按提示补，不猜。

**目标**：fresh clone 后，先让环境可复现，再跑一条最小 Zephyr 构建。

```powershell
git clone <本仓库>
cd kharon-ide
Copy-Item config\host.local.yaml.example host.local.yaml   # 填本机 SDK / 工具链绝对路径
.\kharon.cmd bootstrap                     # 幂等补 venv + west 工作区
.\kharon.cmd deps --check                  # 只读：host / west / SDK / 自研板 module
.\kharon.cmd env --out scripts\kharon-env.ps1
. .\scripts\kharon-env.ps1
.\kharon.cmd build -p f411_breath         # 产物落 build\stm32f4\f411_breath\default
```

如果 `deps --check` 报缺 west/SDK，先按 [`教程/03`](../教程/03-获取Zephyr代码.md)、
[`教程/02`](../教程/02-配置开发环境.md) 补齐；`kharon env` 只生成环境变量，不下载任何东西。

## 前置清单（装一次，之后一直用）

| 东西 | 版本 / 位置 | 必需？ | 说明 |
|---|---|---|---|
| PowerShell 7 | `pwsh` | 必须 | 5.1 不行（脚本用了 `??`、`-Encoding utf8` 等语义） |
| git | 任意 | 必须 | west 全靠它 |
| Python | 3.12 | 必须 | `.deps\venv` 里跑 west |
| Zephyr SDK | **1.0.1** | 必须 | 三个目标链：`arm-zephyr-eabi` / `riscv64-zephyr-elf` / `xtensa-espressif_esp32s3_zephyr-elf` |
| CMake / Ninja | CMake ≥ 3.20.0、Ninja ≥ 1.10 | 必须 | 当前在 `.deps\tools\`，由 `kharon env` 前置 |
| ccache | 4.14.3 | 可选 | 只在构建时加速，没有就自动降级 |
| xpack-openocd | 0.12.0-7 | 可选 | 只影响 `flash`（DAP-Link） |

SDK 的下载页：`https://github.com/zephyrproject-rtos/sdk-ng/releases`。**版本必须对得上 1.0.1**——
`kharon env` 会打印 `ZEPHYR_SDK_INSTALL_DIR` 实际指向哪里。

## 当前自举：`kharon` 负责什么

1. **只读校验**：`kharon deps --check` 逐项打印 host yaml / west 工作区 / `ZEPHYR_BASE` / SDK / 自研板 module，缺什么直接说，不闷着失败。
2. **环境生成**：`kharon env --out scripts\kharon-env.ps1` 从 host yaml + provider defaults 生成 pwsh 脚本；`ZEPHYR_BASE=west/zephyr`，PATH 前置 `.deps\venv`、CMake、Ninja、ccache、`arm-zephyr-eabi`。
3. **构建入口**：`kharon build -p f411_breath` 调内核 `build`，产物落 `build\stm32f4\f411_breath\default`；`kharon flash/debug/monitor` 同理转发。

`kharon deps` 现在是**只读校验**（板子 module 化之后，不再把 `boards_local\` 拷回 west 树）。
真正缺模块时，才按 `west\zephyr\west.yml` 跑 `west update`；不要为了“保险”全量拉 70 个模块。

**S31 的钉住 commit**：`34e025569cbb…` 仍在上游 PR 分支；GitHub 可按 SHA 直取
（`git fetch --depth 1 --filter=blob:none … 34e025569cbb…`），gitee 镜像取不到
（`upload-pack: not our ref`）。复现 S31 时按 [`教程/03`](../教程/03-获取Zephyr代码.md) 的
PR 增量法，不要用 `bootstrap.ps1` 时代的 `-ZephyrRef` 参数（旧脚本仍在，但已不在推荐路径）。

## 哪些进了 git，哪些没进

判断标准就一条：**能不能用一条命令重新拿到**。能拿到的不入库，拿不到的必须入库。

| 对象 | 入库 | 理由 |
|---|---|---|
| `kharon-ide\`（`services\`、`cockpit\`、`docs\`、根 README、`AGENTS.md`）+ `zephyr-workspace\applications\`、`elab-app-common\`、`kharon-manifest\` | ✅ | 本项目自己的东西 |
| `zephyr-workspace\kharon-boards\boards\`（自研板级） | ✅ | 板级住在 module 里，`west update` 不会冲掉；`kharon deps --check` 只读校验 |
| `patches\zephyr\`（如 mbedtls 本地补丁） | ✅ | 对上游 zephyr 的本地改动，重 clone 就丢 |
| `zephyr-workspace\` 里的上游 clone（`zephyr\`、`modules\`、`bootloader\`） | ❌ | `west.yml` 钉 revision，`west update` 能复现 |
| `zephyr-workspace\build\`、`.deps\`（venv/tools/ccache） | ❌ | 可再生成；`build` 里还夹着绝对路径缓存 |
| `scripts\kharon-env.ps1` | ❌ | 由 `kharon env` 生成，每台机器的 SDK 路径不同 |

主仓库跟踪文件数量以 `git ls-files | Measure-Object -Line` 为准（旧文的 2,128 是 11-16 快照）。

## 为什么 zephyr 本体不入库（三句话版）

1. **体量**：它比本仓库大三个数量级，塞进来会毁掉 clone 速度；
2. **可复现**：`west.yml` 把每个项目钉到 revision，`west update` 比"存一份源码快照"更准；
3. **上游自带 `.git`**：再套一层就是嵌套仓库/submodule 语义，`git status`、切换分支、diff 全会变味，而且上游代码有自己的许可证与历史。

## 换机常见故障

| 现象 | 原因 | 处理 |
|---|---|---|
| `west: command not found` | 没建 `.deps\venv` / 没加载环境脚本 | `kharon env --out scripts\kharon-env.ps1` 后 `. .\scripts\kharon-env.ps1` |
| `Cannot find source file stm32f1xx_hal.c` / `core_cm3.h` | 模块没拉齐 | `west update`（按 `west\zephyr\west.yml`），或先 `kharon deps --check` 看缺哪层 |
| `upload-pack: not our ref <sha>` | 用了原厂仓而不是 `zephyrproject-rtos` 镜像 | crypto 两个仓在 `github.com/zephyrproject-rtos/{mbedtls,tf-psa-crypto}`，不是 `Mbed-TLS/…` |
| 拉包时 `early EOF` / 卡在 `tmp_pack` | 代理对大 pack 截断 | 脚本默认走"小请求、多批次"；重跑即可，别用 `-Full` |
| `Failed to connect ... 127.0.0.1:7890` | 代理没开，或端口不是 7890 | 加 `-Direct` 走直连（实测直连 GitHub 能取到钉住的 SHA） |
| `无法将 "﻿#" 项识别为 cmdlet` | 脚本被写坏成双 BOM | 按字节去掉重复 BOM（`pwsh 7` 允许无 BOM） |
| 改了 `prj.conf` / 板级 overlay 后行为没变 | 增量 configure 不重跑 dts | 加 `-Pristine` |
| `region 'dram0_0_seg' overflowed` | 静态 RAM 超预算（S3 槽限 1280 KB） | 先缩 `.c` 里的静态缓冲，再动栈，最后才动 heap |

## 自检口径

```powershell
Set-Location .\west
west list | Select-String "hal_stm32|cmsis_6|mbedtls|tf-psa"   # 四行 revision 要对得上 west.yml
Set-Location ..
.\tools\check-layout.ps1                                       # 期望 5/5、exit 0
```

参考基线（本机实测，2026-11-16）：F103 `-Pristine` 编出 `17104 B`（FLASH 26.10% / RAM 25.55%），F411 `19940 B`（3.80% / 4.25%）。镜像尺寸与基线不一致，先怀疑模块版本而不是应用代码。
