# 同步呼吸灯规则（规范 v1.0）

> **一句话**：亮度是「绝对时间」的纯函数。谁的时间对，谁的灯就对。
> 规则里没有一个字节跟“哪台设备先开机”有关，所以设备之间**不需要通信、不需要选举、不需要握手**。
>
> 核查日期：2026-11（Zephyr 4.x / ESP32-S31 / ESP32-S3 实测）
> 配套实现：`elab-app-common\include\breath_sync.h`、`elab-app-common\src\breath_sync.c`
> 生成脚本：`tools\gen_breath_table.py`　验证程序：`tools\test_breath_sync.c`

---

## 0. 十行速览（要抄就抄这一段）

```text
周期 P        = 4 000 000 us（4 s）
相位锚点 A    = epoch 0（1970-01-01T00:00:00Z）
相位 φ(t)     = (t - A) mod P
归一化 x      = φ / P
相位下标 i    = floor(x × 256)                ← 0..255，查表下标
亮度包络 L    = LUT[i]                        ← 0..255，规范常数，校验和 0x51521FF6
通道值        = base[ch] × L × gain / 255     ← ch = 0..n-1，n=1 单色 / n=3 RGB
二值输出      = (L ≥ 128) ? 1 : 0             ← 开关灯的节拍与 PWM 灯严格同相
```

**三条铁律**：

1. 相位只能由**绝对时间**推导；不得来自上电时长、帧计数、定时器累加。
2. 亮度只能由**同一张 LUT** 决定；不得各自用 `sin()` 现算。
3. 时间是**单调的 UTC 估计**；不得直接用会被校时拨跳的 `CLOCK_REALTIME`。

## 1. 为什么现在的呼吸灯不同步

`applications\esp32s31\korvo_apps\src\main.c` 现在的写法：

```c
case RGB_BREATH:
	env = triangle(now_ms, 2400);      /* now_ms = k_uptime_get_32() */
```

`k_uptime_get_32()` 是「**本机**开机到现在的毫秒数」。这句话里有两个“本机”：

| 现实 | 结果 |
|---|---|
| A、B 两台设备上电时刻相差 1.3 s | 两者相位恒定相差 1.3 s，永不收敛 |
| A 用 25 fps、B 用 10 fps，且实现成 `phase += step` | 呼吸速度不同，越跑越偏 |
| 任意一台重启 | 相位瞬间归零，另一台还在第 2 秒 |

**这不是参数没调好，是坐标系选错了。** 用“相对时间”做周期动画，本质上是让每台设备各走一套时钟。

反过来，只要相位来自**同一套坐标**（UTC），上面三种情况全部自动消失：

- 上电时刻不同 → 不影响，因为算相位根本不看 `uptime`；
- 帧率不同 → 不影响，因为亮度是 `t` 的函数，不是帧序号的函数；
- 重启 → 上电第一帧就正确，因为不需要任何“运行状态”。

> 一处观感差异先说清楚：现在用的是 **2.4 s** 周期（`triangle(now_ms, 2400)`），规范 v1.0 是 **4 s**。接上后呼吸会明显变慢——这是刻意的：2.4 s 是 25 次/分，偏快，更像“紧张”；4 s 是 15 次/分，贴近静息呼吸，而且 60 s 能被 4 s 整除，才能用“整分钟必最暗”做免仪器验收（10.2）。

## 2. 三条铁律（违反其中任意一条，都会失去一致性）

### 2.1 相位只由绝对时间推导

```c
/* ✅ 正确：时间进，亮度出 */
L = breath_envelope(utc_us);

/* ❌ 错误 1：上电时长 */
L = triangle(k_uptime_get_32(), 2400);

/* ❌ 错误 2：帧计数 */
phase += 40;   L = lut[phase % 256];

/* ❌ 错误 3：定时器累加（误差会积分） */
static uint32_t acc;   acc += k_msleep 的实际值;
```

判据很简单：**把同一台设备的运行时长改掉（重启、卡顿、掉帧），亮度轨迹必须不变。**

### 2.2 亮度只由同一张 LUT 决定

不允许“各设备自己 `sin()` 一下”。原因不是性能，是**浮点不可复现**：

| 差异来源 | 后果 |
|---|---|
| 不同 libm（newlib / CMSIS-DSP / glibc） | `sin` 末位可能差 1 ulp |
| 开不开 FMA / `-ffast-math` | 结果不同 |
| FPU 单精度 vs double | 中段亮度差 1~2 个码 |

1 个码的差异人眼看不出，但规范的意义是**可判定**：两张表字节相同，结论就唯一。所以规范定义的是「表 + 校验和」，不是「公式」。

### 2.3 时间是单调的 UTC 估计

`CLOCK_REALTIME` 会在 SNTP 校时时**直接跳变**（几十 ms 到几秒）。如果每帧都读它，相位会跟着跳一下，而且多台设备的跳变时刻不同 → 一时间全乱。

正确做法：维护一个「UTC 估计器」，只让它**缓慢收敛**（第 6.3 节），对外始终给单调的时间序列。

## 3. 时间基准

### 3.1 单位、原点、时区

| 项 | 规定 | 理由 |
|---|---|---|
| 单位 | 微秒（`int64`/`uint64`） | ms 精度在 4 s 周期上是 0.025%，够；但用 us 能同时兼容 API 演进，且不额外贵 |
| 原点 | epoch 0 = 1970-01-01T00:00:00**Z** | 全世界设备无需协商“从哪一刻开始呼吸” |
| 时区 | **禁止本地时间** | 跨时区设备会差整数小时，相位完全不同 |
| 夏令时/时区变更 | 不影响 | 规则只用 UTC，用户改时区灯不该变 |

### 3.2 为什么必须 64 位

| 量 | 现在大约 | 32 位够吗 |
|---|---|---|
| epoch 秒 | 1.77×10⁹ | 到 2038 溢出（经典 2038 问题） |
| epoch 毫秒 | 1.77×10¹² | **早已溢出**（2³² ms ≈ 49.7 天，会每 49.7 天回绕） |
| epoch 微秒 | 1.77×10¹⁵ | 必须 64 位 |

用 32 位毫秒做模运算，设备每 49.7 天回绕一次 → 相位突然跳一个值。这不是理论风险，是必然发生的事故。

### 3.3 闰秒怎么办

规则要求时间线**连续**。两种可选做法，选一种并全设备统一：

| 做法 | 说明 |
|---|---|
| 忽略闰秒（推荐） | 用 TAI 式连续时间线；SNTP 给的 UTC 若含闰秒，在校时那一刻用一次 `STEPPED` 吸收掉 |
| 接受闰秒 | 闰秒发生时 1 s 的跳变会被识别为「大偏差 → 直接跳」。关键是**所有设备同时跳**，所以跳完之后仍然同相 |

禁止的是“一部分设备跳、一部分不跳”——那才是破坏一致性的做法。

### 3.4 时间从哪来

**这不是本规范的问题，是“授时通道”的问题**，因为规则只要求一件事：能拿到一对 `(mono_us, utc_us)`。第 6 章专门讲没有 WiFi 的设备怎么办。

## 4. 相位规则

### 4.1 公式

```text
φ(t) = (t - A) mod P        A = 0, P = 4 000 000 us
i    = floor(φ × 256 / P)   0..255
```

整数实现（与 C 代码逐字节对齐）：

```c
uint8_t breath_phase(uint64_t utc_us)
{
	uint64_t p = (utc_us - (uint64_t)BREATH_ANCHOR_UTC_US) % BREATH_PERIOD_US;

	return (uint8_t)((p * 256u) / BREATH_PERIOD_US);
}
```

### 4.2 为什么 P = 4 s

| 理由 | 数字 |
|---|---|
| 像“呼吸”，不像“闪” | 15 次/分钟，落在静息呼吸 12~20 次/分区间 |
| 能整除一分钟 | 60 s / 4 s = 15 → **每个整分钟相位必为 0**（验收靠肉眼，见 10.2） |
| 帧率友好 | 25 fps 下每帧走 1% 相位（2.56 个表项），肉眼连续 |
| 不与“心跳/告警”语义冲突 | 心跳类通常 0.5~2 s，4 s 留出区分度 |

### 4.3 可以换的周期（必须整除 60 s，且全设备一致）

| P | 每分钟周期数 | 观感 |
|---|---|---|
| 2 000 ms | 30 | 偏快，像“紧张” |
| 2 500 ms | 24 | 常用呼吸灯 |
| 3 000 ms | 20 | 舒缓 |
| **4 000 ms** | **15** | **本规范默认** |
| 5 000 ms | 12 | 很慢，适合待机 |
| 6 000 ms | 10 | 极慢，适合“休眠中” |
| 60 000 ms | 1 | 一分钟一呼一吸，适合“几乎不动”的指示 |

换 P 等于换规范版本：**LUT 也必须重新生成**（`tools\gen_breath_table.py` 改 `PERIOD_US`），校验和会变，所有设备一起换。

### 4.4 整分钟对齐的推论（验收白捡的技巧）

因为 `60 s` 是 `4 s` 的整数倍：

```text
任意 UTC 时间，当“秒数”是 60 的整数倍时，φ = 0 → 灯最暗（完全灭）
```

所以验收时不需要示波器：**盯着系统时间，整分钟那一刻灯必须是最暗的**。两台设备并排，谁在整分钟还亮着，谁的时间就不对。

## 5. 波形与亮度表

### 5.1 余弦，不是三角波

```text
s(x) = (1 - cos(2πx)) / 2      x ∈ [0,1)
```

三角波省 CPU，但两端速度不为零，看起来是“折返”，不是“呼吸”。余弦在 `x=0` 和 `x=1` 处导数为 0，暗和亮两端都有**停顿感**——这正是呼吸灯“呼—停—吸—停”的来源。

成本上也不亏：余弦**只算一次**（在生成脚本里），运行时只是查表。

### 5.2 gamma = 2.0

LED 的输入码值 ≈ PWM 占空比 ≈ 光通量（近似线性），而人眼对亮度的感知近似 `光通量^(1/2.2)`。若不校正，亮度“爬升”会显得生硬、暗部变化过快。

```text
LUT[i] = round( 255 × ((1 - cos(2π i/256)) / 2)^2.0 )
```

副作用（也是有意为之）：**暗部停留变长**。实测 `i=0..16` 全是 0，即每周期前 **265 ms 全灭**，末尾对称再 265 ms。总黑约 530 ms。

这不是 bug，是呼吸的“吸气末停顿”。如果你不想要完全熄灭，把下文的 floor 抬起来（见 5.5）。

### 5.3 表长 256，形状如下

```text
  255 |                  ******
      |                **      *
      |               *         *
      |              *           *
      |             *             **
      |            *                *
      |          **                  *
      |        **                     **
      |   *****                         *****
    0 |***                                   ***
      +-----------------------------------------
      0                                4 s（相位 φ）
```

一个周期的采样（每 250 ms 一点，与 `tools\test_breath_sync.c` 的输出一致）：

| t (ms) | 0 | 250 | 500 | 750 | 1000 | 1250 | 1500 | 1750 | 2000 |
|---|---|---|---|---|---|---|---|---|---|
| phase | 0 | 16 | 32 | 48 | 64 | 80 | 96 | 112 | 128 |
| level | 0 | 0 | 5 | 24 | 64 | 122 | 186 | 236 | **255** |

| t (ms) | 2250 | 2500 | 2750 | 3000 | 3250 | 3500 | 3750 | 4000 |
|---|---|---|---|---|---|---|---|---|
| phase | 144 | 160 | 176 | 192 | 208 | 224 | 240 | 0 |
| level | 236 | 186 | 122 | 64 | 24 | 5 | 0 | 0 |

### 5.4 校验和与“为什么是表”

- **表长**：256 项，1 字节/项 = **256 B** flash，RAM 里可以不载入（直接读 flash）。
- **校验和**：FNV-1a 32 位，规范 v1.0 = **`0x51521FF6`**。
- **生成**：`tools\gen_breath_table.py --inplace`，直接改写 `breath_sync.c` 里的 `BEGIN GENERATED` 区段。

设备自检：

```c
breath_selftest();   /* 0 = 通过；-1 表被改过；-2 相位不符；-3 亮度不符 */
```

**为什么必须校验和**：一台设备的表被“优化”过一个舍入，肉眼完全看不出，但它和别的设备就永远差 1 个码。校验和让这种问题在开机 1 ms 内暴露。

### 5.5 上下限与设备 gain

| 参数 | 规范值 | 说明 |
|---|---|---|
| floor | 0 | 允许完全熄灭（形成节律）；不想灭就改成 8 |
| ceiling | 255 | 满亮由 LUT 决定，不在这里裁 |
| 设备 gain | 0..100 % | **唯一允许逐设备不同的量**，用于不同 LED 型号/亮度的标定 |

`gain` 的约束：

- 必须**固定**（写进配置/标定表），不得随电池电压、时间、用户操作漂移；
- 只影响绝对亮度，**不影响相位**；
- 一致性验收只看相位/包络，不看绝对亮度（红色 LED 与蓝色 RGB 不可能看起来一样亮）。

## 6. 授时通道：没有 WiFi 的设备怎么办

### 6.1 关键认知

> **同步的本质是“共享时间信息”，不是“共享网络”。**

从信息论上讲：两台设备若没有任何共享的时间信息，它们**不可能**保持同相——这不是算法问题，是物理限制。所以设计目标不是“无网也能凭空同步”，而是：

**把“拿到一次 UTC”的通道做成可插拔的；只要拿到过一次，规则就能接管一切。**

`breath_clock_observe_src(c, mono_us, utc_us, source, uncertainty)` 就是那个插口。SNTP、BLE、ESP-NOW、UART、CAN、GPS 的 PPS 脚、DS3231、BPC 长波模块、甚至人工按键——全部走这同一个入口。

### 6.2 授时通道清单

| 通道 | 典型精度 | 硬件成本 | 前提 | 一致性等级 |
|---|---|---|---|---|
| **SNTP / NTP** | 1~30 ms | 0（已有 WiFi） | 能上网 | 3（严格） |
| **GPS/北斗 + PPS** | < 1 us | 模块约 40 元 | 能见天 | 3（远超需求） |
| **BPC 长波（68.5 kHz）** | 5~20 ms | 模块约 30 元 | 发射台在河南商丘，华北/华中接收良好；**华南、边远地区信号弱，选型前必须实机测 RSSI/信噪比** | 3 |
| **DS3231 等 TCXO RTC** | ±2 ppm（1 h 漂 7 ms） | 约 5 元 | 出厂设定一次；±2 ppm 是 0~40 ℃ 指标，机箱内长期高温会变差 | 3（1 h 内）/ 2（24 h） |
| **主从本地广播**（ESP-NOW/BLE/UART/CAN） | 1~10 ms | 0 | 簇内有 master | 3 |
| **GPIO 秒脉冲（一根线）** | < 1 ms | 1 根线 | 同板/同机箱 | 3 |
| **人工对表**（按键/串口/App） | 100~200 ms | 0 | 有人在场 | 2 |
| **出厂锚点 + 标定 + NVS** | 见 6.9 | 0 | 断电不重启 or 有 RTC 域 | 2~3 |
| **同源启动（同时上电）** | 10~100 ms | 0 | 同一路电源 | 2 |
| **什么都没有** | — | — | — | 0（不承诺，见 6.5） |

**推荐组合（按场景）**：

- 有 WiFi 的板子：SNTP，每 1 h 校一次，顺手把 6.9 的标定做掉；
- 无 WiFi 但有 master 的簇：master 用 SNTP，从机用 ESP-NOW 收广播；
- 完全离线、长期运行：DS3231 + 出厂标定，每 24 h 人工/按键对一次；
- 完全离线、同机箱多板：master 出一根 GPIO 秒脉冲，从机 <1 ms；
- 完全离线、只有一块板：自由运行，别承诺同步（6.5）。

### 6.3 误差预算：回答“现在还算同步吗”

一致性不是“是/否”，是**一个随时间增长的量**：

```text
E(age) = U_src                      ← 这口时间本身的不确定度（见 6.2 表）
       + |rate_ppm| × age / 1e6     ← 放了多久，晶振漂了多少
       + 剩余缓释量                  ← 若还在缓慢收敛
```

实现：`breath_clock_error_budget_us()`，等级：`breath_clock_level()`。

| 等级 | E(age) | 含义 | 肉眼 |
|---|---|---|---|
| 3 | ≤ 25 ms | 严格同相 | 完全看不出（相位差 0.6%，亮度差 <2%） |
| 2 | ≤ 250 ms | 基本同相 | 并排细看才觉出“慢半拍” |
| 1 | ≤ 1 s | 能看出不齐 | 明显错拍 |
| 0 | 未同步 / > 1 s | 各走各的 | 两条独立的灯 |

**为什么 25 ms 是分界线**：25 ms 在 4 s 周期上是 0.625% 相位；余弦包络在峰值处的最大斜率 `π`，故亮度差约 `π × 0.00625 ≈ 2%`，刚好在人眼亮度分辨阈值（约 2~3%）之下。而中段（变化最快）相位偏移对应的是“时间上差 25 ms”，人眼对亮度变化的积分容忍更高。

### 6.4 授时周期怎么定

| 校时间隔 | 50 ppm 漂移 | 相位偏移（P=4 s） | 等级 |
|---|---|---|---|
| 10 min | 30 ms | 0.75% | **3** |
| 1 h | 180 ms | 4.5% | 2 |
| 6 h | 1.08 s | 27% | 1 |
| 24 h | 4.32 s | **108%（超过一整个周期）** | 0 |

结论：

- **要求等级 3**：间隔 ≤ 10 min（不标定）/ ≤ 1 h（标定到 2 ppm）。
- **等级 2 可接受**：1 h（不标定）。
- 一天才校一次的“不标定”设备，**物理上不可能同相**——它一天漂了一个多周期。

这就是 6.9「出厂标定」为什么重要：它把 `50 ppm` 换成 `2 ppm`，把可用间隔拉长 25 倍。

### 6.5 未同步时怎么表现：半亮守卫

未同步的设备**不应该假装正常**——否则运维看到两只灯不齐，会怀疑固件坏了。

规则：

```c
gain_used = breath_gain_guard(gain_pct, breath_clock_level(&clk, mono_us));
/* 等级 0 → gain 减半；等级 1~3 → 原样 */
```

效果：未同步的灯仍然正常呼吸（相位、形态都对），但**整体暗一半**。一上表就自动恢复满亮。

为什么这样设计：`gain` 不参与相位，所以“半亮”不会破坏任何一致性；它只是一个诚实的状态指示，且不需要额外的灯位/闪码。

### 6.6 同源启动：最便宜的“同步”

若多台设备由**同一个开关**上电，`breath_clock_init_freerun()` 让各自把上电瞬间当 epoch 0：

```c
breath_clock_init_freerun(&clk, mono_us);
```

于是 `utc_est = mono`，两台设备算出的相位完全相同（误差 = 上电时刻差，典型 10~100 ms）→ **等级 2**。

适用：演示、玩具、同一插排的设备。不适合会分别重启的场合。

### 6.7 主从本地授时（无网簇的标准做法）

master 有网（或 RTC），从机无网。master 定时广播：

```c
struct breath_time_pkt {
	uint8_t  magic[4];       /* 'B','R','H','T' */
	uint8_t  version;        /* 1 */
	uint8_t  source;         /* master 自己这口时间的来源 */
	uint16_t seq;
	int64_t  utc_us;         /* 发包前一刻的 UTC */
};
```

从机收到后：

```c
int64_t utc_rx = pkt.utc_us + air_delay_us;      /* 见下 */
breath_clock_observe_src(&clk, mono_rx, utc_rx, BREATH_SRC_LOCAL_LINK, 10000);
```

**传输延迟补偿**，三档选一：

| 做法 | 精度 | 做法 |
|---|---|---|
| 不补 | 1~15 ms（ESP-NOW/BLE 协议栈+排队） | 对 25 ms 目标**够用** |
| 常数补偿 | 误差降到 2~5 ms | `air_delay` 写死测出来的典型值 |
| ping-pong 往返 | < 1 ms | 从机发 ping（带本地 mono），master 回 pong（带收发 UTC），`delay = (rtt - master处理时间)/2` |

广播周期跟 6.4 一致（等级 3 就 ≤10 min，等级 2 就 ≤1 h）。**广播不需要对时精度，只需要“足够新”。**

### 6.8 一根线：GPIO 秒脉冲

master 在每个 UTC 整秒边界输出 1 ms 高电平，从机用 GPIO 中断记录本地 mono：

```text
error = 中断延迟（通常 < 10 us）+ 线延迟（ns 级）
```

配合一次 UART 告诉从机“下一个脉冲是第 N 秒”，之后从机可以完全脱网维持 **< 1 ms**。成本最低、精度最高，适合同一块底板上的多 MCU。

注意：不要在 ISR 里做授时计算，只在 ISR 里记 `mono_us` 进队列，线程里 `observe_src`。

### 6.9 出厂标定：把 50 ppm 变成 2 ppm

普通无源晶振：初始偏差 ±20~50 ppm + 温漂。标定能砍掉初始偏差这一大块。

**测法（任选）**：

1. 让设备输出 1 Hz 方波，用频率计直接读 ppm；
2. 跑 24 h，对比 PC（已 NTP 同步）的时间，记录累积偏差 `Δ`；
   `ppm = Δ_us / 86 400 000 000 us × 1e6`（即 `Δ_us / 86 400`）。

**符号（最容易错的地方）**：

| 24 h 后设备相对真时间 | 晶振 | 应写入 |
|---|---|---|
| **快** 4.32 s | 偏快 | `rate_ppm = -50`（让估计走慢一点） |
| **慢** 4.32 s | 偏慢 | `rate_ppm = +50` |

因为 `utc = anchor + dt + dt*ppm/1e6`：`ppm` 为正 = 估计走快。

写入：

```c
breath_clock_set_calib(&clk, mono_us, -50);   /* 或用 NVS 里的标定值 */
```

标定后的收益（实测量级）：

| 场景 | 1 h | 24 h |
|---|---|---|
| 不标定（50 ppm） | 180 ms（等级 2） | 4.32 s（等级 0） |
| 标定 2 ppm | 7.2 ms（**等级 3**） | 173 ms（等级 2） |

所以「一次授时 + 标定」的离线设备，**能撑一天**；这在没有网络的量产设备里很实用。

### 6.10 离线重启：锚点持久化（有前提）

```c
struct breath_clock_save sv;                     /* 存进 NVS / RTC backup RAM */
breath_clock_save_state(&clk, mono_us, &sv);     /* 关机前 */
breath_clock_restore(&clk, &sv, mono_us);        /* 开机后 */
```

**前提（必须满足才可用）**：单调时钟跨重启连续。

| 设备类型 | 能用吗 | 说明 |
|---|---|---|
| 有 RTC 备份域（ESP32 的 RTC slow memory / RTC 计数器） | ✅ | 断电或软复位后计数连续，可以直接续上 |
| 电池供电、只软重启（看门狗/OTA） | ✅ | uptime 归零但“真实间隔”≈ 0，误差可忽略 |
| 真断电、无 RTC | ❌ | mono 从 0 开始，会把“关机 3 天”当成 0，误差被严重低估 |

对第三种情况，`restore` 仍然给出“保存时刻的时间”，但会把 `uncertainty` 放大 10 倍写进误差预算，逼你尽快再授时一次——这是刻意的诚实。

### 6.11 绝对不能做的三件事

| 做法 | 为什么不行 |
|---|---|
| 用 `CLOCK_REALTIME` 直接当相位源 | 校时时会跳，多机跳变时刻不同 → 相位乱跳 |
| 把 `k_uptime_get_32()` 直接取模当相位 | 49.7 天回绕；且上电时刻不同（见第 1 节） |
| 未同步时假装已同步 | 运维无法区分“没对上表”和“固件坏了” |

## 7. 多种灯型：RGB / 单色 LED / 灯带

### 7.1 关键认知

> **同步的是“亮度标量”，不是“灯”。**

一台设备是 WS2812 三通道 RGB，另一台是一颗单色 LED 加一路 PWM，它们在物理上永远不可能看起来一样（颜色不同、亮度不同）。但它们可以做到一件事——**同一毫秒亮、同一毫秒暗、同一条余弦曲线**。

这就是规范要保证的“一致性”，也是唯一有意义的一致性定义。

### 7.2 四层架构

```text
┌──────────────────────────────────────────────────────────┐
│ L3 时间层   UTC 估计器（授时可插拔：SNTP/RTC/BLE/GPIO…）  │ ← 只有这层跟“同步”有关
├──────────────────────────────────────────────────────────┤
│ L2 波形层   phase → LUT → level(0..255)                  │ ← 规范常数，跨设备逐字节一致
├──────────────────────────────────────────────────────────┤
│ L1 通道层   level × base[n] × gain → n 个通道值           │ ← n=1 单色 / 3 RGB / 2 双色 / N 灯带
├──────────────────────────────────────────────────────────┤
│ L0 输出层   WS2812 / PWM / GPIO / I2C LED 驱动            │ ← 硬件差异只在这里
└──────────────────────────────────────────────────────────┘
```

**同步只发生在 L2/L3。** L1/L0 只是“翻译”，不能改变时间（见 7.9 的禁令）。

### 7.3 通道数 n 的统一模型

同一个 `breath_channels(utc_us, base, n, gain, out)` 覆盖所有灯：

| 灯型 | n | base 填什么 | 输出到 |
|---|---|---|---|
| 单色 LED（PWM） | 1 | `{255}` | 1 路 PWM 占空比 |
| 单色 LED（只有 GPIO） | 1（二值） | — | `breath_binary()` → `gpio_pin_set` |
| 双色 LED（红/绿） | 2 | `{255, 0}` 或按标定 | 2 路 PWM |
| 共阳 RGB LED（3 脚） | 3 | `{r,g,b}` | 3 路 PWM（硬件极性反转） |
| WS2812 单珠 | 3 | `{r,g,b}` | `led_strip_update_rgb` |
| RGBW | 4 | `{r,g,b,w}` | 4 通道 |
| WS2812 灯带 | 3×N | 每像素各调一次 | 一次 `update_rgb(px, N)` |

实测（`tools\test_breath_sync.c` 第 7 节，t=1.000 s）：

```text
env=64  mono=64  rgb=(64,64,64)
```

三个通道值完全相同 → 色相不变、只改明暗；单色灯的 level 与 RGB 灯的 level 是同一个数 → **严格同相**。

### 7.4 输出后端与各自禁忌

| 后端 | 刷新语义 | 必须注意 |
|---|---|---|
| **WS2812 / `led_strip`** | 整帧一次性推送，中间不可改 | 一次传输约 2 ms（含 300 us reset）；帧率上限约 500 fps，实际用 25 fps 就够 |
| **硬件 PWM（LEDC 等）** | 改占空比立即生效 | PWM 频率 ≥ 1 kHz（推荐 4 kHz），否则肉眼可见闪烁；分辨率 8~16 位 |
| **GPIO 直驱** | 只有亮/灭 | 必须用阈值二值化（7.6），不能“模拟呼吸” |
| **I2C LED 驱动**（IS31FL3731 等） | 寄存器写，有总线延迟 | 一帧内把所有通道写完再 `update`，避免撕裂 |
| **继电器/机械开关** | 有寿命 | **禁止 4 s 呼吸**（每天 2 万次吸合）。改用 ≥1 min 慢闪或常亮 |

### 7.5 单色 LED 的 PWM 细节

```c
uint8_t  lvl  = breath_envelope(utc_us);          /* 0..255 */
uint32_t duty = breath_duty(lvl, 12);             /* 0..4095，12 位 */
uint32_t pulse_ns = (uint32_t)((uint64_t)period_ns * duty / 4095u);
pwm_set_pulse_dt(&led_pwm, pulse_ns);
```

三个坑：

1. **极性**：共阳接法（低电平亮）要把占空比反相：`duty = max - duty`。这一步在 L0，**不影响相位**。
2. **分辨率与暗部**：8 位 PWM 在 level=1..5 时只有 5 个台阶，暗部会“顿”。用 12/16 位 PWM，`breath_duty` 会自动扩展。
3. **PWM 频率与亮度上限**：频率越高，可用占空比精度越低（取决于定时器时钟）。4 kHz + 72 MHz 时钟 → 18000 级，够。

### 7.6 开关灯（只有亮/灭的灯）

```c
gpio_pin_set_dt(&led, breath_binary(utc_us));    /* level ≥ 128 → 1 */
```

得到的是 **2 s 亮、2 s 灭** 的方波，与 RGB 灯的余弦呼吸**节拍同相**（同一毫秒翻转）。看起来不像呼吸，但“同步”是成立的——适合状态指示、低成本产品。

若要更像呼吸，给 GPIO 加软件 PWM（1 kHz 定时器翻转），成本只是 CPU：

```c
/* 伪代码：1 kHz 中断里累加，超过 level 就灭 */
uint16_t acc = (acc + 255) % 255;
gpio_pin_set_raw(led, acc < level);
```

软件 PWM 的**相位仍然由 level 决定**，所以不破坏一致性。

### 7.7 灯带：整条同相 vs 空间波

| 效果 | 怎么算 | 两台同规格设备 |
|---|---|---|
| 整条一起呼吸 | 所有像素用同一个 `level` | 逐颗对齐 |
| 波浪（相位沿灯带走） | `breath_pixel_phase(utc_us, i, step)`，`step` 是规范常数 | 波峰位置也逐颗对齐 |

```c
/* 波浪：step=16 → 每颗灯差 1/16 周期，一条 16 颗的带正好绕一圈 */
uint8_t ph = breath_pixel_phase(utc_us, i, 16);
uint8_t lv = breath_lut_lookup(ph);      /* 该像素的 level */
```

`step` 必须是**规范常数**（写进配置），不得由本地随机数或启动顺序决定。

### 7.8 不同灯型之间“算不算同步”的判据

| 组合 | 判据 |
|---|---|
| RGB ↔ RGB | 三通道值逐帧相同（或相位差 ≤ 25 ms） |
| RGB ↔ 单色 LED | **只看明暗节拍**：同一时刻“最亮/最暗”的时刻一致；不比颜色、不比绝对亮度 |
| PWM 呼吸 ↔ 开关灯 | 开关灯在 level 跨 128 的时刻翻转，落在 PWM 灯的半亮时刻 → 节拍一致 |
| 灯带 ↔ 灯带 | 第 i 颗对第 i 颗（同 `step`、同长度、同方向） |
| 灯带 ↔ 单珠 | 整条同相时，灯带任一颗与单珠同相 |

### 7.9 输出层三条禁令

| 禁令 | 原因 |
|---|---|
| **不许再做平滑/淡入淡出/插值** | 任何低通都会引入**相位滞后**，多设备的滞后量不同 → 看起来不齐。包络本身已经平滑，直接刷。 |
| **不许把亮度做成“帧计数驱动”** | 见铁律 1；不同帧率会得到不同速度。 |
| **不许各通道用各自的周期/相位** | 会出现颜色随时间漂移（比如红慢蓝快），破坏“同一盏灯”的观感。 |

## 8. 帧循环

### 8.1 每帧重算，不累加

```c
while (1) {
	int64_t mono = monotonic_us();
	int64_t utc  = breath_clock_now_us(&clk, mono);

	struct breath_rgb px;
	breath_frame((uint64_t)utc, &base, gain, &px);
	led_strip_update_rgb(strip, /*…*/, 1);

	/* 绝对 deadline 睡眠，避免“处理耗时”累积成帧率漂移 */
	k_sleep(K_TIMEOUT_ABS_US(next));  next += 40 * 1000;
}
```

### 8.2 帧率不影响轨迹（这张表就是证据）

| 帧率 | 每帧相位步进 | 表项步进 | 观感 |
|---|---|---|---|
| 10 fps | 100 ms（2.5%） | 6.4 | 有台阶 |
| 25 fps | 40 ms（1%） | 2.56 | 连续（默认） |
| 100 fps | 10 ms（0.25%） | 0.64 | 极平滑（会有重复 level） |

**轨迹相同，采样密度不同。** 一台 25 fps 的 WS2812 和一台 100 fps 的 PWM 灯并排：任何时刻的 `level` 都相同，只是 PWM 灯的台阶更细。所以“同步”成立。

### 8.3 掉帧、卡顿、重启

| 事件 | 后果 |
|---|---|
| 掉一帧 | 下一帧自动回到正确相位（无状态） |
| 卡顿 200 ms | 亮度“跳”一下，但**与别的设备仍然同相** |
| 重启 | 上电第一帧即正确（只要有 UTC） |
| 改帧率 | 轨迹不变 |

这是“无状态”设计最大的好处：**没有任何需要恢复的运行状态**。

### 8.4 不要在中断里读时间

`CLOCK_REALTIME` / 某些平台的 `clock_gettime` 会拿锁。ISR 里只记录 `mono_us` 进队列，线程里换算。

## 9. 部署矩阵：实际怎么组一套

| 场景 | master 授时 | 从机授时 | 预期等级 | 验收方法 |
|---|---|---|---|---|
| **A. 全部有 WiFi** | 各设备自己 SNTP（≤1 h） | — | 3 | 串口打印相位，互差 ≤ 25 ms |
| **B. 有网一台 + 无网多台** | SNTP，ESP-NOW/BLE 广播 | 收广播 | 3 | 从机打印 `uncertainty`/`level` |
| **C. 全离线 + RTC** | DS3231，出厂设定 + 2 ppm 标定 | 同左 | 3（1 h 内）/ 2（24 h） | 24 h 后复测相位 |
| **D. 全离线 + 同机箱** | 一块板出 GPIO 秒脉冲 | 中断捕获 | 3 | 示波器量两路亮度波 |
| **E. 全离线、无 RTC** | 同一电源同时上电 | 同左 | 2 | 断电重上电后看是否同拍 |
| **F. 混合灯型** | 统一 UTC（任选上面） | 各自 L1 通道层 | 取决于授时 | 只看明暗节拍（7.8） |

**注意 B 的一个坑**：从机的等级由 `LOCAL_LINK` 的 10 ms 不确定度决定，若 master 自己只校过一次、已放了 12 h，则 master 的预算早就 > 1 s。**从机的等级 ≤ master 的等级**，广播时必须把 master 自己的 source/uncertainty 一并传下去（包里已留 `source` 字段）。

## 9.1 本仓库的接入现状（2026-11 核查）

四个工程里有呼吸灯行为，全部已经走这一套；`elab-app-common\src\breath_sync.c` 是唯一实现，
各工程的 `CMakeLists.txt` 都加了它和 `elab-app-common\include`。

| 工程 | 灯型 | 授时通道 | 用到的层 | 怎么验 |
|---|---|---|---|---|
| `applications\esp32s31\korvo_apps` | 板载 WS2812 1 颗 | **人工对表** `app sync <epoch秒>`（MANUAL） | `breath_frame`（n=3） | `app time` 看相位/等级 |
| `applications\esp32s3\s3_wifi_portal` | 板载 WS2812 1 颗 | **SNTP**（工程本来就开了 `CONFIG_SNTP`，拿到 IP 后自动对时；失败退 `203.107.6.88`） | `breath_channels`（n=3） | 日志 `led: ... grade=3` |
| `applications\esp32s31\korvo_lab` | LEDC0 通道 0 → GPIO26（PWM） | **人工对表** `lab synctime <epoch秒>` | `breath_channels`（n=1）+ `breath_duty(12bit)` | `lab syncbreath 8` |
| `applications\esp32s31\korvo_periph` | 板载 WS2812，当单色灯用 | **人工对表** `korvo synctime <epoch秒>` | `breath_channels`（n=1） | `korvo syncbreath 8` |

三点说明：

1. **`korvo_apps` 的 `rainbow` / `status` 也一起换成了 UTC 驱动**（原来用 `now_ms`）。
   同一份参数，顺带就对齐了：彩虹的色相、心跳的节拍，多台设备都会落在同一拍上。
   这两个模式没有走 LUT（它们不是呼吸），但“相位只由绝对时间推导”这条铁律同样适用。
2. **`korvo_periph` 的 `korvo breath` 和 `korvo_lab` 的 `lab pwm` 保持原样没动**。
   它们是“驱动演示”：周期可调、逐档打印返回值，教程正文引用的就是那些输出。
   新加的 `syncbreath` 才是规范实现，两条命令并存。
3. **两个无网工程的默认状态是「等级 0 + 半亮」**，这是设计而不是 bug：
   没有共享时间信息就不该假装同相（§6.5）。`synctime` 对一次表就恢复满亮，
   而且此后靠标定能撑很久（前提是晶振稳定，见 §6.9）。

## 10. 验收

### 10.1 单机自检（1 ms 内完成）

```c
int rc = breath_selftest();
/* 0 通过；-1 表被改过（校验和不对）；-2 相位不符；-3 亮度不符 */
```

建议开机打一行：

```text
[breath] spec=v1.0 lut=0x51521FF6 selftest=0 gain=60 src=network level=3 budget=21ms
```

### 10.2 秒表法（不需要仪器）

因为 `60 s` 能被 `4 s` 整除：**整分钟那一刻灯必须最暗（全灭）**。

操作：看着手机/电脑上的秒数（或 `ntpdate` 后的 `date`），在 `:00` 秒观察灯。

- 最暗对齐 → 时间对（等级 ≥ 2）；
- 差半拍 → 约 2 s 偏差，时间明显错；
- 一直亮着不灭 → 周期或锚点被改过。

### 10.3 双机对相位（工程验收）

两台都开一个 shell 命令，打印同一时刻的相位：

```text
[breath] utc=1735689605000000 phase=128 level=255
```

同一秒抓两条（或用 `breath_phase_error_us(a, b)` 直接算）：

```c
int64_t e = breath_phase_error_us(utc_a, utc_b);   /* |e| ≤ 25 ms 即同相 */
```

更严格：用 `breath_clock_error_budget_us()` 两台相加，若 ≤ 25 ms 则系统级等级 3。

### 10.4 物理测光（最终判据）

光敏电阻 + 示波器，测两路的波形：

- 上升沿时刻差 ≤ 25 ms；
- 波形形状一致（同一条余弦，不是三角/方波）。

这一条能把“两台设备各自好看但不同拍”的问题彻底暴露。

### 10.5 PC 端复现（连硬件都不用）

```powershell
gcc -std=c99 -Wall -Wextra -I elab-app-common\include `
    tools\test_breath_sync.c elab-app-common\src\breath_sync.c `
    -o $env:TEMP\test_breath.exe
& $env:TEMP\test_breath.exe
```

输出应包含 `RESULT: PASS`。这个程序同时给出下面的验收向量表。

### 10.6 验收向量（规范 v1.0，必须逐条相同）

| utc_us | phase | level | 说明 |
|---|---|---|---|
| 0 | 0 | 0 | epoch 0 |
| 250 000 | 16 | 0 | x=1/16 |
| 500 000 | 32 | 5 | x=1/8 |
| 1 000 000 | 64 | 64 | x=1/4 |
| 1 500 000 | 96 | 186 | x=3/8 |
| 2 000 000 | 128 | 255 | x=1/2 峰值 |
| 2 500 000 | 160 | 186 | x=5/8 |
| 3 000 000 | 192 | 64 | x=3/4 |
| 3 500 000 | 224 | 5 | x=7/8 |
| 3 999 999 | 255 | 0 | 周期最后一微秒 |
| 4 000 000 | 0 | 0 | 整周期回绕 |
| 1 735 689 600 000 000 | 0 | 0 | 2025-01-01T00:00:00Z |

最后一条值得注意：`2025-01-01T00:00:00Z` 恰好是 4 s 的整数倍，相位为 0。**任何整分钟都是相位 0**，这条性质本身就是一个免费的验收点。

| 参数 | 值 | 位置 | 可否逐设备不同 |
|---|---|---|---|
| 周期 P | 4 000 000 us | `BREATH_PERIOD_US` | ❌ 全局 |
| 锚点 A | 0（epoch） | `BREATH_ANCHOR_UTC_US` | ❌ 全局 |
| 表长 N | 256 | `BREATH_LUT_SIZE` | ❌ 全局 |
| gamma | 2.0 | 生成脚本 | ❌ 全局 |
| 校验和 | `0x51521FF6` | `BREATH_LUT_CHECKSUM` | ❌ 全局 |
| 二值阈值 | 128 | `BREATH_BINARY_THRESHOLD` | ❌ 全局 |
| 小误差阈值 | 25 ms | `BREATH_SYNC_SMALL_US` | ✅ 可调（影响收敛策略，不影响相位） |
| 大误差阈值 | 1 s | `BREATH_SYNC_BIG_US` | ✅ |
| 缓释速率 | ≤ 5000 ppm | `BREATH_SLEW_PPM` | ✅ |
| 漂移上限 | ±100 ppm | `BREATH_RATE_PPM_LIMIT` | ✅ |
| 默认漂移 | 50 ppm | `BREATH_DRIFT_DEFAULT_PPM` | ✅（标定后不用它） |
| 设备 gain | 0..100 | 设备配置 | ✅ **唯一鼓励逐设备不同的量** |
| 基色 base | 各通道 0..255 | 设备配置 | ✅（颜色本来就该不同） |
| 帧率 | ≥ 20 fps | 设备 | ✅ |
| 灯带 step | 0（整条同相） | 设备配置 | ✅ 但同规格灯带必须相同 |

## 12. 坑表

| 现象 | 原因 | 解法 |
|---|---|---|
| 两台设备“各呼吸各的” | 相位取自 `k_uptime` | 换成 UTC（第 1 节） |
| 呼吸速度一台快一台慢 | `phase += step` 累加式实现 | 改成每帧重算（铁律 1） |
| 呼吸“一顿一顿” | 用 `k_work` 系统工作队列被插队 | 独立线程，优先级高于 shell |
| 校时后灯“跳一下” | 直接读 `CLOCK_REALTIME` | 用 UTC 估计器 + 缓释（2.3） |
| 两台设备明明都联网还是不同步 | 一台校时成功、另一台 SNTP 失败但仍显示“正常” | 用等级/半亮守卫把失败暴露出来（6.5） |
| 单色 LED 暗部“咯噔” | 8 位 PWM 量化 | 12/16 位 PWM + `breath_duty` |
| 单色 LED 与 RGB 灯节拍对不上 | 单色灯用了“非 4 s”或自己算三角波 | 必须共用 `breath_envelope()` |
| 开关灯与呼吸灯不同拍 | 阈值不是 128，或用了独立周期 | 用 `breath_binary()` |
| 灯带波浪位置两台不一样 | `step` 用了本地随机/启动顺序 | `step` 写死为规范常数 |
| 呼吸“越来越慢” | 用 `k_msleep(40)` 且把处理耗时算进去 | 绝对 deadline（8.1） |
| 断电重启后时间回到 1970 | 没有 RTC 备份域却调了 `restore` | 见 6.10 前提 |
| 呼吸有 49.7 天周期 | 用了 32 位 ms 取模 | 全用 64 位（3.2） |
| 两台设备颜色不同，被判“不同步” | 拿颜色/绝对亮度当判据 | 判据是相位/明暗（7.8） |
| 加了“淡入淡出”后反而不齐 | 输出层低通引入相位滞后 | 删掉（7.9） |

## 附录 C　接入示例（Zephyr）

### C.1 RGB（WS2812）

```c
/* 1) 全局只建一个 UTC 估计器 */
static struct breath_clock g_clk;

/* 2) 上电：如果没有授时能力，先用自由运行（它会自动半亮） */
breath_clock_init_freerun(&g_clk, k_uptime_get() * 1000);

/* 3) 帧循环里：时间 → 亮度 → 刷灯 */
int64_t mono = k_uptime_get() * 1000;
int64_t utc  = breath_clock_now_us(&g_clk, mono);

uint8_t lvl  = breath_clock_level(&g_clk, mono);
uint8_t gain = breath_gain_guard((uint8_t)g_bright, lvl);

struct breath_rgb b = { g_base.r, g_base.g, g_base.b };
struct breath_rgb px;
breath_frame((uint64_t)utc, &b, gain, &px);

struct led_rgb strip_px = { .r = px.r, .g = px.g, .b = px.b };
led_strip_update_rgb(strip, &strip_px, 1);
```

> 注意：`struct led_rgb` 与 `struct breath_rgb` 字段顺序相同但**不要强转**，逐字段赋值最稳。

### C.2 单色 LED（PWM）

```c
uint8_t  lvl   = breath_envelope(utc);
uint32_t duty  = breath_duty(lvl, 12);                 /* 12 位 */
uint32_t pulse = (uint32_t)((uint64_t)period_ns * duty / 4095u);

pwm_set_pulse_dt(&led_pwm, pulse);                     /* 共阳则 pulse = period - pulse */
```

### C.3 只有 GPIO 的灯

```c
gpio_pin_set_dt(&led, breath_binary(utc));
```

### C.4 SNTP 授时（有网设备）

```c
struct sntp_time tm;
int rc = sntp_simple("ntp.aliyun.com", 5000, &tm);   /* timeout 单位 ms */

if (rc == 0) {
	int64_t mono = k_uptime_get() * 1000;          /* ms -> us，精度 1 ms，够 */
	int64_t utc  = (int64_t)tm.seconds * 1000000
	             + (int64_t)(((uint64_t)tm.fraction * 1000000ull) >> 32);

#if defined(CONFIG_SNTP_UNCERTAINTY)
	/* 打开这个选项后，连“这口时间有多准”都是现成的 */
	int32_t unc = (int32_t)tm.uncertainty_us;
#else
	int32_t unc = (int32_t)tm.rsp_delay_us + 5000; /* 服务器→本机的估计延迟 + 本地抖动 */
#endif

	breath_clock_observe_src(&g_clk, mono, utc, BREATH_SRC_NETWORK, unc);
}
```

字段说明（`include\zephyr\net\sntp.h`）：

| 字段 | 类型 | 含义 |
|---|---|---|
| `seconds` | `uint64_t` | 整秒（自 epoch） |
| `fraction` | `uint32_t` | 小数秒，单位 `1/2^32 s`（NTP 原生格式） |
| `rsp_delay_us` | `uint32_t` | 服务器发送→客户端收到的估计延迟（us） |
| `uncertainty_us` | `uint32_t` | 仅 `CONFIG_SNTP_UNCERTAINTY`，直接可用作 `uncertainty` |

需要 `CONFIG_NETWORKING` + `CONFIG_SNTP`，以及一条能用的网络（WiFi/以太网）。
注意：`sntp_simple` 是阻塞调用，别在动画线程里调——放一个低优先级授时线程，或在空闲时调。

### C.5 RTC 授时（无网设备）

```c
/* DS3231 每 24 h 读一次，或者上电读一次。
 * ds3231_read_utc_us() 是占位名，换成你 I2C 驱动里读时间/日期寄存器的那段。 */
int64_t utc  = ds3231_read_utc_us(&i2c);
int64_t mono = k_uptime_get() * 1000;

breath_clock_observe_src(&g_clk, mono, utc, BREATH_SRC_RTC, 0);
```

配合 6.9 的标定，这就是“无 WiFi 也能一天同相”的标准做法：
RTC 提供“这口时间是几”，标定负责“它走得多准”。

/* 从机：收到包 */
