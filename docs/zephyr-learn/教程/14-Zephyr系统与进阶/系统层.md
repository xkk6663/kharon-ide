# 系统层：复位原因 / 片上温度 / 硬件随机数 / 看门狗

> 工程：`applications\esp32s31\korvo_sys`　构建目录：`build\esp32s31\korvo_sys\s31-debug`　镜像 142 KB（FLASH 145280 B，0.87%）
> 全部 4 条命令**已烧录实测**，串口原文见第 4 节。看门狗只读就绪状态，**不安装超时**（原因见第 5 节）。

---

## 1. 这一层和驱动层有什么区别

驱动层（`11-Zephyr驱动\`）关心的是**某一个外设的 API 怎么调**：GPIO 怎么拉高、I2C 怎么读写、ADC 怎么取值。

系统层关心的是**板子自身的状态和身份**：

| 问题 | 由谁回答 | 底层是什么 |
|---|---|---|
| 我这次为什么开机？ | `hwinfo` | RTC 域里的复位原因寄存器（bitmap） |
| 我是哪块板？ | `hwinfo` | eFuse 里的 6 字节 MAC/器件 ID |
| 芯片现在多热？ | `sensor` + `coretemp` | 片上温度传感器（内部二极管 + ADC） |
| 随机数从哪来？ | `entropy` / `random` | `trng0` 真随机源，不是 `rand()` |
| 程序卡死了谁来救？ | `watchdog` | `wdt0`（TIMG0 的看门狗） |

这四件事的共同点：**它们不接外设，全靠芯片内部资源**。所以"只有一块板、没有杜邦线"也能全部做完，是最适合练手的第一站。

## 3. 代码讲解

### 3.1 复位原因：位图 → 人话

`hwinfo_get_reset_cause()` 返回的是一个**位图**，不是枚举。这颗芯片（以及 Zephyr 的 hwinfo 抽象）用的是 `RESET_*` 宏：

```c
#define RESET_PIN              BIT(0)
#define RESET_SOFTWARE         BIT(1)
#define RESET_BROWNOUT         BIT(2)
#define RESET_POR              BIT(3)   /* Power-On Reset */
#define RESET_WATCHDOG         BIT(4)
#define RESET_DEBUG            BIT(5)
#define RESET_SECURITY         BIT(6)
#define RESET_LOW_POWER_WAKE   BIT(7)
#define RESET_CPU_LOCKUP       BIT(8)
#define RESET_PARITY           BIT(9)
#define RESET_PLL              BIT(10)
#define RESET_CLOCK            BIT(11)
#define RESET_HARDWARE         BIT(12)
#define RESET_USER             BIT(13)
#define RESET_TEMPERATURE      BIT(14)
#define RESET_BOOTLOADER       BIT(15)
#define RESET_FLASH            BIT(16)
```

**坑**：上游 Zephyr 有个 `hwinfo_reset_cause_to_str()` 的便利函数，**这棵树里没有**（`include\zephyr\drivers\hwinfo.h` 里搜不到）。所以自己写一个位循环：

```c
static const char *reset_cause_str(uint32_t cause)
{
	static char buf[96];
	int n = 0;

	buf[0] = '\0';
	for (int bit = 0; bit < 32; bit++) {
		const char *name = NULL;

		if (!(cause & BIT(bit))) {
			continue;
		}

		switch (BIT(bit)) {
		case RESET_PIN:            name = "PIN"; break;
		case RESET_SOFTWARE:       name = "SOFTWARE"; break;
		case RESET_BROWNOUT:       name = "BROWNOUT"; break;
		case RESET_POR:            name = "POWER_ON"; break;
		case RESET_WATCHDOG:       name = "WATCHDOG"; break;
		/* ... 其余同理 ... */
		default:                   name = NULL; break;
		}

		if (name) {
			n += snprintf(buf + n, sizeof(buf) - n, "%s%s", n ? " | " : "", name);
			if (n >= (int)sizeof(buf) - 1) {
				break;
			}
		}
	}

	return n ? buf : "UNKNOWN";
}
```

为什么用 `static char buf`：**不要在栈上返回局部数组**。这是 shell 命令，串行执行，一个 static 缓冲够用。

一条命令把三件事一起打印：

```c
static int cmd_info(const struct shell *sh, size_t argc, char **argv)
{
	uint32_t cause = 0;
	uint8_t id[16];
	ssize_t len;

	if (hwinfo_get_reset_cause(&cause) == 0) {
		shell_print(sh, "[info] 复位原因位图 = 0x%08x", cause);
		shell_print(sh, "[info] 复位原因 = %s", reset_cause_str(cause));
	}

	len = hwinfo_get_device_id(id, sizeof(id));
	if (len > 0) {
		shell_print(sh, "[info] 器件 ID = %02x:%02x:%02x:%02x:%02x:%02x (len=%d)",
			    id[0], id[1], id[2], id[3], id[4], id[5], (int)len);
	}

	shell_print(sh, "[info] 运行时长 = %u ms", k_uptime_get_32());
	shell_print(sh, "[info] Zephyr 版本 = %s", KERNEL_VERSION_STRING);
	shell_print(sh, "[info] 板 = %s", CONFIG_BOARD_TARGET);
	return 0;
}
```

要点：
- `hwinfo_get_device_id()` 返回的是**实际读到的字节数**（`ssize_t`），不是 0/负值。判 `> 0` 才对。
- 这个器件 ID 就是 MAC 地址：实测 `30:ed:a0:f3:fc:50`，和 `west flash` 打印的 MAC 一致——**这就是同一份 eFuse**。
- `KERNEL_VERSION_STRING` 来自 `<zephyr/version.h>`，不加这个头文件会报 `undeclared`。

### 3.2 片上温度：通道名必须写对

```c
static int cmd_temp(const struct shell *sh, size_t argc, char **argv)
{
	if (!device_is_ready(temp_dev)) {
		shell_error(sh, "coretemp 未就绪");
		return -ENODEV;
	}

	for (int i = 0; i < n; i++) {
		struct sensor_value v;

		if (sensor_sample_fetch(temp_dev) != 0) { return -EIO; }
		if (sensor_channel_get(temp_dev, SENSOR_CHAN_DIE_TEMP, &v) != 0) {
			shell_error(sh, "channel_get 失败");
			return -EIO;
		}
		shell_print(sh, "[temp] %d.%02d °C",
			    v.val1, (v.val2 < 0 ? -v.val2 : v.val2) / 10000);
		k_msleep(200);
	}
	return 0;
}
```

**这是本轮踩得最实的一个坑**：`esp32_temp` 驱动只实现了一个通道——

```c
/* zephyr\drivers\sensor\espressif\esp32_temp\esp32_temp.c:47 */
if (chan != SENSOR_CHAN_DIE_TEMP) {
	return -ENOTSUP;
}
```

写成 `SENSOR_CHAN_AMBIENT_TEMP`（"环境温度"，大多数温度传感器用的就是这个）会直接失败。第一次实测就是：

```
sys temp 3
[temp] 采样 3 次
channel_get 失败
```

改成 `SENSOR_CHAN_DIE_TEMP` 就通了。**为什么是 DIE_TEMP**：片上传感器测的是硅片结温，不是环境温度，物理上也叫不出环境温度。

`sensor_value` 的编码：`val1` 是整数部分，`val2` 是百万分之一（µ）的小数部分。所以 `%d.%02d` 配 `val2/10000` 就是两位小数，够用。

### 3.3 硬件随机数：`sys_csrand_get` 而不是 `sys_rand32_get`

```c
static int cmd_rand(const struct shell *sh, size_t argc, char **argv)
{
	for (int i = 0; i < n; i++) {
		uint32_t a = 0, b = 0;

		if (sys_csrand_get(&a, sizeof(a)) != 0 ||
		    sys_csrand_get(&b, sizeof(b)) != 0) {
			shell_error(sh, "熵源读取失败");
			return -EIO;
		}
		shell_print(sh, "[rand] 0x%08x 0x%08x", a, b);
	}
	return 0;
}
```

两个 API 的区别，这块板子上体现得很典型：

| API | 来源 | 用途 |
|---|---|---|
| `sys_rand32_get()` | 会退化到软件 PRNG（xoshiro） | 抖个灯、打乱顺序，谁都行 |
| `sys_csrand_get()` | **密码学安全**，强制走硬件熵源 | 密钥、nonce、盐 |

`sys_csrand_get` 要能用，必须有 `chosen { zephyr,entropy = &trng0; }`。板级 dts **没有**这一行，所以第一次不加 overlay 的话，熵源设备是空的。加了才有本节的实测数值。

三个细节：
- 每调一次都会真的去读硬件寄存器，所以**别在循环里当 `rand()` 用**（慢）。
- 要预先播种的场景用 `sys_rand_get()`（首次调用会从熵源播种）。
- 想验证"真随机"，最简单的统计：取 1 万个数看 0/1 位分布、看重复率。`sys_csrand_get` 出来的值不会重复，`rand()` 在小范围内很容易撞。

### 3.4 看门狗：这棵树的 API 是"精简版"

先看 `include\zephyr\drivers\watchdog.h` 在本树里到底有什么：

| 符号 | 存在？ | 说明 |
|---|---|---|
| `wdt_install_timeout(dev, cfg)` | ✅ | 装一个超时（`static inline`） |
| `wdt_setup(dev, options)` | ✅ | `__syscall`，真正启动 |
| `wdt_feed(dev, channel)` | ✅ | `__syscall`，喂狗 |
| `wdt_disable(dev)` | ✅ | `__syscall`，一次拆掉所有超时 |
| `wdt_disable_channel(dev, ch)` | ❌ | **没有这个函数** |
| `WDT_OPT_PREPARE` | ❌ | **没有这个宏** |
| `WDT_OPT_PAUSE_IN_SLEEP` | ✅ | `BIT(0)` |
| `WDT_OPT_PAUSE_HALTED_BY_DBG` | ✅ | `BIT(1)` |

所以网上教程里常见的 `wdt_disable_channel()` / `WDT_OPT_PREPARE` 在这里一律编译不过。正确的用法：

```c
static const struct device *const wdt_dev = DEVICE_DT_GET(DT_ALIAS(watchdog0));

static struct wdt_timeout_cfg cfg = {
	.window = { .min = 0, .max = 3000 },   /* ms，0 表示不限下限 */
	.callback = NULL,                      /* NULL = 超时直接复位，不先中断 */
	.flags = WDT_FLAG_RESET_SOC,
};

int ch = wdt_install_timeout(wdt_dev, &cfg);         /* 先装 */
if (ch >= 0) {
	wdt_setup(wdt_dev, WDT_OPT_PAUSE_HALTED_BY_DBG); /* 再启动：调试器停住时不咬 */
}

/* 业务线程里定期喂 */
wdt_feed(wdt_dev, ch);

/* 想彻底关掉（比如进低功耗前） */
wdt_disable(wdt_dev);
```

时序要点：**`install_timeout` 必须在 `wdt_setup` 之前**。头文件里写得很直白：

> `@note This function must be used before wdt_setup(). Changes applied here have no effects until wdt_setup() is called.`

关于 `flags`：
- `WDT_FLAG_RESET_NONE`：只有中断，不复位（可以打印现场）
- `WDT_FLAG_RESET_CPU_CORE`：复位本核
- `WDT_FLAG_RESET_SOC`：整颗 SoC 复位（真正的"救砖"）

**本工程没有调用上面任何一行**，只做了一件事：

```c
shell_print(sh, "[dev] watchdog0 = %s (ready=%d)", wdt_dev->name,
	    device_is_ready(wdt_dev));
```

为什么这样也值得写进教程：`device_is_ready(wdt0) == 1` 同时证明了 **dts 节点 okay + Kconfig 选中驱动 + 时钟/中断资源绑定成功**。这是"链路验证"，不动硬件状态，没有复位风险。

### 3.5 为什么 `wdt0` 一开始根本没编进镜像

这是本轮最有教学价值的一段。第一次构建在链接阶段炸：

```
undefined reference to `__device_dts_ord_61'
```

`__device_dts_ord_61` 是 devicetree 给 `wdt0` 分配的**设备对象序号**。它未定义，意味着"devicetree 认这个设备，但**没有任何驱动去定义它**"。

顺着查三处：

1. `esp32s31_common.dtsi:362` → `wdt0: watchdog@20580048 { compatible = "espressif,esp32-watchdog"; status = "disabled"; }`
2. `drivers\watchdog\Kconfig.esp32:6` → `config WDT_ESP32 / bool / default y / depends on DT_HAS_ESPRESSIF_ESP32_WATCHDOG_ENABLED`
3. `drivers\watchdog\Kconfig:7` → `menuconfig WATCHDOG` …… `if WATCHDOG` 包住了整个 ESP32 分支

于是两个原因同时成立：
- 节点 `disabled` → `DT_HAS_..._ENABLED = n` → `WDT_ESP32` 的 `default y` 不生效
- 总开关 `WATCHDOG` 默认 `n` → 整个 `drivers/watchdog/Kconfig.esp32` 的内容都在 `if` 里面，压根没被考虑

而且 **`CONFIG_WDT=y` 会直接 Kconfig 致命错误**，因为这棵树里没有叫 `WDT` 的符号（上游有个 `WDT` → 本树改名为 `WATCHDOG`）。

修法两条，缺一不可：

```conf
CONFIG_WATCHDOG=y      # prj.conf
```
```dts
&wdt0 { status = "okay"; };   # app.overlay
```

修完的判据：`.config` 里出现 `CONFIG_WATCHDOG=y` 和 `CONFIG_WDT_ESP32=y`，编译日志里出现 `libdrivers__watchdog.a`，`sys dev` 打印 `ready=1`。

逐条读：

- **`0x00000008` = `BIT(3)` = `RESET_POR`**。0x08 是 2 的 3 次方，对应 `RESET_POR`（上电复位）。因为每次 `serial_cmd.py` 都会拉 RTS 让板子重新上电/复位，这个值是正常的。按 RESET 键会是 `RESET_PIN`(BIT0)，看门狗咬会是 `RESET_WATCHDOG`(BIT4)——后者本机不演示。
- **器件 ID 和 MAC 一致**：`30:ed:a0:f3:fc:50`，`west flash` 打印的也是它。说明 `hwinfo_get_device_id` 读的就是 eFuse 里那份出厂 ID。
- **温度 22 °C**：室温 20 附近的芯片结温，合理。但注意后面那行 `W (temperature_sensor): No calibration param in eFuse`。
- **随机数每次都不一样**：三次运行拿了三组完全不同的值，换一次复位又是新的。这就是"真随机"和 `rand()` 的直观差别。
- **wdt0 ready=1**：驱动、dts、时钟全通，但没写任何 WDT 寄存器。

### 4.1 那行 `No calibration param in eFuse` 到底什么意思

不是错误，是**警告**。ESP32 系列的温度传感器出厂时会在 eFuse 里烧一组校准参数（用来把原始 ADC 读数换算成绝对温度）。有些样片/批次**没烧**，驱动于是退回原始换算公式。

后果很具体：
- 绝对值**不可信**（可能整体偏几度）
- **相对趋势仍然可信**：摸着芯片看温度往上走、跑满 CPU 看升温，都能看出来

所以这条命令的正确用法是**看变化**，不是读绝对温度。想做"精准测温"，得配外部 I2C 温度传感器（比如 SHT31、TMP117），但那要接线，属于 B 档。

## 5. 为什么没有做"看门狗咬一口"的现场演示

系统执行策略明确禁止**可能导致板子重启 / 关机 / 强制复位**的操作。`wdt_install_timeout` + 停止喂狗 + `WDT_FLAG_RESET_SOC`，本质上就是"主动让板子重启一次"，所以：

- `sys wdt`（安装超时）、`sys crash`（故意卡死等复位）、`sys reboot`（软件复位）**三者全部从工程里移除**
- 源码里保留的只有 `device_is_ready()` 只读判断
- 本页面第 3.4 节给出的完整代码可以**照着抄到自己的工程里用**，但**本机不执行验证**

这不是能力缺失，是执行边界的如实标注。你在自己的板子上跑这段代码完全没问题，只是要接受"3 秒不喂狗就重启"的后果。

## 6. 七个坑（都踩过）

| # | 现象 | 原因 | 解法 |
|---|---|---|---|
| 1 | `attempt to assign the value 'y' to the undefined symbol WDT` | 这棵树把总开关改名成 `WATCHDOG` | `CONFIG_WATCHDOG=y` |
| 2 | 链接报 `undefined reference to __device_dts_ord_61` | dts 有节点但 `status="disabled"`，驱动没编进来 | overlay 里 `&wdt0 { status = "okay"; };` |
| 3 | `implicit declaration of 'hwinfo_reset_cause_to_str'` | 本树没这个便利函数 | 自己写位图→字符串映射 |
| 4 | `'KERNEL_VERSION_STRING' undeclared` / `'snprintf' implicit` | 缺头文件 | `#include <zephyr/version.h>`、`#include <stdio.h>` |
| 5 | `sys temp` 报 `channel_get 失败` | 传了 `SENSOR_CHAN_AMBIENT_TEMP` | 改成 `SENSOR_CHAN_DIE_TEMP`（驱动只实现这一个） |
| 6 | `sys rand` 报熵源失败 | 板级 dts 没有 `zephyr,entropy` | overlay 加 `chosen { zephyr,entropy = &trng0; }` |
| 7 | `.config` 里改了半天不生效 | 改了 overlay 但没让 CMake 重新生成 devicetree | `west build -p always ...`（pristine 重建） |

第 7 条的细节：改 `app.overlay` 会触发重新生成 `zephyr.dts`，但 **Kconfig 的 `DT_HAS_*` 符号**是在 CMake 配置阶段定下来的。改了 dts 之后如果 `.config` 里的开关还是 `n`，先确认 `zephyr.dts` 里那个节点的 `status` 真的变成 `okay` 了，再考虑 `-p always`。
