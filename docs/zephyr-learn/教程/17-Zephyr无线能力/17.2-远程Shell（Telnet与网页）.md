# 17.2 远程 Shell：Telnet 后端 + 网页内命令

> 目标：不用插 USB，也能在局域网里跑板子的 shell 命令。
> 两个入口共用同一套 shell 内核：**Telnet（:23）** 和 **HTTP 页面（/api/shell）**。
>
> 这一篇里最值钱的不是"怎么开"，而是「一连就卡死」那次的定位过程 —— 它其实是 LED 线程栈溢出，
> 和 Telnet 本身无关。完整推理见 17.8。

## 1. 三个 shell 后端的分工

Zephyr 的 shell 是「一个内核 + 多个后端」：

| 后端 | 配置 | 输出形态 | 适合谁 |
|---|---|---|---|
| serial | `CONFIG_SHELL_BACKEND_SERIAL=y` | 流式，直接打到串口 | 手边有 USB |
| telnet | `CONFIG_SHELL_BACKEND_TELNET=y` + `SHELL_TELNET_PORT=23` | 流式，按连接回写 | 局域网长会话、看实时日志 |
| dummy | `CONFIG_SHELL_BACKEND_DUMMY=y` + `SHELL_BACKEND_DUMMY_BUF_SIZE=2048` | **收进内存缓冲**，执行完再取 | 网页这种"一问一答" |

关键结论：**网页里那条命令必须走 dummy 后端**。serial/telnet 是流式输出，命令跑完就散了，
拿不回来；dummy 把输出攒在缓冲里，用 `shell_backend_dummy_get_output()` 取整段。

## 2. Telnet 凭据

> **2026-11-16 更新：这一节已经作废 —— Telnet 后端被整体关掉了。**
>
> 原因不是"口令麻烦"，而是这一版 Zephyr 的 telnet backend 绑 `0.0.0.0`、
> **没有来源过滤、也没有认证钩子**：手机连上 `S3-Portal` 就能拿到一个无口令的交互式 shell。
> 页面受众分离做完之后，它是唯一剩下的漏口。
>
> 落地方式（三选一里选的方案 1）：
>
> | 方案 | 代价 | 结论 |
> |---|---|---|
> | ① 关掉 Telnet，远程执行只走 `/api/shell` | 失去交互式手感 | **采用** |
> | ② 给 telnet 加口令 | 要包一层或改 backend | 否 |
> | ③ 自写 TCP shell + 同款来源判据 | 多一个监听线程要维护 | 否 |
>
> `prj.conf` 现在是 `# CONFIG_SHELL_BACKEND_TELNET is not set`，并删掉了两条
> `SHELL_TELNET_*_LOG_LEVEL_DBG`。**代价是一次全量重编（实测 540 s）**，
> 镜像从 869780 B 降到 868772 B（-1008 B）。
> 远程执行改走 `/api/shell`：应用层能判来源（AP 侧 404）、能要 `k=`，这正是 telnet 缺的两样。

- 原设计：端口 `23`，无口令（局域网内"可接受"，实际证明不可接受）。
- 原日志级别：`CONFIG_SHELL_TELNET_LOG_LEVEL_DBG` / `..._INIT_LOG_LEVEL_DBG` —— 已随后端一起删除。

## 3. `/api/shell` 的语义（页面用的那条）

```
GET  /api/shell?k=<口令>&cmd=kernel%20uptime
POST /api/shell?k=<口令>   body: cmd=kernel uptime
```

返回：

| 情况 | body |
|---|---|
| 成功 | `{"ok":true,"out":"…"}` |
| 另一条命令还在跑 | `{"ok":false,"err":"busy"}` |
| 2.5 s 没跑完 | `{"ok":false,"err":"timeout"}` |
| 缺参数 | `{"ok":false,"err":"missing cmd"}` / `"empty cmd"` |

实现要点（`main.c`）：

- `sh_cmd_thread`：独立线程 `K_THREAD_DEFINE(sh_cmd_tid, 6144, …, 7, 0, 0)`，
  接收命令 → `shell_execute_cmd()` → 等 dummy 输出 → 拼 JSON。
- 为什么单独开线程：HTTP handler 跑在 http_server 的栈上（`CONFIG_HTTP_SERVER_STACK_SIZE=6144`），
  在里面同步跑 shell 命令会把这 6 KB 直接吃掉。
- 短命令（如 `kernel uptime`）2.5 s 足够；`kernel thread list` 也能出结果。
- 输出里会残留 ANSI 颜色片段（实测 `[1;31m`），页面用 `stripAnsi()` 在**前端**去掉，
  不在固件里做 —— 这样串口/Telnet 侧仍然是有颜色的原样。

## 4. 页面上那张「远程命令」卡片

为了不改动 `index_html` 里那一大段 HTML（改一次容易踩到页面结构），卡片是**运行时用 JS 造出来的**：

```js
const card = document.createElement('div');
card.className = 'card';
card.innerHTML = '…输入框 + 执行按钮 + 快捷按钮…';
document.body.appendChild(card);
```

快捷按钮最初填的是 `net check` / `wifi scan` / `wlog` —— **全是 `command not found`**。
换成板上真实存在的之后才可用：

| 快捷按钮 | 命令 | 说明 |
|---|---|---|
| 门户状态 | `portal status` | 本工程自定义的 shell 子命令 |
| 运行时长 | `kernel uptime` | |
| 线程列表 | `kernel thread list` | 能看每个线程的栈用量（排栈溢出时非常有用） |
| 网卡信息 | `net iface` | |
| 已存网络 | `portal saved` | |
| 主动断开 | `portal drop` | 抓断连 reason_code 时用，见 17.4 |

板上可用的顶层命令（实测 `help`）：`clear / date / device / devmem / help / history /
kernel / net / portal / rem / resize / retval / shell`。

## 5. 验收命令

Telnet 侧（本项目自带脚本，会剥掉 ANSI 再打印正文）：

```powershell
$root = "C:\Users\xiao1\Desktop\ELAB\kharon-ide"
& "$root\.venv\Scripts\python.exe" "$root\tools\telnet_hold.py" 10.168.1.226 23 "kernel uptime" 5
```

HTTP 侧：

```powershell
& "$root\.venv\Scripts\python.exe" -c "import urllib.request,urllib.parse;q=urllib.parse.quote('kernel thread list');print(urllib.request.urlopen('http://10.168.1.226/api/shell?k=<REDACTED-PSK>&cmd='+q,timeout=8).read().decode()[:600])"
```

实测基线：`/api/shell` 跑 `kernel uptime` 返回 `{"ok":true,"out":"…Uptime: 27392 ms"}`；
`kernel version` 返回 `Zephyr version 4.5.99`；不存在的命令返回 `command not found`。

## 6. 未实现 / 已知边界

- Telnet 无口令、无 TLS：局域网内任何人都能连。要收紧得加"连接后先输口令"的状态机。
- `/api/shell` 走配网页口令 `k=`，和 OTA 的 `X-Key` 同一档（明文共享密钥，不含 HMAC）。
- 一次只能跑一条命令（`busy` 保护），没有命令队列。
