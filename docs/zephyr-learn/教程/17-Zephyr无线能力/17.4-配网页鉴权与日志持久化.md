# 17.4 配网页鉴权、崩溃日志与断连日志持久化

> 三件事放在一篇，因为它们共用同一块存储（NVS `storage` 分区）和同一套"重启后还要在"的诉求。

## 1. 鉴权：为什么最后落成查询参数 `k=`

### 1.1 `psk` 里的 `k=`：一个只在真浏览器上必现的 401

找口令的写法原来是 `strstr(buf, "k=")`。而 `/api/connect` 的查询串是

```
?ssid=OpenWrt&psk=WrongPass-2026&k=<REDACTED-PSK>
```

`psk=` 这个词的**尾巴正好是 `k=`**，于是先命中了密码字段，口令比对失败 → 401 `need key`。
后果是"凡带 `psk` 的请求全 401"，而 curl 手打时习惯把 `k=` 放最前面，所以一直没暴露；
页面统一把 `k` 拼在最后，必现。

修法必须**按参数边界判**：

```c
const char *q = buf;
while ((q = strstr(q, "k=")) != NULL) {
	if (q == buf || q[-1] == '?' || q[-1] == '&') { p = q; break; }
	q += 2;
}
```

`q == buf` 这一支不能省：**GET 的 `req->data` 带一个前导 `?`**，只认 `&k=` 会把最常见的
`?k=...` 判成"没给口令"。两个坑是连着的，先修第一个会立刻踩到第二个。
顺带把缓冲区从 `128` 扩到 `192`：`ssid + psk + k` 会超过 127。

先说结论：**本版 Zephyr 的 HTTP server 请求头捕获有缺陷**。

- `CONFIG_HTTP_SERVER_CAPTURE_HEADERS` 恒为 NONE，`request_ctx->headers` 拿不到任何自定义头；
- 于是任何"读请求头 → 比口令"的实现（`Authorization: Bearer …`、`X-Auth: …`）都会**恒放行** ——
  看起来鉴权写好了，实际对所有人敞开。

所以本工程的鉴权统一走查询参数：

```
http://10.168.1.226/?k=<REDACTED-PSK>
http://10.168.1.226/api/status?k=<REDACTED-PSK>
```

实现细节：

| 项 | 值 |
|---|---|
| 默认口令 | `<REDACTED-PSK>` |
| 存储 | NVS `auth/pw` |
| 前端保存 | `localStorage` 键 `s3k`，页面全局变量 `K` |
| 改口令 | `/api/pw?pw=新口令&k=旧口令` |
| 无 `k` 时 | `/` 返回 200 + 解锁页；`/api/*` 返回 401 |

明说的边界：口令出现在 URL 里，会被浏览器历史、路由器日志、抓包看到。
在"局域网配网门户"这个档位可以接受，但它**不是** TLS 级别的保护。

## 2. Captive Portal 的 302 自跳环（早期踩过的坑）

早期为了"手机连上热点自动弹配网页"，对未知路径一律 302 回首页。结果出现：

```
错误代码:-9  net::ERR_TOO_MANY_REDIRECTS
```

原因：302 的目标也是同一台设备的首页，浏览器判定成环。
现在的行为：`/`、`/index.html` 正常出页面，未知路径才回 302，且目标带唯一参数避免成环。
另外注意：**`192.168.4.1` 不是本板**（TTL 253、无 ARP 条目，是上游路由器的地址），
拿它诊断一定会走错方向。

## 3. 崩溃日志持久化上报：`boot` 计数 + `clean` 标志

思路不是"存一份 coredump 文本"，而是**用启动次数与干净退出标志推断崩溃**，成本极低且重启后一定还在：

1. 每次启动先把 NVS 里的 `boot.n` 加一，并读上一次的 `clean`；
2. 运行正常时，周期性/主动重启前调用 `ops_boot_mark_clean()` 把标志置真；
3. 若上次 `clean=false`，说明是掉电/异常复位/崩溃，`boot.crash` 加一；
4. `/api/boot` 与 `/api/status` 的 `boot{…}` 一起给页面。

实测字段语义：

```json
"boot":{"n":29,"crash":6,"last_up":56,"clean":true,"rst":"software"}
```

| 字段 | 含义 |
|---|---|
| `n` | 累计启动次数 |
| `crash` | 异常退出累计次数 |
| `last_up` | 上次运行了多少秒 |
| `clean` | 本次之前是否干净退出 |
| `rst` | 复位原因（`software` / `other`） |

这条机制的实际价值：**LED 线程栈溢出那次**（见 17.8）就是靠"重启后 `crash` 加一 + `clean=false`"
确认"板子不是自己重启，是真崩了"，而不是靠运气看串口。

埋点注意：`ops_boot_mark_clean()` 必须在 `sys_reboot()` **之前**调用，且 OTA 的
`POST /api/ota/reboot` 里已经接好了这一步（见 17.5）。

## 4. 断连日志持久化：`/api/wlog`

Wi-Fi 断连常常是"无缘无故"，而现场转瞬即逝。做法是把每一类 WiFi 事件记一条结构化记录，
存 NVS 环形缓冲，`/api/wlog` 吐 JSON：

```json
"ops: wlog: kind=1 reason=0 rc=0 sc=0 rssi=0 ssid=501A"
```

| 字段 | 含义 |
|---|---|
| `kind` | 事件类别（连接/断开/扫描结果等） |
| `reason` | 底层 reason code（断连原因，重点看这个） |
| `rc` / `sc` | 关联/扫描的返回码 |
| `rssi` / `ssid` | 当时的信号与网络名 |

`/api/status` 里的 `wlog` 是**条数**，明细走 `/api/wlog`。

### 4.1 2026-11-16 补记：这条链路原来是"写了但读不回来"

早前只做了 `settings_save_one("wlog/blk", ...)`，**没注册 `settings` 读回 handler**，
所以每次上电 `g_ev` 都是空的 —— `/api/wlog` 只在本次运行内有效，重启即失忆。
这也是"只能靠挂串口等样本"的真因。修法与判据（结构体长度不符要整块丢弃、magic/head/count 越界要挡）
写在 [17.10 第 12 节](17.10-页面受众分离（用户配网页与开发者台）.md)。

### 4.2 新增 `/api/drops`：值班只需要看一条

环形数组适合事后翻账，但"上次为什么断"通常一句话就够：

```json
{"total":8,"conn":4,"disc":1,"fail":3,
 "last_drop":{"t":97,"held_s":34,"dr":2,"drtxt":"User request","rc":0,"rctxt":"none","sc":0,"rssi":-30,"ssid":"Power"},
 "last_fail":{"t":9,"sc":3,"rssi":0,"ssid":"Power"}}
```

- `last_drop` 只取 `kind=2`，`last_fail` 只取 `kind=3`：**别把两者合成一个 `last`**，
  否则"从来没连上"会被读成"网络掉过"；
- `held_s`（这条链路活了多久）是新增字段：连 3 秒就断和连 40 分钟才断，是完全不同的故障；
- `drtxt` / `rctxt` 是人话翻译，省掉查表。

实测跨 `kernel reboot cold` 后仍在：重启后 `/api/wlog` 还能读到上一轮的 `kind=2 dr=2`。

现状要说明：已经拿到**本地主动断开**（`dr=2` = User request，`rc=0` 因为本地断开时驱动不给 802.11 reason）
和**关联失败**（`sc=1/3`）两类；**"AP 端踢人"的 `rc` 样本（2/4/8/15/34）仍然缺**，
需要一台可控 AP 从后台踢客户端 —— 本轮没这个条件（不能动用户的 `Power` 路由器、也不能切 PC 的 WiFi）。

## 5. 存储与它和 OTA 的关系

上面所有东西都在 NVS，落在 `storage` 分区（`0x3b0000`，192 KB）：

| 键 | 内容 |
|---|---|
| `auth/pw` | 配网页口令 |
| `s3ota/nonce` | 已接受的最大 nonce |
| `s3ota/psk` | 可选：OTA 的 PSK（不写则用编译期默认） |
| `s3ota/rb` | OTA 断点记录（见 17.6） |
| 崩溃计数 / boot 标志 / WiFi 凭据 / wlog 环形缓冲 | 各自前缀 |

**OTA 只写 `image-0`/`image-1` 两个槽，不碰 `storage`** —— 所以升级完口令、WiFi 凭据、
nonce 计数、崩溃计数全都在。这也是"升完级 IP 没变、口令还能用"的原因。

## 6. 验收

```powershell
# 鉴权：无 k → 401
& "$root\.venv\Scripts\python.exe" -c "import urllib.request;print(urllib.request.urlopen('http://10.168.1.226/api/status',timeout=8).status)"
# 期望抛 HTTPError 401

# 启动/崩溃计数
& "$root\.venv\Scripts\python.exe" -c "import json,urllib.request;print(json.load(urllib.request.urlopen('http://10.168.1.226/api/status?k=<REDACTED-PSK>',timeout=8))['boot'])"

# 断连日志
& "$root\.venv\Scripts\python.exe" -c "import urllib.request;print(urllib.request.urlopen('http://10.168.1.226/api/wlog?k=<REDACTED-PSK>',timeout=8).read().decode()[:400])"
```
