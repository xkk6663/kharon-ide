# 17.1 配网门户与状态监控

> 这一篇只讲「局域网里怎么看到板子状态」。代码在 `applications\esp32s3\s3_wifi_portal\src\l1\`（HTTP 与接口层），
> 页面字符串在 `src\l1\page.c` 的 `index_html` 等常量里。
> ⚠️ 2026-11-16 分层改造后不再是单个 `src\main.c`：路由去 `src\l1\http_core.c`、
> 灯语去 `src\l2\led_status.c`、自检去 `src\l1\selftest.c`；本篇讲的报文格式与判据没变。
>
> 前置：板子 STA 已连上路由器，拿到 `10.168.1.226`（用串口日志里的 `STA got IP:` 一行确认，
> **不要**用 `192.168.4.1` 去诊断 —— 那是 AP 侧地址，实测不是本板）。

## 1. 页面长什么样

一个页面走完全部操作：顶部状态条（连接状态 / SSID / IP / RSSI / 掉线次数 / 运行时长 / 时钟），
中间按卡片分区：

| 卡片 | 干什么 | 对应接口 |
|---|---|---|
| 网络 | 扫描、连接、忘记、断开、切换 | `/api/scan`、`/api/connect`、`/api/forget`、`/api/disconnect` |
| 已保存网络 | 列出 NVS 里的凭据，标「当前」 | `/api/saved` |
| AP 客户端 | 谁连在板子的热点上 | `/api/apclients` |
| 信号历史 | RSSI 折线（最近若干点） | `/api/rssi_hist` |
| 掉线日志 | 最近的断连事件 | `/api/wlog` |
| 启动信息 | 启动次数、崩溃次数、上次运行时长、是否干净退出 | `/api/boot` |
| 远程命令 | 网页里直接跑 shell 命令 | `/api/shell`（见 17.2） |
| OTA | 选固件、上传、看进度、重启生效 | `:8080/ota`（见 17.5、17.6） |
| 口令 | 改配网页口令 | `/api/pw` |
| 两个槽 | 各槽镜像大小/版本、是否 confirmed、swap 类型（只读，回滚评估用） | `/api/ota/slots`（见 17.9） |

## 2. `/api/status`：所有监控数据的唯一出口

页面每 2 s 拉一次这个接口。字段（实测返回）：

```json
{
  "state":"connected","ssid":"501A","ip":"10.168.1.226","msg":"connected",
  "rssi":-48,"reconnects":0,"uptime":82,"last_err":"","clock":"18:05:32",
  "netcheck":200,"netrc":42,"netdone":1,
  "dns":0,"dnsip":"203.107.6.88","gw":"10.168.1.1","netip":"183.2.172.177",
  "sntp":0,"sntpsrv":"203.107.6.88",
  "wlog":1,
  "boot":{"n":27,"crash":6,"last_up":76,"clean":false,"rst":"other"},
  "ota":{"stage":"idle","pct":0,"written":0,"total":0,"ver":0,
         "local_ver":112,"pending":false,"err":""}
}
```

几处值得记住的语义：

- `boot.clean`：上一次是「主动重启/正常退出」还是「异常掉电/崩溃」。OTA 主动重启前会调
  `ops_boot_mark_clean()`，所以 `rst:"software" + clean:true` 是正常 OTA 重启的证据。
- `ota.stage`：`idle / recv / verify / ready / fail`。**`ready` 表示镜像已落盘并校验通过、
  只等重启**；这个状态不会被"别人乱发一个请求"抹掉（见 17.5 里 `fail()` 的坑）。
- `netcheck`：HTTP 出网自检的返回码；`dns`：DNS 解析自检结果；`sntp`：对时状态。
- `wlog`：掉线日志条数，明细在 `/api/wlog`。

## 3. 用命令行验收（不依赖浏览器）

```powershell
$root = "C:\Users\xiao1\Desktop\ELAB\kharon-ide"
& "$root\.venv\Scripts\python.exe" -c "import json,urllib.request;print(json.load(urllib.request.urlopen('http://10.168.1.226/api/status?k=<REDACTED-PSK>',timeout=10)))"
```

为什么把这一步做成习惯：**产品内置浏览器与本机局域网是隔离的**（实测 `blocked=unreachable`），
所以在这个项目里，板子页面一律用 python urllib 直连 STA 侧 IP 验证，不要试图用产品浏览器打开。

## 4. 鉴权怎么带上

所有接口都要求查询参数 `k=<口令>`（默认 `<REDACTED-PSK>`，存 NVS `auth/pw`）。
没带 `k` 时：

- `/` 返回 200 + 解锁页（让人输入口令）；
- `/api/*` 返回 401，body 就是一句人话：`need key: 在网址后加 ?k=<口令>`。

为什么是查询参数而不是请求头：本版 Zephyr 的 HTTP server 头捕获有缺陷
（`CONFIG_HTTP_SERVER_CAPTURE_HEADERS` 恒为 NONE），任何基于 `request_ctx->headers` 的鉴权都会**恒放行**。
这条坑在 17.4 里详述。

## 5. 常见误判

| 现象 | 真正原因 |
|---|---|
| 手机开页面 `ERR_TOO_MANY_REDIRECTS` | captive portal 的 302 自跳环，见 17.4 的 captive 说明 |
| 页面显示 IP `0.0.0.0` | STA 没连上，不是接口坏了 |
| `connect failed 4` | 密码错/AP 拒绝；`3` 通常是找不到 AP，`missing ssid` 是请求参数没带 |
| `/api/status` 401 | 忘了 `?k=` |

补充一条 2026-11-16 的实测：**带 `psk` 的请求曾经全 401**，因为口令是从 `strstr("k=")` 裸搜出来的，
而 `psk=` 的尾巴正好是 `k=`。修法是按参数边界（`q == buf` / `?` / `&`）判，详见 17.4 第 1.1 节。

## 6. 2026-11-16 补记：页面已经按受众分离

现在 `/` 返回哪一页**取决于请求从哪个网段来**：

| 来源 | 返回 | 响应头 |
|---|---|---|
| `192.168.4.0/24`（手机连 `S3-Portal`） | 用户配网页（只有扫描/连接/已保存/忘记/断开） | `X-Portal-Scope: user` |
| 局域网 + 无 `?k=` | 要口令的小页 | — |
| 局域网 + 有 `?k=` | 开发者台（状态/日志/OTA/远程命令） | `X-Portal-Scope: dev` |

`/api/status` 这类开发者接口在 AP 侧直接 404，所以"页面里没画卡片"之外，手敲 URL 也拿不到命令。
断连原因改成**掉线即写 NVS**，重启后局域网 `/api/drops` 就能查（不再靠挂串口）。
实现与踩坑见 [17.10 页面受众分离](17.10-页面受众分离（用户配网页与开发者台）.md)。
