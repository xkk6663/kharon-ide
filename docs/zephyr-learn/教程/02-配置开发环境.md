# 02 · 配置开发环境

> **现状校准（2026-11-19）**：当前仓库用 `.deps/venv` + `.deps/tools`，环境由
> `kharon env` 从 host yaml / provider 生成；旧 `tools\zephyr\env.ps1` 可作 fallback，
> 但默认不再让你手写。west 工作区是仓库根
> `west/`，`ZEPHYR_BASE=west/zephyr`。下面第 1–4 步的依赖说明仍有参考价值，
> 第 5 步已换成当前入口；旧 `cross-compile` 路线只作为历史坑保留。

这一章只做一件事：让 `west build` 能在你的 Windows 上跑起来。

## 需要哪几样东西

| 组件 | 作用 | 不装会怎样 |
|---|---|---|
| Python 3.10+ | 跑 west、Zephyr 的构建脚本 | 什么都做不了 |
| west | Zephyr 的元构建工具（管工作区、调 cmake） | — |
| Git | 拉代码 | — |
| CMake ≥ 3.20 | 生成构建系统 | `west build` 直接报错 |
| Ninja | 实际执行编译 | 会退回 Make，慢且容易出错 |
| RISC-V 工具链 | 编译 S31 的代码 | 编译阶段找 `riscv32-*-gcc` 失败 |
| Python 依赖包 | `scripts/requirements.txt` | 生成 devicetree 头文件时崩 |

`dtc`（devicetree compiler）在 Zephyr 4.x 里**不是必需的**——DTS 的预处理已经交给 Python 侧的 `edtlib` 了，`dts.cmake` 里只在找到 dtc 时才用它做额外检查。所以没有 dtc 也能构建，这点和很多老教程不一样。

## 第 1 步：独立的 Python 环境

不要用 ESP-IDF 那套 Python，两边包版本会打架：

```powershell
python -m venv C:\Users\xiao1\Desktop\ELAB\kharon-ide\.deps\venv
C:\Users\xiao1\Desktop\ELAB\kharon-ide\.deps\venv\Scripts\Activate.ps1
pip install west
```

## 第 2 步：CMake 和 Ninja

两个选择：

**A. 官方安装包**
```powershell
winget install Kitware.CMake
winget install Ninja-build.Ninja
```

**B. 复用你机器上已有的（本教程采用）**

装了 ESP-IDF 的机器，`C:\Espressif\dist\` 里就有现成的 zip，解压即用，不用再下载：

```powershell
$dist = "C:\Espressif\dist"
$out  = "C:\Users\xiao1\Desktop\ELAB\kharon-ide\.deps\tools"
Expand-Archive "$dist\cmake-3.30.2-windows-x86_64.zip" "$out\cmake" -Force
Expand-Archive "$dist\ninja-win.zip" "$out\ninja" -Force
```

然后把这两个目录加进 PATH。注意**别用 cmake 4.x**——Zephyr 的部分 CMake 脚本对 4.x 的兼容还在推进，3.30 最稳。

## 第 3 步：RISC-V 工具链

同样两个选择。

**A. Zephyr 官方 SDK（推荐给干净机器）**

```powershell
west sdk install -t riscv64-zephyr-elf
```
体积约 1 GB，从 GitHub 下载，国内可能要很久。

**B. 复用 ESP-IDF 的 riscv32 工具链（本教程采用）**

装了 ESP-IDF 的机器上已经有：

```
C:\Espressif\tools\riscv32-esp-elf\esp-15.2.0_20251204\riscv32-esp-elf\bin\riscv32-esp-elf-gcc.exe
```

Zephyr 支持"任意交叉编译器"，只要告诉它前缀：

```powershell
$env:ZEPHYR_TOOLCHAIN_VARIANT = "cross-compile"
$env:TOOLCHAIN_HOME = "C:/Espressif/tools/riscv32-esp-elf/esp-15.2.0_20251204/riscv32-esp-elf/bin"
$env:CROSS_COMPILE  = "C:/Espressif/tools/riscv32-esp-elf/esp-15.2.0_20251204/riscv32-esp-elf/bin/riscv32-esp-elf-"
```

`CROSS_COMPILE` 是**前缀 + 结尾的短横线**，不是目录；路径必须**正斜杠**，用反斜杠会被 CMake 当转义吃掉（详见第 5 步的坑）。写错会报 `Zephyr was unable to find the toolchain`。

> **这条路不是我拍脑袋想的**：参考教程（YuzukiNeko / 玄铁 C907 板）也是 `ZEPHYR_TOOLCHAIN_VARIANT=cross-compile` + 玄铁 900 GCC + 一个 `env.sh`，明确说"不使用 Zephyr SDK"。手上已有厂商工具链时，cross-compile 是标准做法。

代价是：这个工具链的 libc 是 newlib，Zephyr 默认期望 picolibc。如果构建报 libc 相关错误，就加 `CONFIG_PICOLIBC=n` 并用 newlib，或者换回方案 A。**本教程后续章节的实测结果，会在 04 章注明实际用的是哪条。**


## 第 4 步：Python 依赖

```powershell
pip install -r C:\Users\xiao1\Desktop\ELAB\kharon-ide\west\zephyr\scripts\requirements.txt
```

这个文件会连带装 `requirements-extras.txt`（包含 spsdk、Pillow 这些，体积不小）。**建议装，别偷懒**：少了 `pyelftools` 或 `pykwalify`，症状是构建到 30% 突然报一个和代码毫无关系的 Python traceback。

## 第 5 步：生成环境脚本（当前仓库）

当前仓库的默认入口是 `kharon env`；旧 `tools\zephyr\env.ps1` 仍可作 fallback，环境事实来自 `config/host.*.profile.yaml` 与 provider 的
`defaults.env`。新机器先把本机覆盖模板复制出来，填 SDK / 工具链绝对路径：

```powershell
Copy-Item config\host.local.yaml.example host.local.yaml
# 编辑 host.local.yaml 的 classic:/kharon: 分节（SDK、GCC、OpenOCD 路径）
```

然后在仓库根执行：

```powershell
cd C:\Users\xiao1\Desktop\ELAB\kharon-ide
.\kharon.cmd env --out scripts\kharon-env.ps1
. .\scripts\kharon-env.ps1
```

脚本会设置 `ZEPHYR_BASE=west/zephyr`、`ZEPHYR_SDK_INSTALL_DIR`，并前置
`.deps/venv`、CMake、Ninja、ccache、`arm-zephyr-eabi` 的 PATH。`kharon env --check`
只校验 host/provider 能否收集，不输出脚本。

以后每个新终端第一件事：`. .\scripts\kharon-env.ps1`。

### 如果你仍走旧的 cross-compile 路线（历史坑）

1. **反斜杠**：写成 `C:\Espressif\...\riscv32-esp-elf-` 会报

   ```
   Zephyr was unable to find the toolchain. Is the environment misconfigured?
   CROSS_COMPILE: C:\Espressif\...
   TOOLCHAIN_HOME:
   ```

   因为 `cmake/compiler/gcc/generic.cmake` 里那行是
   `find_program(CMAKE_C_COMPILER ${CROSS_COMPILE}${CC} PATHS ${TOOLCHAIN_HOME} NO_DEFAULT_PATH)`，
   反斜杠在 CMake 字符串里被当转义序列吃掉了。**全部换正斜杠**即可。

2. **只设 `CROSS_COMPILE` 不设 `TOOLCHAIN_HOME`**：`NO_DEFAULT_PATH` 让 CMake 不去 PATH 里找，只信 `TOOLCHAIN_HOME`。两个都设才稳。

修好之后日志里会出现这两行，说明通了：

```
-- Found toolchain: cross-compile (C:/Espressif/tools/riscv32-esp-elf/esp-15.2.0_20251204/riscv32-esp-elf/bin/riscv32-esp-elf-)
-- The C compiler identification is GNU 15.2.0
```

## 自检

```powershell
west --version
cmake --version
ninja --version
& "${env:CROSS_COMPILE}gcc" --version        # 能打印 riscv32-esp-elf-gcc 版本
python -c "import elftools, yaml; print('deps ok')"
```

四条都过，环境就齐了。

## 常见错误

| 报错 | 原因 |
|---|---|
| `'west' 不是内部或外部命令` | venv 没激活，或 PATH 没加 |
| `CMake 3.x or higher is required` | cmake 版本低了，或 PATH 里是另一个 cmake |
| `Could NOT find Ninja` | ninja 没进 PATH |
| `riscv32-esp-elf-gcc: not found` | `CROSS_COMPILE` 结尾少了 `-`，或路径是目录不是前缀 |
| `ModuleNotFoundError: elftools` | 第 4 步没做，或装到了别的 Python |
