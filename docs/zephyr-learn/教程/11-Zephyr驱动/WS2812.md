# WS2812（led_strip）

这块板子上的 RGB 灯只有一颗，接在 **GPIO37**。它是 800 kHz 单线时序的 WS2812，用普通 GPIO 翻转很难稳住时序，所以 Zephyr 在 ESP32 上走的是 **RMT 外设 + `pulse_io` 抽象**：

- `led_strip` 对上提供"给我一组 RGB，把灯点亮"；
- 底下 `ws2812_pulse_io.c` 把 RGB 编成一串脉宽，交给 `pulse_io`；
- `pulse_io_esp32_rmt.c` 用 RMT 通道把脉宽硬件发出去。

中间这一层是你在这棵树上必须知道的东西，因为 **Kconfig 选的是 `WS2812_STRIP_PULSE_IO`，不是 RMT**。

本页所有输出来自 `lab led`。

## 设备树

板级 dts 里已经定义好灯（`esp32s31_function_coreboard_hpcore.dts`）：

```dts
led_strip: ws2812 {
	compatible = "worldsemi,ws2812-pulse-io";
	pulse-ios = <&rmt 0>;        /* 用 RMT 通道 0 */
	chain-length = <1>;          /* 只有一颗灯 */
	color-mapping = <LED_COLOR_ID_GREEN LED_COLOR_ID_RED LED_COLOR_ID_BLUE>;
	reset-delay = <300>;         /* 复位低电平 300 us */
};
```

`color-mapping` 是 GRB —— WS2812 的物理顺序是绿、红、蓝，驱动会按这个顺序重排字节，所以你在代码里写 `r/g/b` 不用管硬件顺序。

RMT 本身默认 `disabled`，且要先分配引脚：

```dts
&pinctrl {
	rmt_korvo: rmt_korvo {
		group1 { pinmux = <RMT_OUT0_GPIO37>; };
	};
};

&rmt {
	pinctrl-0 = <&rmt_korvo>;
	pinctrl-names = "default";
	status = "okay";
};
```

```conf
CONFIG_LED_STRIP=y
CONFIG_WS2812_STRIP_PULSE_IO=y
```

📖 `CONFIG_WS2812_STRIP_PULSE_IO` 依赖 `DT_HAS_WORLDSEMI_WS2812_PULSE_IO_ENABLED`（也就是设备树里有那个 `compatible`），并 `select PULSE_IO`。它**不** select RMT——RMT 是被 `pulse_io` 那一层选中的。

## led_strip_length

```c
size_t led_strip_length(const struct device *strip);
```

返回 `chain-length`。用来确认"驱动看到的灯数"和你的缓冲区大小是否一致。

```c
shell_print(sh, "[node] strip=%s, length=%d", strip->name, led_strip_length(strip));
```

板子输出：

```text
[node] strip=ws2812, length=1
```

## led_strip_update_rgb

```c
int led_strip_update_rgb(const struct device *strip, const struct led_rgb *pixels, size_t num_pixels);
```

一次把 `num_pixels` 个 RGB 值刷出去。`led_rgb` 是三个 `uint8_t`（r/g/b），**亮度要自己控制**——WS2812 单颗满亮电流不小，本页刻意用 `0x20`（约 12%）而不是 `0xff`。

```c
struct led_rgb px = {0};
const char *names[] = {"红", "绿", "蓝", "白", "灭"};
struct led_rgb colors[] = {
	{.r = 0x20, .g = 0x00, .b = 0x00},
	{.r = 0x00, .g = 0x20, .b = 0x00},
	{.r = 0x00, .g = 0x00, .b = 0x20},
	{.r = 0x20, .g = 0x20, .b = 0x20},
	{.r = 0x00, .g = 0x00, .b = 0x00},
};

for (int i = 0; i < ARRAY_SIZE(colors); i++) {
	px = colors[i];
	int ret = led_strip_update_rgb(strip, &px, 1);
	shell_print(sh, "[update] %s = %s", names[i], err(ret));
	k_msleep(400);
}
```

板子输出：

```text
[color-mapping] 板级 dts 是 GRB，驱动自动按此重排
[update] 红 = 0
[update] 绿 = 0
[update] 蓝 = 0
[update] 白 = 0
[update] 灭 = 0
[update] 完成（WS2812 在 GPIO37）
```

✅ **自检**：五行全 0，灯应该在红/绿/蓝/白/灭之间每 400 ms 换一次（灭之后停住）。**这一节是全教程里唯一"返回值 0 就等于看见了效果"的地方**——灯亮没亮眼睛就能判断，不需要回读寄存器。

⚠️ 如果 `led_strip_update_rgb` 回 `-ENODEV` 或设备没就绪，代码里会打印：

```text
led_strip not ready：检查 CONFIG_WS2812_STRIP_PULSE_IO 和 &rmt
```

三个排查点：`CONFIG_LED_STRIP` 有没有开、`compatible` 是不是 `worldsemi,ws2812-pulse-io`、`&rmt` 有没有 `status = "okay"` 并配好 `RMT_OUT0_GPIO37`。

## 为什么不是"GPIO 翻转 + 忙等"

| 方案 | 能不能用 | 原因 |
|---|---|---|
| 普通 GPIO 翻转 + `k_busy_wait` | ❌ | 800 kHz 下高电平 0.4/0.8 µs，还有中断抖动，颜色会错 |
| `led_strip` + `pulse_io` + RMT | ✅ | 脉宽由 RMT 硬件产生，不占 CPU，不受中断影响 |
| `led_strip` + SPI 伪时序 | ❌ | 这块板子没把 WS2812 接到 SPI 上 |

📖 这也是"驱动分层"的价值：你只写 `led_strip_update_rgb`，底层换 RMT/SPI/PWM 都不用改应用代码。参考教程里那块板用的是另一套底层，但上层 API 完全一样。

## 这一页要带走的东西

| 结论 | 证据 |
|---|---|
| 灯在 GPIO37，走 RMT 通道 0 | `pinctrl` 里的 `RMT_OUT0_GPIO37`、`pulse-ios = <&rmt 0>` |
| 颜色顺序 GRB 由设备树声明 | `[node] strip=ws2812, length=1` + dts 的 `color-mapping` |
| 亮度要给小值 | 示例用 `0x20` 而不是 `0xff` |
| 这是最适合"验证到头"的外设 | 返回值 0 + 肉眼可见 |
