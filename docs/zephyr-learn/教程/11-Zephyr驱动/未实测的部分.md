# 没做到"实机演示"的部分

这一页是诚实清单。上一页那句"每个接口都有真机输出"只对 GPIO / I2C / ADC / WS2812 四类成立。下面这些要么硬件上没法观测，要么这棵树上根本没有驱动，我把"为什么做不了"和"要补什么才能做"写清楚，你以后有条件时可以直接接上。

## 1. PWM（`ledc0`）

**现状**：SoC dtsi 里有 `ledc0@20392000`（`espressif,esp32-ledc`、`pwm-controller`、`#pwm-cells=3`），默认 `disabled`；驱动 `pwm_esp32.c` 在树里，`CONFIG_PWM=y` 就能用。

**为什么没做**：Korvo-1 上没有任何 PWM 引脚接出去的可观测负载。板子上能接 PWM 的只有背光/蜂鸣器这类，背光由屏幕那侧的驱动占用，蜂鸣器没有引出排针。写了 `pwm_set_dt` 也只会返回 0，示波器不在手边时**无法区分"真的在输出"和"参数写进寄存器了"**——这正是本教程反复强调的"返回 0 不等于有效果"。

**要补什么**：

```dts
&ledc0 {
	status = "okay";
	pinctrl-0 = <&ledc0_korvo>;     /* 需要自己写 pinmux 宏 */
	pinctrl-names = "default";
};
```

再挑一个空闲脚（比如 DB15 的 GPIO36）外接 LED + 电阻，就能用 `pwm_set_dt` 调亮度并肉眼验证。**这是唯一"代码能写、就差一根线"的驱动**，有条件时最值得补。

## 2. UART（第二个串口）

**现状**：`uart@2038a000` 就是 `uart0`，已经是 shell 的控制台（COM9 / 115200）。SoC 里还有 UART1 / UART2，但 Korvo-1 没有把它们引到排针上（UART1 通常被日志或下载口占用）。

**为什么没做**：把控制台换到 UART1、再用 UART0 做回环，是能做的，但会**让 shell 从 COM9 上消失**——一旦 `chosen` 指向别的 UART，你连命令都发不进去，只能 `esptool erase_flash` 救回来。对"跟着教程一步步学"的人来说风险太高，收益只有一个 `uart_poll_out` 的返回值。

**要补什么**：如果确定要试，先确认 `chosen { zephyr,console = &uart0; }` 别动，只把 UART1 打开、把 TX/RX 短接做自环：

```dts
&uart1 { status = "okay"; current-speed = <115200>; };
```

然后 `uart_fill_fifo` + `uart_poll_out` + `uart_poll_in`，自环时发什么收什么，这才是可验证的。⚠️ 短接前确认那一对脚真的是 UART1 的 TX/RX。

## 3. I2S / 音频（ES8389）

`ES8389` 在 0x10 上能读能写（见 [I2C](I2C.md)），但**Zephyr 里没有 ES8389 的 codec 驱动**，I2S 也不在 S31 这份 PR 的已支持列表里。所以"放一段声音"这件事在这棵树上做不了，只能做到"我确认了 codec 在总线上、能读它的寄存器"。

## 4. 显示 / 触摸 / 摄像头

| 器件 | 型号 | 状态 |
|---|---|---|
| LCD | ST7262E43 | 无 Zephyr 驱动 |
| 触摸 | GT1151 | 无 Zephyr 驱动 |
| 摄像头 | DVP/CSI 接口的模组 | 无驱动，PR 未合 |
| G2D / VDEC | 硬件加速单元 | 无驱动 |

这四项是"这块板子最像开发板的部分"，恰恰也是 Zephyr 侧最空的部分。想学显示栈，得等上游把 `display_esp32*` 补到 S31，或者自己照 `drivers/display/display_st77xx.c` 的写法移植一个。

## 5. Wi-Fi / BLE

仍然在草稿 PR 里（`#125547`、`#123231`）。`net` 子系统能编译、能跑 `net iface`，但没有可用的射频驱动，扫不到 AP。

## 6. 低功耗（PM）

这份 PR 只跑 HP 核、CPU1 处于复位状态，没有 PM 框架支持，只有 `sys_poweroff()` 能用。所以 `CONFIG_PM` 相关的示例（tickless、device runtime PM、`pm_device_action`）都不能在本板验证。

## 怎么处理"教程里有、板子上跑不了"的段落

本教程的原则是：**代码照写、状态照标**。

- 代码块保留（它是通用写法，换成有硬件/有驱动的板子就能跑）；
- 段落开头标 `📖`（概念、无实测）而不是 `✅`（实测）；
- 在页面末尾或本节这样的清单里写清楚"缺什么"，不假装跑过。

如果你在别的板子上补齐了，把输出贴回对应页面替换掉那一段的标记即可——页面结构本来就是按"一个接口一小节、小节里留输出位"设计的。
