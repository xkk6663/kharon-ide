## Zephyr 是什么

Zephyr 是一个由 Linux Foundation 托管、面向资源受限设备的实时操作系统。和 ESP-IDF 最大的区别不是"功能多少"，而是**硬件描述与驱动实现分离**：

- 硬件长什么样，写在 **devicetree**（`.dts` / `.overlay`）里；
- 要开哪些功能，写在 **Kconfig**（`prj.conf`）里；
- 应用代码只跟**统一的驱动 API** 打交道，不关心底层是 ESP32 还是 STM32。

所以同一份 `i2c` 代码，在 STM32、nRF、ESP32 上写法完全一样。这是 Zephyr 最值钱的部分。

## 这本教程的定位

面向"想系统学 Zephyr、并且希望每一步都能在真实板子上复现"的读者。全书只讲**一个版本**（Zephyr 4.5.99 / SDK 1.0.1，见 01 章），结构固定为**三层**：一条主线、一类迁移练习、一个附录。

| 层 | 板子 | 为什么放在这一层 | 状态 | 位置 |
|---|---|---|---|---|
| **主线** | **ESP32-S3**（`esp32s3_devkitc/esp32s3/procpu`） | 主干直接支持、零补丁，读者拿一块小板就能复现 | ✅ 已实测 | 00–17 章 |
| **迁移练习** | **STM32F411CEU6 / STM32F103C8T6**（Black Pill / 最小系统板） | 主干有完整 STM32 系列支持，是“同一份代码换到另一家芯片”的第二站：换架构（ARM）、换厂商、换 pinctrl 语法，再换烧录探针 | ✅ F411 已实机（`tutorials/10`/`14`）；F103 见第 15 组 | 第 15 章那套六步 |
| **附录 A** | **ESP32-S31**（Korvo-1 V1.1） | 主干没有这个 SoC，靠未合并 PR #119851；读者打不上补丁就卡在第一步 | 📖 只到"能编能烧、基础外设可用" | 附录 A |

这么排的理由只有一条：**教程要别人能跟着做。** 主线用 S3，读者敲 `west build -b esp32s3_devkitc/esp32s3/procpu` 就能复现，不用先打补丁、也不用担心哪天上游 rebase 把教程里的 commit 冲掉。

而 Korvo-1/S31 不是删掉，是**改当附录 A**——它恰好是"一块还没进主干的芯片长什么样"的真实样本，能讲清主干板子讲不出来的那一层：SoC dtsi、pinctrl 头文件、Kconfig.caps、板级 15 文件、驱动里的 SoC gate（我们踩到的坑也在里面，见 `docs\课程同款\07-七项外设落地实录.md` §9.1 与 `08` 章）。

> **先记住一句**：Zephyr 的"跨芯片"是**框架统一、支持分散**——同一套 API 换板不改代码，但每个芯片都有自己的 SoC 层、dtsi 和板级目录，编译仍然按板目标分别编译。不是一份固件通吃所有板子。

### 以后的芯片往哪一层放

加一块新板时，按这三个问题定层（和附录 A 里那套判定同源）：

1. SoC 的 dtsi 在**主干**里有吗？（`zephyr\dts\<arch>\<vendor>\<soc>\`）
2. 驱动里认这块 SoC 吗？（`drivers\...` 里有没有 `#if defined(CONFIG_SOC_SERIES_xxx)`）
3. 有没有现成板级？（`zephyr\boards\<vendor>\`）

| 判定结果 | 放哪一层 | 例子 |
|---|---|---|
| 三个"有" | **迁移练习**（第 15 章加一节） | STM32 Nucleo、ESP32-P4、nRF |
| SoC 层在主干的 PR 里 | **附录**（写清缺哪层、怎么补） | S31 / Korvo-1 |
| SoC 层都没有，只有自家板 | 自己写板级（`03c` 的五层职责 + 模板） | 自制底板 |

**不要把新芯片开成新主线。** 教程一旦有两条主线，读者就不知道该跟哪条走；正确做法永远是"主线不动，加一节迁移练习"。

### 不是什么

- 不是"找一个官方镜像刷进去"——Zephyr **从来不发布板级预编译镜像**，所有固件都得自己编；
- 不是"ESP-IDF 的替代品介绍"——两者并存，S31 上音频/屏幕这类 Zephyr 侧还没通的东西，回 ESP-IDF 是理性做法。

## 主线这块板（S3）能跑什么

能（主干支持，书里都实测过）：UART / USB-Serial-JTAG、GPIO + pinctrl、I2C、SPI、LEDC/PWM、**ADC（12 位）**、RMT + WS2812、TWAI、**I2S**、**SD 卡（SDMMC）**、**LCD_CAM（并口屏 / DVP 摄像头）**、**Wi-Fi**、**BLE**、AES/SHA、WDT、Flash+PSRAM。

不能 / 要注意：板载没有 PA_CTRL、没有 IO42 四键分压梯、没有 codec —— 这些是 Korvo-1 才有的东西，附录 A 里讲。

## 附录 A 那块板（S31 Korvo-1）能跑什么

能（PR 已支持）：UART / USB-Serial-JTAG、GPIO + pinctrl、I2C、SPI(+GDMA)、LEDC/PWM、MCPWM、TWAI-FD、ADC、RMT/WS2812、温度传感器、TRNG、AES/SHA、WDT、Flash+PSRAM。

不能（书里明确跳过）：
- **Wi-Fi / BLE / 802.15.4**：白名单不含 S31；
- **I2S / SD 卡 / LCD_CAM（并口屏、DVP 摄像头）**：S31 的 SoC dtsi 里没有这些节点；
- **ADC 四键**：能读出通道值，但 IO42 的按键判定在 Zephyr 侧目前不成立（证据链见 `06` §9.1）；
- 双核：PR 只用 HP 核，CPU1 保持在复位。

## 读完的顺序

1. **00 → 01 → 02 → 03 → 04 → 05**：环境与工具，六章连着做，中间断一步后面全卡；
2. **10 → 11 → 12**：主线知识（sample → 驱动 → 组件），边读边在 S3 上动手；
3. **13 → 14 → 16 → 17**：把板子真正用起来（RGB / 按键 / NVS / 系统层 / 无线）；
4. **15**：等你有了一份"确实能跑"的代码之后再读，它讲的是"把板子差异从代码里摘出去"。**这一组就是"迁移练习"的模板**：已实测三条路径——S31(RISC-V) ↔ S3(Xtensa)、ESP32 → STM32F411（换厂商）、STM32F411 → STM32F103（同厂商换系列）。你手上的 STM32 板照同一套六步做即可；前置条件是 SDK 的 `arm-zephyr-eabi` 目标已装好（本机三个目标齐全：`riscv64` / `xtensa-esp32s3` / `arm-zephyr-eabi`）。
5. **附录 A**：随时可读。它不依赖前面任何一步，但读之前最好已经做过一次 15 章的跨芯片迁移。

每一章末尾都有 **自检**，答不上来就回去重读那一段——比继续往下翻有效。
