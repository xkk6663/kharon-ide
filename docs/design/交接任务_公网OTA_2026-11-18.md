### 2.2 固件侧（主体已写完，尚未编译通过）

分层：`ota_cloud.c` 属 **L0 引擎层**，不 include L2 头；链路状态由 `wifi_link.c`（L2）通过 `ota_cloud_link_feed()` 反向喂入，符合既有分层纪律。

时序（与 `cloudhub.py` 逐字对齐）：

1. TLS1.2 连 `120.76.230.17:8443`，CA 内嵌（`hub_ca.inc`），校验 CN/IP SAN；
2. `GET /v1/ota/check?dev=<id>` + `X-Dev-Token` → 204 继续睡 / 200 拿 OFFER；
3. 四道门禁（复用 `ota_engine` + 局域网同一把 PSK）：
   - `HMAC-SHA256(PSK, "ver|size|sha256|nonce|force")` 比对 `OFFER.auth`
   - nonce 严格递增（NVS 账本，重放必死）
   - `ver` 必须大于本机版本（`force` 无豁免，公网不开放配网页那种弱口令档）
   - `size` ≤ 槽容量
4. `GET /fw/<file>?dev=<id>`（`X-Dev-Token`，续传带 `Range`）→ 流式写 slot1，共用 `ota_backend`，SHA-256 累积 + 回读；
5. `POST /v1/ota/report?dev=<id>` → admin 在 `/v1/ota/status` 查；
6. `ota_arm_upgrade()`：`BOOT_UPGRADE_PERMANENT` 切槽 + nonce 提交 + 清断点 + 记自证窗口。

线程模型：专属线程 + 信号量（阻塞 socket/TLS 握手不进系统工作队列）；周期 15 min，`portal ocheck` 可手动踢醒；`ota_lan_idle()==false` 时拒绝并发（写槽上下文是全局的）。

## 8. 不要踩的坑（前面已经替你踩过）

1. **不要**用 `west config build.sysbuild` —— 工作区全局，会把普通工程一起劫持；sysbuild 是工程根 `sysbuild.conf` 的文件系统事实，内核注入 `${ws:sysbuild_flag}`。
2. **不要**用 `runner: esp` —— `runners.yaml` 里是 **`esp32`**。
3. esptool 三坑：PATH 要含 `.deps/venv/Scripts`；venv 要有 `cbor2`；`esptool.exe` shim 会整个静默坏（重装即好）。
4. `doctor` 对全 provider 工程跳过 ARM 工具链检查；board-as-chip（有 `target` 键）走 zephyr 口径。
5. 驾驶舱 flash 是否需要探针由芯片 `flash.runner` 裁定，非 openocd 免探针。
6. 改 `packs/**` 后必须跑 `./elab pkg index`（本任务目前没改 packs，暂不需要）。
7. Git 提交纪律：**等用户明确指令再 commit**。
8. 行尾：Write/Edit 会把整份文件转 CRLF；批量改完先看 `git diff --stat`，异常大的单文件行数就是翻车信号。
