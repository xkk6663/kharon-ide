> 目标：classic（elab 裸机 + CubeMX/IDF 工程）的每个例程，在 Zephyr 侧都有一个**能上板跑、
> 能进教程**的对等物；教程沿用旧版风格（实机截图 + 逐步讲解 + 证据链），架构段落补手写 SVG。

判定「教程可用」的四条硬标准（每条都验，不靠感觉）：

1. **能上板**：`kharon run -p <proj> --steps doctor,build,report,flash,monitor` 全绿，证据落盘。
2. **能看见**：驾驶舱里左栏可选中、构建面板有数、串口有输出（截图来自真面板）。
3. **图文并茂**：≥1 张实机截图 + ≥1 张手写 SVG 架构图 + 命令可复制即用。
4. **能回去**：classic 原篇顶部有一行「→ Zephyr 版：[NN-xxx](NN-xxx.md)」，不删旧内容。

## 3. 批次与顺序（为什么是这个顺序）

| 批次 | 内容 | 为什么排这里 |
|---|---|---|
| **A** | 路线图 + `10-Zephyr模式上手`（f411_breath） | 先把「新教程长什么样」定下来，后面每篇照这个模子写 |
| **B** | `E3 f411_modbus` + `11-Zephyr_Modbus从站` | 唯一一个「同一块板、同一条串口、同一套面板」的严格对照：换固件不换工具，最能说明迁移成本 |
| **C** | `E2 f411_ota`（MCUboot）+ 教程；`E6 wave` + `E5 korvo` 教程 | OTA 是 Zephyr 侧真正的新增量（镜像签名、槽位交换），需要单独一轮把 swap 策略与回滚讲透 |
| **D** | 站点整合（`site/tutorials.json`、索引分组） + classic 篇 legacy 标注 | 内容齐了再改导航，避免半成品入口 |

顺序的底层逻辑：**先工具、再协议、后系统**。工具（A）定标准；协议（B）证明「一套内核驱动两种固件」；
系统（C）才是 Zephyr 独有能力（OTA/多板）的展示；收口（D）永远最后。

## 4. blocked：AT32F421（E4）

`west/zephyr/boards/` 下没有 `artery`，`west/zephyr/dts/arm/` 也没有 at32 系列 dtsi。要让 AT32F421
进 Zephyr，需要自己做 SoC porting（clock/pinctrl/gpio/uart dtsi + pinctrl 驱动绑定 + flash 布局），
工作量与「接一颗新芯片」等同，不是写个板子 yaml 的事。

三个选项（**需要人决定**，本轮不擅自开工）：

| 选项 | 代价 | 结果 |
|---|---|---|
| 冻结 | 0 | AT32 只有 classic 版；教程里明写「Zephyr 侧暂不支持」 |
| 上游移植 | 大（SoC dtsi + 驱动验证 + 上游 PR 周期） | 长期最干净，Zephyr 官方支持 at32f421 |
| 私板移植 | 中（在 `boards/` 里做 vendor 板 + 复用上游 at32 驱动，若有） | 快，但要长期跟上游 |

## 6. 素材与写作约定（给后面每一篇用）

- **截图**：真机 + 真内核 + 真面板，统一放 `docs/tutorials/assets/<主题>/`，命名 `NN-描述.png`。
  禁止用示意图冒充截图；示意图一律走 SVG。
- **SVG**：独立文件 `assets/<主题>/*.svg`，浅底深字（GitHub 与站点都要能看），
  `viewBox` 自带留白，字号 ≥ 12，**不依赖外部字体**（用 `font-family="system-ui,Segoe UI,sans-serif"`）。
  教程里用 `![](...)` 引用——站点渲染器 `md2html` 会转义内联 HTML，**内联 `<svg>` 会被吃掉**。
- **代码块**：只放能直接粘进终端的命令和关键源码片段；长源码给路径不整段贴。
- **数字**：一律来自当轮 `run` 输出或面板实测，写完回查一遍证据表。
