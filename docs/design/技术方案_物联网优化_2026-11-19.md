# 技术方案：s3_wifi_portal 物联网能力优化（2026-11-19）

> 目标：在**不新增任何入站端口、不搬局域网能力**的前提下，补齐公网侧的
> 「设备影子 + 命令队列」这一层，使「看状态 / 发命令 / 升级」三件事都能跨网完成。
>
> 适用范围：`applications/esp32s3/s3_wifi_portal`（设备侧）+
> `/opt/hub/cloudhub.py`（云端）。局域网能力（SoftAP 配网、mDNS、`:80` 调试面、
> `:8080` 直推 OTA、串口）**全部保留不动**。

---

## 1. 结论先行

| 问题 | 结论 | 依据 |
|---|---|---|
| 要不要设备被公网访问 | 不要 | 设备在 NAT 后、无稳定地址；`:80` 是口令级调试面，出公网等于公开复位/密钥注入接口 |
| 要不要出站公网 | 要，且已在用 | 8443 TLS1.2 + CA 固定，5 轮真机 OTA（152→159）全部通过 |
| 局域网"发现"要不要搬 | 不要 | mDNS/SSDP/SoftAP 依赖二层广播，公网无广播域；云端对应物是"账号绑定 + 设备列表"，不是发现 |
| 现在缺什么 | 只缺公网侧「影子 + 命令」，外加轮询节奏与失败退避 | 云端仅有 `POST /v1/ota/report`，过程与状态不可见 |

## 3. 总体设计：一条出站连接承载三件事

```text
                    ┌──────────── VPS cloudhub :8443 (TLS1.2, CA pin) ────────────┐
   设备 (只出站)      │  /v1/ota/check   /v1/shadow   /v1/cmd/result   /fw/<file>  │
      │  ── 1 次 TLS 会话（keep-alive）────────────────────────────────────────▶ │
      │  ① POST /v1/shadow    心跳快照（本次进入的触发点）                         │
      │  ② GET  /v1/ota/check 带 X-Proto:3 → 应答 {cmds:[], offer:null|{}}       │
      │  ③ 执行命令（白名单）→ POST /v1/cmd/result{id,rc,out}                     │
      │  ④ 有 offer → GET /fw/<file>（Range 续传）→ 校验 → 切槽 → 重启            │
      └──────────────────────────────────────────────────────────────────────────┘
   局域网（不变）：SoftAP 配网、mDNS、:80 调试面、:8080 直推 OTA、串口
```

要点：

1. **不新增端口**。影子、命令、回执全部挂在已有的 8443。
2. **一次连接做完四步**，避免每次 check 都重复 TLS 握手（当前每轮 = 一次完整握手）。
3. **局域网能力一条都不动**：配网、发现、调试、直推都属于"现场/产线"场景，跨网不需要它们。

## 4. 详细设计

### 4.1 轮询节奏与失败退避（改 `ota_cloud.c`）

| 场景 | 周期 | 说明 |
|---|---|---|
| 空闲稳态 | **3 min**（可配置 `HB_PERIOD_SEC`，NVS `s3cloud/hb`） | 兼顾命令延迟与功耗；当前 15 min 对命令不可接受 |
| 有 pending 命令 / 命令执行后 5 min | **1 min 快轮询** | 保证多步操作能连贯完成 |
| 连续失败 | 1→2→5→10→**15 min 封顶** | 替代当前"失败也等 15 min"；成功即复位到空闲周期 |
| 链路上升沿（`NET_EVENT_IPV4_ADDR_ADD`） | **立即** 补一次 | 现在等下一个周期，最长白等 15 min |

失败分类（决定是否值得重试，避免对不可恢复错误死循环）：

| 错误 | 判定 | 动作 |
|---|---|---|
| `-EAGAIN` / `-ETIMEDOUT` | 网络抖动 | 退避重试 |
| `-ECONNREFUSED` / 5xx | 服务端异常 | 退避重试 |
| `-0x2180`（X509_INVALID_FORMAT） | CA/证书配置错 | **不重试**，置 `cfg_err` 上报影子 |
| `-0x7780` 等 TLS 告警 | 握手失败 | 退避，累计 5 次后拉长到 1 h |
| `401` | token 失效 | 不重试，影子里带 `"auth":"badtoken"` |

### 4.2 设备影子（新增 `POST /v1/shadow`）

设备每轮 check 前上报一份快照；云端只保留最新一条 + 可选历史（压缩存储）。

```json
{"dev":"s3-0001","proto":3,"ver":159,"boot":213,"crash":6,"up":365,
 "rssi":-24,"ssid":"Power","ip":"<hub-ip>","link":"sta","reconnects":0,
 "stage":"idle","pct":0,"written":0,"err":"",
 "clock":1795020749,"net":{"dns_rc":0,"http":200},
 "heap_free":12345,"stk":{"cloud":3120,"http":2048,"net":1024},
 "wedge":"none","last_cmd":42}
```

- 序列化用**静态 768 B 缓冲** `snprintf`，不占堆（dram 余量只有 9.5 KB）。
- `stk` 取 `k_thread_stack_space_get()`（`CONFIG_THREAD_STACK_INFO` 已开），用最低水位做"栈要溢出了"的早期告警。
- `wedge` 用来暴露"线程被粘住"：`cloud_run_once` 前后打时间戳，超过 90 s 未归零即置位（本次 204 事故的通用化防护）。
- 云端：`shadows(dev_id TEXT PK, ts INT, body TEXT)`；`GET /v1/shadow?dev=`（仅 admin）返回最新 + 24 h 内变化点。

### 4.3 命令队列（新增 check 应答字段 + `POST /v1/cmd/result`）

**协议升级到 `OTA_PROTO_VER 3`，双端同步发布**（必须，见 4.3.3 兼容性）。

```text
VPS: cmds(id INTEGER PK AUTOINCREMENT, dev_id TEXT, cmd TEXT, args TEXT,
          created INT, ttl INT, state TEXT, done_ts INT, result TEXT)
state: queued | taken | done | expired
```

设备 `GET /v1/ota/check?dev=...` 增加请求头 `X-Proto: 3`，云端按 proto 分支：

```json
HTTP/1.1 200
{"dev":"s3-0001",
 "cmds":[{"id":42,"cmd":"reboot","args":"cold","ttl":300}],
 "offer":null}
```

- 无命令且无 offer → 维持 `204`（省电、省解析），逻辑不变。
- 有命令 → `200`，设备执行完**立即** `POST /v1/cmd/result` 回执。
- offer 与 cmds 可以在同一应答里并存：先回执命令，再走升级（升级会重启，命令不能丢）。

**命令白名单（只放这些，其余一律 403）**

| cmd | args | 作用 | 等价本地入口 |
|---|---|---|---|
| `reboot` | `cold` / `warm` | 复位 | `/api/shell?cmd=kernel+reboot+cold` |
| `ocheck` | — | 立即触发 OTA check | `portal ocheck` |
| `netcheck` | — | 重新跑 DNS+HTTP 自检 | `portal netcheck` |
| `led_test` | `r/g/b/purple/off` | 点亮测试（现场找板子） | 新增，5 s 后自动恢复 |
| `log_dump` | `n<=64` | 拉最近 N 行日志 | `/api/wlog` |
| `cfg_set` | `hb=<sec>` | 改心跳周期（1–60 min） | 新增 |
| `ota_clear_resume` | — | 丢弃断点记录 | 新增 |

**明确禁止**：任何写 `s3ota/psk`、`s3cloud/token` 的命令（密钥注入只能本地/产线）。

### 4.3.1 幂等与防重

- 设备把最后执行过的 `id` 存 NVS `s3cloud/lastcmd`；`id <= lastcmd` 直接回执 `"dup":true` 不执行（防止云端重推导致重启风暴）。
- 命令 `ttl` 到期由云端置 `expired`，设备取到 `ttl` 已过的命令直接回执 `expired`。
- 命令执行串行化：`cmds` 一次最多带 3 条，按 `id` 升序，`reboot` 类必须最后执行。

### 4.3.2 回执

```json
POST /v1/cmd/result {"dev":"s3-0001","id":42,"rc":0,"out":"rebooting (cold)","uptime":365}
```

`out` 截断到 512 B（本地 `/api/shell` 的输出缓冲同样限制，避免把 shell 全量塞进 TLS）。

### 4.3.3 兼容性（关键）

现有 159 固件把 check 的 body 当作 OFFER 解析；若云端对新旧设备一律返回 envelope，
旧设备会报 `offer json parse failed`。因此：

1. 云端**只看 `X-Proto` 头**：缺失或 `<3` → 走旧语义（204 或纯 OFFER JSON）。
2. 设备新固件上线后，云端再用 `clients.proto` 记录灰度（先一台，再全量）。
3. 协议号改动写进 `ota.h` 注释与教程 §8.2，避免下次"字段变了但两端不同步"。

### 4.4 连接复用（省一次握手）

现状：每轮 check = 新建 TLS → 握手 → 一次请求 → close。改为：

- 建一条连接后依次 `shadow → check → cmd/result`，最后 `Connection: close`（不跨轮次保活，规避 NAT 超时与半开连接）。
- 已开的 `CONFIG_MBEDTLS_SSL_SESSION_TICKETS=y` 让跨轮次握手走 session resumption（省一次完整的 X25519/RSA 运算）。
- 只在单轮内复用，不做长连接：**理由**是本方案的目标是"命令 3 分钟内可达"，不是秒级控制；长连接要额外付出保活、重连、半开检测三套状态机，收益不匹配。

### 4.5 安全加固（P1）

| 项 | 现状 | 目标 |
|---|---|---|
| 设备身份 | 编译期 `s3-0001` + 明文 dev-token | 出厂写入 `dev_id`（NVS `s3cloud/dev`）+ **一机一证**（mTLS，ECC P-256），dev-token 退化为过渡 |
| 传输 | dev-token 在 URL query（会进代理/日志） | 改 `X-Dev-Token` 头（云端已支持该头，只需设备改发法） |
| 命令完整性 | 无签名 | `X-Cmd-Sig = hex(HMAC(PSK, "id|cmd|args|ttl"))`，复用现有 PSK；云端生成、设备验 |
| 审计 | 无 | `cmds` 表即审计（谁在何时下发、是否成功、输出摘要），`GET /v1/cmd/log?dev=` 可查 |
| 本地口令 | `k=` 在 URL 里 | 保留（局域网内可接受），但加"仅 STA 网段可用 + 每 IP 5 次/分"限流 |

> mTLS 落地前提：证书签发与烧录链路（产线工具 + NVS 只读分区）。若无产线工具，P1 退化为
> "dev-token 出头 + 命令签名"，其余照做。

### 4.6 资源预算（dram 只剩 9.5 KB）

| 新增项 | 静态占用 | 说明 |
|---|---|---|
| 影子 JSON 缓冲 | 768 B | 静态，一次性 |
| 命令应答解析缓冲 | 1,024 B | 最多 3 条命令 |
| 命令回执缓冲 | 512 B | 复用同一块 |
| 时间戳/状态字段 | ~64 B | — |
| **合计** | **≈ 2.3 KB** | 余量 9.5 KB → 落地后 ~7 KB |

若后续还要加功能，按顺序腾：`HTTP_SERVER_MAX_CLIENTS 4→2`（-1.5 KB）、`HEAP 48→44 KB`（-4 KB）。
**任何腾挪都必须重跑一次完整 OTA 验收**，dram 逼近上限时溢出点在 TLS 握手（历史已踩过 22 KB）。

### 4.7 稳定性防护（把这次事故变成机制）

1. **状态机看门狗**：`cloud_run_once` 入口记 `t_enter`，收尾层检查耗时；> 90 s 记 `wedge` 并上报影子（不改现有收尾逻辑，只是观测）。
2. **task_wdt**：把 `cloud_thread` 注册进 `CONFIG_TASK_WDT`，超 3 个周期未喂 → 打印所有线程栈后重启（比"静默 busy"好排查）。
3. **栈水位进影子**：`stk.cloud` 低于 1 KB 时影子置 `"warn":"lowstack"`，提前于崩溃发现。

### 4.8 省电档（本期不做，写清边界）

当前 `CONFIG_ESP32_WIFI_STA_POWER_SAVE_NONE=y`（APSTA 共存下 modem sleep 会无故掉线）。
本方案面向**插电设备**：3 min 心跳 ≈ 每天 480 次、约 600 B/次，可接受。
若将来是电池设备，路线是"心跳拉长到 15–30 min + 深睡 + 只在有命令时唤醒"，
与"命令 3 分钟可达"直接冲突，需要产品先定 SLA，**不在本期范围**。

## 6. 分期与验收（每期都能独立上机）

### P0 —— 影子 + 命令 + 退避（预计 1.5 人日）

改动面：

| 文件 | 改动 |
|---|---|
| `l0/ota_cloud.c` | 新增 `cloud_shadow()` / `cloud_fetch_cmds()` / `cloud_cmd_result()`；worker 改节奏与退避；`CHECK_PERIOD_MS` 改可配 |
| `l0/cloud_ops.c`（新） | 命令白名单执行器（reboot/ocheck/netcheck/led_test/log_dump/cfg_set） |
| `l0/ota.h` | `OTA_PROTO_VER 2→3`、`OTA_LOCAL_VERSION +1` |
| `l1/shell_cmds.c` | 新增 `portal ccmd`（本地模拟云端下发，便于无网调试） |
| `/opt/hub/cloudhub.py` | 新增 3 端点 + 2 表（`shadows`、`cmds`），按 `X-Proto` 分支 |
| `prj.conf` | 无改动（零新 Kconfig，控制重编代价） |

**验收（机器可判定）**

1. `curl -H "X-Admin-Token: …" https://…/v1/shadow?dev=s3-0001` → `ts` 与当前时间差 < 200 s。
2. `POST /v1/cmd {"cmd":"reboot","args":"cold"}` → 设备 ≤ 3 min 内重启，`boot` +1，`cmds.state=done`，`result.out` 含 `rebooting`。
3. 下发 `{"cmd":"led_test","args":"purple"}` → 灯紫 5 s 后恢复（**需人肉眼确认**，C36 规矩）。
4. 断网 10 min 再恢复：影子 `ts` 在 60 s 内更新（链路上升沿立即触发，不再等一个周期）。
5. 连续三条命令 `id` 递增：全部执行且不重复（NVS `lastcmd` 生效）。
6. 旧固件（159）行为不变：`X-Proto` 缺省仍拿 204/纯 OFFER，回归一次完整 OTA 通过。

### P1 —— 安全与运维（预计 2 人日）

- mTLS（或退化为 dev-token 出头）+ 命令 HMAC 签名 + `cmds` 审计查询。
- `log_dump` 拉取最近 64 行（云端与本地 `/api/wlog` 对同一条环形缓冲）。
- 局域网 `k=` 限流（每 IP 5 次/分，防爆破）。

验收：伪造签名的命令被拒（回执 `rc=-5`）；`cmds` 表能查到操作人与结果；`log_dump` 输出与串口一致。

### P2 —— 按需（不做不进计划）

- 影子历史 + 阈值告警（`rssi < -80` 持续 10 min、`crash` 递增、`wedge` 置位）。
- 秒级控制（如确需）：换 MQTT 长连接，代价见 4.4。
- 电池档省电（见 4.8）。

## 7. 明确不做的部分

| 不做 | 原因 |
|---|---|
| 把 SoftAP / mDNS / 配网页搬到云端 | 发现依赖二层广播；跨网对应物是"账号绑定"，成本远高于收益 |
| 把 `:80` 调试面暴露到公网 | 口令级鉴权 + 可复位/可运行 shell，出公网等于送攻击面 |
| 云端主动连设备（端口映射/反向代理） | NAT 后不可达；主流做法始终是设备出站 |
| 废掉 `:8080` 局域网直推 OTA | 产线、开发、急救仍需要"不依赖外网"的升级路径 |
| 为命令延迟做长连接（P0 阶段） | 3 min 轮询已满足"运维级"需求，长连接的状态机成本不划算 |

## 8. 风险与回滚

| 风险 | 影响 | 处置 |
|---|---|---|
| 协议 2→3 双端不同步 | 旧设备把 envelope 当 OFFER，OTA 报错 | 云端按 `X-Proto` 分支；先灰度 1 台；`OTA_PROTO_VER` 变更必须同一次发布 |
| 3 min 轮询放大云侧压力 | 每设备每天 480 次 | 云端按 `dev` 限频；单机 ≤ 5 设备时无感；规模化前评估 |
| dram 逼近上限 | TLS 握手期溢出重启 | 落地前用 `build` 内存表卡住阈值（> 98% 不许发布）；必要时按 4.6 腾空间 |
| 命令重启风暴 | 设备反复重启 | `ttl` + `lastcmd` 幂等 + 一次最多 3 条 + `reboot` 最后执行 |
| 命令通道被滥用 | 远程复位成攻击手段 | 白名单 + admin token + `cmds` 审计；写密钥类命令永久禁止 |

**总开关**：NVS `s3cloud/enable`（0/1）。置 0 时 worker 只做影子不做命令，可远程止血。
