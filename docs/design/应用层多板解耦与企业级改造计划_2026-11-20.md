# 应用层多板解耦与企业级改造计划（2026-11-20）

> 状态：**A0–A5 已落地 · 进入收口验证**（执行结果见附录 D）。
> **已确认（2026-11-20）**：S3 实物是**自定义 S3 板** —— 按键 IO45、RGB GPIO48、控制台走原生 USB；
> 因此所有 S3 产品的唯一 board 统一为 **`esp32s3_korvo`**，`esp32s3_devkitc` 只保留给原厂 DevKitC，不再作为当前 S3 产品默认。

> 2. 为什么“一份 APP 配多块板”现在还不是产品能力；
> 3. 按什么顺序、改哪些文件、怎么验收，才能在不全量编译的前提下把它做成企业级能力。

## 0. 结论摘要

1. **不是所有 APP 都板绑定。** `korvo_sys`、`korvo_apps`、`blinky_s3`、`input_btn`、`s3_wifi_portal` 的 C 代码基本都走 `DT_ALIAS / DT_CHOSEN / DT_NODELABEL`，换板只改设备树；真正写死硬件的只有 `korvo_lab`、`korvo_periph`、`korvo_shell` 和少量 STM32 overlay。
2. **但 APP 层确实还有五类硬件真相**：完整板级身份、板级接线 overlay、SoC 寄存器/引脚常量、板级存储/控制台事实、APP 内的构建环境与板名预设。另有 4 个产品映射错误，是“多板能力”的直接断点。
3. **`esp32s3_korvo` 是最典型的硬伤。** 同一块自定义 S3 板的 7 个板级文件，在 `blinky_s3` 和 `input_btn` 里各存一份；板级 DTS 自己还把按键写成 `&gpio0 45`（GPIO45 实际属于 `gpio1` 的 pin13），并把 `usb_serial` 关掉；真正能用的按键/控制台定义反而藏在 4 个 APP 的 overlay 里。
4. **`blinky_s3` / `input_btn` 的产品 yaml 与预设是两套板。** 产品 `chip: esp32s3_devkitc`，但上游 DevKitC DTS 没有 `zephyr,led-strip` chosen，`DT_CHOSEN(zephyr_led_strip)` 直接无节点；而 `CMakePresets.json` 又写 `BOARD: esp32s3_korvo/...`。按当前产品图，这两个产品不可成立。**已确认实物是自定义 S3 板，A1 统一改 `chip: esp32s3_korvo`。**
5. **`korvo_wifi` 是空壳。** 目录里只有 `boards/esp32s3_ble.overlay` 与 `boards/..._usb_serial.overlay`，没有 `CMakeLists.txt`、`prj.conf`、`src/`；产品 yaml 却仍在清单里。
6. **10 个 `CMakePresets.json` 全部失效。** 它们写死的 `ZEPHYR_BASE` 指向 `C:/Users/xiao1/Desktop/esp32/zephyr-learn/zephyr_k/zephyr`（当前不存在），`Python3_EXECUTABLE` 也指向已不存在的 venv；S31 预设仍用旧 `esp32s31_function_coreboard`，而产品已切 `korvo1`。
7. **`f103_breath` 的 64 KB/20 KB 容量是板级事实，却写在 APP overlay 里。** 上游 `stm32f103_mini` 按 F103xE（256 KB）建板，APP 每次都要覆盖 flash/sram 才能得到真实 size 报告；这属于“板级 variant 缺失”，不是 APP 差异。
8. **`korvo_lab` / `korvo_periph` / `korvo_shell` 是实验台/板级诊断，不是产品 APP。** 它们可以保留单板事实，但必须显式标记 `board_scope: single`，不能混进“一份 APP 多板”的产品矩阵。
9. **Product 层还没有 `targets`。** 产品 yaml 只有一个 `chip:`，`kharon run` 没有 `--target`；`korvo_sys` 因此被拆成 `korvo_sys_s31.yaml` + `korvo_sys_s3.yaml` 两个产品，而不是一个产品 × 两个 target。
10. **实施顺序必须是“先清板级身份，再上 targets”。** 否则 `targets` 只是把一个错误的产品图复制成 N 份。

一句话：

> **Board 已经是独立真相，APP 也能按 board 编译；现在缺的是“APP 不再拥有板级身份”和“Product 能表达 Board × App 矩阵”。**

## 2. 目标模型：Board / App / Product 三层

### 2.1 三层定义

| 层 | 回答什么 | 唯一宿主 | 允许的内容 |
|---|---|---|---|
| **Board** | 这块 PCB 上有什么、接在哪、控制台走哪、存储多大 | `kharon-boards/boards/<vendor>/<board>/` | 板级 DTS、pinctrl、board.yml、defconfig、openocd、板级 variant |
| **App** | 这个产品要做什么功能 | `applications/<family>/<app>/` | `src/`、`prj.conf`、APP 级 overlay、`app.yaml` |
| **Product** | 这次发布把哪个 APP 装到哪块板、用什么串口/调试 | `kharon-manifest/products/` | `root`、`targets[]`、串口判据、monitor 判据、matrix |

### 2.2 三条硬规则

1. **APP 不拥有板级身份。** `board.yml`、板级主 DTS、`support/openocd.cfg`、完整 pinctrl 不得出现在 `applications/**`。
2. **APP 不写板级接线。** 按键在哪个 GPIO、RGB 在哪个引脚、控制台走 UART 还是 USB、Flash/RAM 多大，全部由 Board 提供；APP 只通过 alias/chosen/`zephyr,user` 读取。
3. **Product 不复制 APP。** 同一份 APP 的多个板，写成 `targets[]`，不复制 APP 目录，也不复制产品 yaml。

### 2.3 “一份 APP 多板”成立的最小条件

一个 APP 要能配 N 块板，必须同时满足：

- APP 源码只依赖**能力名**（`led0` / `led-strip` / `sw0` / `pa-ctrl` / `pwm-led0` / `can0` / `zephyr,user` 属性），不依赖具体板名、引脚号、寄存器地址。
- 每块板在 Board DTS 里提供这套能力；缺能力时，APP 能编译期裁掉或在运行期明确报“不支持”，而不是编译失败。
- Product yaml 用 `targets[]` 表达 N 个 `(chip, build_dir, serial)`，CLI/驾驶舱能选 target。
- APP 的 `boards/<target>.overlay` 只放“本 APP 额外要的外设”，不放板级公共接线。

### 3.2 一句话总结

- **产品 APP 里真正“代码写死硬件”的只有三个实验台**：`korvo_lab`、`korvo_periph`、`korvo_shell`。
- **产品 APP 里更严重的是“板级身份放错地方”**：`blinky_s3` / `input_btn` 的完整板定义、4 个 S3 APP 的板级 overlay、10 个预设文件。
- **`korvo_sys` / `korvo_apps` 已经证明“同一份 C 代码可以跨 S31/S3”**；现在缺的是 Product 层的 `targets`，不是代码重构。

### 3.3 S3 board 统一决策（已确认）

**事实：**

- 按键：IO45（`gpio1` pin13），不是原厂 DevKitC 的 BOOT/GPIO0。
- RGB：WS2812，数据脚 GPIO48，走 RMT OUT0。
- 控制台：原生 USB-Serial-JTAG（`usb_serial`），不是 UART0/CP2102。

**结论：**

- 唯一 canonical board：`esp32s3_korvo/esp32s3/procpu`，板级目录 `kharon-boards/boards/espressif/esp32s3_korvo/`。
- 所有 S3 产品统一 `chip: esp32s3_korvo`：
  - `blinky_s3`
  - `input_btn`
  - `s3_wifi_portal`
  - `korvo_apps` 的 S3 target（A3）
  - `korvo_sys` 的 S3 target（A3）
  - `korvo_wifi`（源码恢复后）
- `esp32s3_devkitc` 的 chip 适配保留，但只服务真正的原厂 DevKitC；当前 S3 产品不再引用它。
- 板级 DTS 必须直接提供：`led-strip` alias + `zephyr,led-strip` chosen、`sw0`（`gpio1 13`）、`usb_serial` console；APP overlay 不再重复这些事实。

## 4. APP 层残留的五类硬件真相与一类产品断点（带证据）

### 4.1 类型一：完整板级身份被放进 APP

**位置：**

- `applications/esp32s3/blinky_s3/boards/xtensa/esp32s3_korvo/`
  - `board.yml`
  - `board.cmake`
  - `esp32s3_korvo-pinctrl.dtsi`
  - `esp32s3_korvo_procpu.dts`
  - `esp32s3_korvo_procpu_defconfig`
  - `Kconfig.defconfig`
  - `Kconfig.esp32s3_korvo`
- `applications/esp32s3/input_btn/boards/xtensa/esp32s3_korvo/` —— **同一套 7 个文件的第二份副本**。

**为什么是硬伤：**

- 这 7 个文件就是一块完整 PCB 的身份，按设计 D4 / §3.5 只能住在 `kharon-boards`。
- 两份副本已经漂移：两份都写 `button0 = <&gpio0 45 ...>`；而 GPIO45 在 ESP32-S3 上属于 `gpio1` 的 pin13，APP overlay 里实际用的是 `<&gpio1 13 ...>`。板级定义自己就是错的，靠 APP overlay 打补丁。
- 板级 DTS 还把 `&usb_serial { status = "disabled"; }`，而 APP overlay 又把它打开并切 console；说明“哪路 USB 是控制台”这个板级事实没有归位。
- `blinky_s3` / `input_btn` 的产品 yaml 根本没用这块板（见 4.5），所以这两份板定义目前是“死代码 + 错误真相”。

**结论：** 先把 `esp32s3_korvo` 提升为唯一板，修正 DTS，再从两个 APP 里删除。

### 4.2 类型二：板级接线藏在 APP overlay

**位置与内容：**

| 文件 | 板级事实 |
|---|---|
| `applications/esp32s3/s3_wifi_portal/boards/esp32s3_devkitc_esp32s3_procpu.overlay` | WS2812@GPIO48、RMT OUT0、`led-strip` 别名、按键 `button0` 改到 `gpio1 13`（IO45）、console 切 `usb_serial`、开 `adc0/adc1` |
| `applications/esp32s31/korvo_apps/boards/esp32s3_devkitc_esp32s3_procpu.overlay` | 同上：WS2812@48、删 `pa-ctrl`、按键 IO45、console USB、开 ADC |
| `applications/esp32s31/korvo_apps/boards/esp32s3_devkitc_esp32s3_procpu.conf` | `CONFIG_INPUT=y` —— 但 `korvo_apps/prj.conf` 已经开了 `CONFIG_INPUT`，这是重复 |
| `applications/esp32s31/korvo_sys/boards/esp32s3_devkitc_esp32s3_procpu.overlay` | console 切 USB；`coretemp/wdt0` 打开（后两项是 APP 功能，可留） |

| `applications/esp32s3/korvo_wifi/boards/esp32s3_devkitc_esp32s3_procpu_usb_serial.overlay` | 纯 console 切换（板级） |

**判定：**

- **纯板级、应上移**：WS2812 节点/引脚、按键 IO45、`pa-ctrl` 是否存在、console 走 UART 还是 USB、RMT/ADC 节点是否 okay。
- **APP 级、可留**：BLE HCI 打开、`coretemp/wdt0` 打开、某个实验台额外点的 PWM/CAN。
- 这些 overlay 用的文件名是 `esp32s3_devkitc...`，但内容描述的是一块“IO45 按键 + IO48 RGB”的自定义 S3 板，不是原厂 DevKitC。**板名与内容不一致**，是当前 S3 产品图混乱的根源。**已确认以内容为准：这块板就是 `esp32s3_korvo`，文件名/产品 chip 都要改过来。**

## 5. 目标契约（企业级规则）

### 5.1 Board 契约

Board 目录必须是“这块 PCB 的唯一事实源”：

```text
kharon-boards/boards/<vendor>/<board>/
├── board.yml
├── board.cmake
├── Kconfig.<board>
├── <board>_defconfig
├── <board>.dts                 # 或 <board>_<variant>.dts
├── <board>-pinctrl.dtsi
├── support/openocd.cfg
└── doc/
```

Board DTS 必须提供：

| 能力 | 提供方式 | 说明 |
|---|---|---|
| 普通 LED | `aliases { led0 = &...; }` | APP 用 `DT_ALIAS(led0)` |
| RGB/WS2812 | `aliases { led-strip = &...; }` + `chosen { zephyr,led-strip = &...; }` | 两种写法都提供，兼容两类 APP |
| 按键 | `aliases { sw0 = &button0; }` + `gpio-keys` 父节点 | 引脚、极性、去抖全部 Board |
| 功放使能 | `aliases { pa-ctrl = &...; }`，没有就**不要定义** | APP 用 `DT_HAS_ALIAS(pa_ctrl)` 裁功能 |
| PWM LED | `aliases { pwm-led0 = &...; }` | APP 用 `PWM_DT_SPEC_GET` |
| CAN | `chosen { zephyr,canbus = &...; }` + `aliases { can0 = &...; }` | 收发器/回环差异 Board |
| 控制台 | `chosen { zephyr,console = &uart0/&usb_serial; zephyr,shell-uart = ...; }` | **不允许 APP overlay 再切 console** |
| 存储 | `chosen { zephyr,flash = ...; zephyr,code-partition = ...; }` + `storage_partition` | NVS/OTA 依赖 |
| 板级非标准外设 | `zephyr,user { ... }` 或自定义 binding | 例如 ADC 键梯、额外 GPIO |

**同一 PCB 的不同 revision / 内存 / 控制台** 用 `board.yml` 的 `variants`，不要用 APP overlay 打补丁。

#### 5.1.1 `zephyr,user` 约定（用于 APP 需要的板级参数）

例如 Korvo-1 的 ADC 四键：

```dts
/ {
    zephyr,user {
        key-adc = <&adc0 0>;
        key-thresholds-mv = <260 759 1237 1647>;
        key-pad-gpios = <&gpio1 10 GPIO_ACTIVE_HIGH>;
    };
};
```

APP 侧：

```c
#define KEY_ADC_NODE DT_NODELABEL(zephyr_user)
#if DT_NODE_HAS_PROP(KEY_ADC_NODE, key_adc)
static const struct adc_dt_spec key_adc = ADC_DT_SPEC_GET_BY_IDX(KEY_ADC_NODE, 0);
#endif
```

没有这个属性的板，`HAS_ADC_KEYS` 为 0，APP 自动裁掉 ADC 键命令；而不是编译失败或读错通道。

### 5.2 App 契约

每个 APP 增加一个轻量 `app.yaml`（KHaron 读，Zephyr 不读）：

```yaml
name: korvo_apps
kind: product            # product | lab | sample
board_scope: portable    # portable | single
requires:                # 缺一个就构建期报错
  - led-strip
optional:                # 有就编，没有就裁
  - pa-ctrl
  - sw0
  - adc-keys
```

规则：

- `kind: product` 才允许进产品 `targets`；`kind: lab` 必须 `board_scope: single`。
- `requires` 由构建期检查（CMake `dt_*` 查询或 `kharon app check`）；缺能力时输出“board X 不提供 led-strip”而不是一屏编译错误。
- `src/` 不出现 `#include "../boards/..."`、`#include "../../common/..."`；公共 C 代码只走 `elab-app-common`。
- `boards/<target>.overlay` 只允许：
  - APP 额外外设（例如实验台的 PWM 灯、CAN 回环）；
  - APP 功能节点（例如 `modbus0` 子节点、BLE HCI 打开）；
  - **不允许** 板级按键/RGB/console/存储定义。
- `prj.conf` 不写板名相关 Kconfig；`CMakeLists.txt` 不写 `BOARD_ROOT`、不写死 `ZEPHYR_BASE`。
- APP 目录不出现 `CMakePresets.json`。

### 5.3 Product 契约：`targets[]`

产品 yaml 从“单板”升级为“矩阵”，并保持向后兼容：

```yaml
name: korvo_sys
root: ${ZEPHYR_ROOT}/applications/esp32s31/korvo_sys
pack: zephyr/framework
archetype: zephyr
provider: zephyr/west@>=1 <2

targets:
  - id: korvo1
    chip: korvo1
    build:
      work_dir: ${ZEPHYR_ROOT}/build/korvo1/korvo_sys/default
    serial: { port: auto, baud: 115200 }
  - id: s3
    chip: esp32s3_korvo
    build:
      work_dir: ${ZEPHYR_ROOT}/build/esp32s3_korvo/korvo_sys/default
    serial: { port: auto, baud: 115200 }

matrix: korvo_sys
```

规则：

1. **有 `targets` 时，顶层 `chip` 不再作为第二真相**；可保留为默认 target 的别名，但必须与 `targets[0]` 一致，或直接删除。
2. `targets[].id` 是 CLI/驾驶舱的选择键；`targets[].chip` 必须能在 `packs/**/chips/*.yaml` 解析到 `target`。
3. `work_dir` 必须按 target 唯一；没有写时默认 `${ZEPHYR_ROOT}/build/<target.id>/<product.name>/default`。
4. `kharon run -p <product>`：
   - 只有 1 个 target：直接跑；
   - 多个 target 且未给 `--target`：**报错并列出可选 target**，不静默选第一个；
   - `--target <id>`：选定；
   - `--all-targets`：CI 用，按顺序跑，失败即停。
5. 驾驶舱左栏：`Product -> Target` 二级节点；串口/调试/烧录都挂在 target 上。
6. `matrix` 保留为“同一组对照”的聚合键；`korvo_sys_s31` / `_s3` 合并后，matrix 仍是 `korvo_sys`。

### 5.4 兼容策略

- 旧产品 yaml 没有 `targets`：继续按现有单 `chip` 逻辑跑，保证迁移期不破。
- 新产品 yaml 有 `targets`：`Config.chip_of()` 增加“按 target 解析”的入口；现有调用点逐步切。
- 旧 `CMakePresets.json`：先移到 `kharon-ide/.work/legacy-presets/` 保留一个版本，确认无人使用后删除；APP 目录内不再出现。
- 旧 `blinky_s3` / `input_btn` 产品：统一改 `chip: esp32s3_korvo`，不复制 APP；`esp32s3_devkitc` 只留给后续真正的原厂 DevKitC，且必须另建独立 board 定义，**不能与 `esp32s3_korvo` 同时服务当前产品**。

## 附录 A：`targets` 解析的兼容伪代码

```python
def chip_of(proj, target_id=None):
    targets = proj.get("targets") or []
    if not targets:
        return legacy_chip_of(proj)          # 现有单 chip 路径

    if target_id is None:
        if len(targets) == 1:
            target = targets[0]
        else:
            raise ElabError(
                f"产品 {proj['name']} 有 {len(targets)} 个 target，"
                f"请用 --target 指定：{', '.join(t['id'] for t in targets)}"
            )
    else:
        target = next((t for t in targets if t["id"] == target_id), None)
        if not target:
            raise ElabError(f"未知 target：{target_id}")

    top = proj.get("chip")
    if top and top != target["chip"]:
        raise ElabError(
            f"产品 {proj['name']} 顶层 chip={top} 与 target {target_id} "
            f"chip={target['chip']} 冲突；只保留一个真相"
        )
    return resolve_chip(target["chip"])
```
